# q1–q6 是否应归入三审三校：分析

> 交付物类型：评估类（结论＋证据＋建议，不含实施，rules/08 §14）。可复算探针：`bin/probe_merge.py`。
> 状态：分析结论待用户裁定；未改动任何规则、状态机或工具。

## 1 结论

1. **全部归入不可取**：会把流程退回 2026-11 之前“六类混装 s2／S3”的形态，而那正是本项目判定失效的结构原因。
2. **部分归入仅有形式层的外观理由**（q5 计量、q6 标点看似都属于“形式”），但并入会使 S3 同时承担结构、标点、计量、交付格式四个对象，并丢失全库清账能力。
3. **应当归入的不是判据所有权，而是执行责任**：六轴判据保持独立节点与独立凭据；三审三校承担“谁去修、谁签字”的责任映射（§5）。判据维度与审校层级正交。

## 2 关键事实：现状就是“已归入”的形态

`rules/04` 2026-11 之前的口径是：标点在 s3（三校）、语法与语域在 s2（二校）、引文只有 ADR-0011 的中文/日文窄条款、计量只有“照录源”一句、句级逻辑空白。也就是说，六类中的四类**本来就在三审三校之内**。它们失效的原因不是“没有归入”，而是：

* 一个校次承担多个对象（s2 三对象、S3 四对象）；
* 没有独立判据表、独立凭据、独立裁判；
* 机检工具互相重叠却无所有权（`check_style`／`check_quotes`／`check_pairs` 三处判标点）。

“归入”不是解药，是病史。

## 3 可计算证据

### 3.1 归并无法被现有公理拦截（负向实验）

`bin/probe_merge.py` 构造假想 pipeline：删除 q1–q6，把六判据全部挂到 S3，`S3.prev=global`，登记表同步。结果：

```
合并后节点数：16；S3 判据数：9
汇总：13 项，通过 13，失败 0
```

`check_stages` 的 S2 只检查“**一个判据**是否挂在多个硬拦节点”，不检查“**一个节点**挂了多少判据”。因此 P29（六轴独立）的机检承载不足：今天若有人把六轴并回 S3，门禁不会红。

**这本身是必须修的缺口**（见 §6），但它的存在不能反过来证明归并合理。

### 3.2 负荷分布（试金石三件合计）

| 轴 | 清单量 | 若归入的承接校次 | 承接后该节点新增负荷 |
| ---- | ---- | ---- | ---- |
| q1 引文 | 221 | 一校 s1 | ＋221 条查证 |
| q2 逻辑 | 417（全句 1427） | 复审 r2 | ＋417 条（r2 原已重构掉逐句回核） |
| q3 语法 | 209 | 二校 s2 | ＋209 |
| q4 语域 | 4 | 二校 s2 | ＋4 |
| q5 计量 | 187 | 三校 s3 | ＋187 |
| q6 标点 | 115 | 三校 s3 | ＋115 |

归并后 s2 新增 213、s3 新增 302、s1 新增 221、r2 新增 417。试金石已显示 q1／q2 是重项（单件下限 47–149 小时），把它们压进既有校次会使校次负荷失衡 2–3 倍。

### 3.3 资质与独立性

ISO 17100 要求校者独立于译者且资质相当；ISO 5060 要求评估者具备源语言理解与领域知识。q1 需版本查证（Bekker／Stephanus／Akademie 等），q2 需命题骨架判断，均非普通三校的职责范围。归并等于让不具资质的校者做专业判定。

## 4 逐类评估

| 轴 | 最近邻校次 | 并入可行性 | 理由 |
| ---- | ---- | ---- | ---- |
| q1 引文 | 一校 s1 | 不可 | s1 判漏译／错译，不判“原文＋英文”双呈现；且 q1 必须在语法工序前锁定 hash，并入 s1 后锁定点被 s2 越过，守恒（P30）失效 |
| q2 逻辑 | 复审 r2 | 不可 | `pipeline.json` 已把 R2 从“逐句回核原文”重构为“逻辑链与跨节连贯”；并入即回退该重构；且 r2 在 s3 之后，逻辑错误要回退整条链 |
| q3 语法 | 二校 s2 | 不可 | s2 已承担去欧化、语体、句读节奏；再并入成三对象 |
| q4 语域 | 二校 s2 | 不宜（可与 q3 合并为“语言层”，见 §7） | 语域与语法的边界按 ISO 5060 定义切割；合并节点可辩护，但凭据须仍分轴 |
| q5 计量 | 三校 s3 | 不宜（可与 q6 合并为“形式层”，见 §7） | 核心是量值-单位对应（GB 3100／ISO 80000），不是排版 |
| q6 标点 | 三校 s3 | 不宜 | 标点需全库清账（`check_quotes` 总检与 `check_pairs` 配对轴），并入 s3 会丢失清账粒度 |

## 5 推荐：责任映射，不是节点合并

| 三审三校 | 责任 | 与六轴的关系 |
| ---- | ---- | ---- |
| 一校 s1 | 准确性 | 执行 q1 指出的“引文漏检／出处错”修复；形态判定仍由 q1 出凭据 |
| 二校 s2 | 语言 | 执行 q3／q4 指出的修复；判定由 q3／q4 出凭据 |
| 三校 s3 | 体例 | 执行 q5／q6 指出的修复；判定由 q5／q6 出凭据 |
| 初审 r1 | 受众适切 | 抽样复核 q4 档位（Verity 维度，不替代 R-a） |
| 复审 r2 | 连贯 | 抽样复核 q2 骨架（跨节连贯，不替代 L-1…L-12） |
| 终审 r3 | 验收 | 六类凭据完整性与 CI |

**允许一人兼多轴，但须留痕且受独立性约束（ADR-0020）**；判据所有权与凭据文件不合并。这样“人按三审三校组织”与“判据按六轴独立”同时成立。

## 6 必须补的谓词（无论是否归并）

新增 S6：**每个 `stage` 节点的判据数 ≤1，除非其判据登记为同一对象类**。

* 现状 S3 挂 3 个判据（`check_style`／`check_images`／`check_summary`），同属“交付格式”对象，应登记 `object_class: deliverable-format` 豁免；若不补此谓词，“一节点一对象”从未被机检强制（本次实验已证）。
* 落地方式：`pipeline.json` 节点增 `object_class` 字段；`check_stages` 增 S6 谓词；`axioms.json` P29 的 `check.ref` 改为 `["S2","S6"]`。

## 7 可选降本形态（不推荐，列出以备裁）

若目标是把节点数从 22 降到 20 并减少迁移：

| 形态 | 内容 | 代价 |
| ---- | ---- | ---- |
| 4 节点 | q1 引文、q2 逻辑、q3 语言（语法＋语域）、q4 形式（计量＋标点） | 独立回炉与门禁升档粒度变粗；须同时补 S6 与 `object_class`，否则两轴合并不可检 |
| 3 节点 | 引文、逻辑、语言与形式合一 | 回到“一节点三对象”，不建议 |

**不推荐理由**：试金石显示六轴成本与误报结构差异极大（q1 查证、q2 骨架、q5 单位、q6 条款），独立节点才能按轴分批、按轴升门禁、按轴回炉；合并会把四条不同性质的工单压成一个通过位。

## 8 对“是否符合国内出版制度”的回答

三审三校（《图书质量管理规定》与 CY/T 系列）约束的是**责任层级与签字链**：谁初审、谁复审、谁终审，谁对哪一类差错负责。它不规定“一个校次只能查什么”。因此：

* 把六轴并入三审三校，不会更符合制度——制度要的是责任分离，归并反而稀释责任（一个校次对四类差错负责）。
* 正确对齐方式是 §5 的映射表：制度对齐看签字链，判据完整性看六轴节点，两者各司其职。
