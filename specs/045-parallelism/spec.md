# 045 — 全翻译流程并行性的公理化证明：充分性、一致性、完备性

**版本** v1.0 ｜ **状态** 方案（待批）｜ **日期** 2026-11-18 ｜ **权威** 用户指令“全翻译流程同一流程，AZ 条目允许并行，不同流程去耦合允许并行，AZ 跨流程并行；公理化形式证明完备性、充分性、一致性”

## 0. 方向声明（rules/08）

- **目标**：证明同一翻译流程在 AZ 词条级、跨流程级的并行执行下，满足**充分性**（并行不破坏正确性）、**一致性**（共享状态无中间态/无丢失更新）、**完备性**（无死锁、无饥饿、每词条可达 done）。
- **非目标**：不改变现有并发机制（锁、认领、同步面）；不新增线程/进程调度；不改状态机。
- **验收判据**：①并发模型与公理成文；②六条定理（S1/S2、C1/C2、K1/K2/K3）证明完整；③判定器静态断言公理成立、负向样本可证伪；④`check_all` 全绿、提交推送。

## 1. 并发模型（据实取证）

- **执行单元**：词条 `e ∈ E`（1,872 件，按首字母分 26 个 AZ 组）。每词条一条**串行状态机链** σ(e)（`pending → cleared → s0 → draft → s1 → s2 → s2.4 → global → S3 → R1 → R2 → R3 → done`，`prev` 唯一前驱）。
- **私有状态** `Priv(e)`：`tasks/<l>/<e>.json`（`_os_path`）、`<l>/<e>.md`（译文）、`journal/<l>/<e>.ndjson`（`_journal_path`）——三者仅以 `slug` 为键，**不同词条零交集**。
- **共享状态** `Sh`：`baseline/entries.json`（词条元数据/yuanwen 登记）、术语册 `shu-yu-biao.md`、人名册 `ren-ming-biao.md`、`SUMMARY.md`（CI 同步，不手改）。
- **原子原语**：`write_json_verified`＝序列化→临时文件→`fsync`→读回逐字节比对→`os.replace` 原子替换（5 次重试）→再读回比对；`BASELINE_LOCK` 单把 `threading.Lock`，三处 `with` 获取、**无嵌套**；`campaign.py claim` 认领互斥（`claimed_by` 非空即拒）。
- **跨进程**：多机/多会话只经 `origin/main` 同步（ADR-0026/0066），同批次认领互斥，同词条单写者。

## 2. 公理（据上述事实）

- **A1 私有隔离**：∀ eᵢ≠eⱼ，`Priv(eᵢ) ∩ Priv(eⱼ) = ∅`。
- **A2 共享原子**：一切写 `Sh` 经 `write_json_verified`（原子替换＋读回校验）；`baseline` 写经 `BASELINE_LOCK`（单锁无嵌套）。
- **A3 单写者**：同一词条的推进在任意时刻至多一个执行者（认领互斥＋origin/main 同步面）。
- **A4 无跨词条依赖**：词条推进动作只读 `Priv(e)` 与 `Sh`（原子读），不读、不等其他词条的私有状态。

## 3. 定理与证明

### 3.1 充分性（并行不破坏正确性）

**S1 词条可交换性**：任意两词条 eᵢ、eⱼ 的动作可交换，故并行调度可**线性化**为某串行调度，最终状态与调度顺序无关。

> 证明：eᵢ 的动作只写 `Priv(eᵢ)`、eⱼ 只写 `Priv(eⱼ)`（A1 零交集），二者对共享状态 `Sh` 的写经 A2 原子且无相互依赖（A4）。故 eᵢ、eⱼ 的动作集互不重叠、互不依赖，满足交换律 ⇒ 任何交错执行存在等价的串行执行（可交换性引理）。∎

**S2 共享点原子性**：`Sh` 的每次更新对任意观察者呈现为完整旧值或完整新值，无部分写、无丢失更新。

> 证明：A2 的 `os.replace` 是文件系统原子操作——观察者要么读到替换前的完整旧文件、要么读到替换后的完整新文件；`BASELINE_LOCK` 串行化进程内写者；认领互斥（A3）串行化跨进程同资源写者。三者合取排除部分写与丢失更新。∎

### 3.2 一致性

**C1 单文件原子可见性**：`write_json_verified` 落盘的任何文件，任意时刻读取得到的是完整一致的版本（无中间态）。

> 证明：临时文件写满并 `fsync` 后才 `os.replace`，替换前的正本始终完整；替换后的正本由读回校验保证与内存对象逐字节一致。故不存在“写了一半”的可观察状态。∎

**C2 事件序单调**：同词条 journal 事件 `seq` 严格递增、全序，无乱序、无覆盖。

> 证明：`append_event` 只追加（`existing + line` 重写全文件，非 in-place 改写），`seq` 由单调递增；A3 单写者保证同词条事件串行产生，故事件序即产生序。∎

### 3.3 完备性（无死锁、无饥饿、可达）

**K1 无死锁**：不存在循环等待。

> 证明：锁资源仅 `BASELINE_LOCK`（单把、A2 无嵌套）与认领互斥（单资源、单次获取）。任意执行者一次只持一把锁、持有期间不请求第二把 ⇒ 等待图无环 ⇒ 无死锁。∎

**K2 无饥饿**：任何被认领的词条都能推进到 `done`，不被其他词条阻塞。

> 证明：A4 词条推进不等待其他词条；AZ 组间、词条间无 barrier 与顺序依赖；`Sh` 的锁（K1）不会死锁且临界区有界（写一个 JSON）。故每个词条的推进链上无持久阻塞点。∎

**K3 可达**：∀e，`pending →* done` 可达。

> 证明：σ(e) 是有限无环链（`prev` 唯一前驱 + 无环，specs/043 A1/A7/A3 已证），自 `pending` 至 `done` 逐前驱可达。∎

**完备性 ⟺ K1 ∧ K2 ∧ K3 ∧ 覆盖**（每词条独立可推进且可达终态）。

## 4. 边界（不可自证）

- 本证明的**对象是“结构并行性”**（锁、隔离、无环、可达），可机检可证伪；**不证明**“人工执行质量”与“调度公平性”的实时语义（跨进程协调的实时互斥依赖认领纪律与 origin/main 同步面，属纪律层而非结构层，同 specs/043 §6.4 相对完备边界）。
- `K2` 的“任何词条都能推进”以“该词条已被认领且无 hard 缺陷阻塞”为前提——hard 缺陷（源不可解析等）是内容层阻塞，非并行结构缺陷。

## 5. 落点

- `specs/045-parallelism/spec.md`：本规格。
- `specs/045-parallelism/bin/verify_parallelism.py`：静态断言判定器（A1 隔离、A2 单锁无嵌套、A3 认领互斥、K3 无环），负向样本可证伪。
