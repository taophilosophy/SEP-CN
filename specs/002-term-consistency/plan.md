# Implementation Plan: 术语一致性检查器

**Branch**: `002-term-consistency` | **Date**: 2026-10-27 | **Spec**: [spec.md](./spec.md)

## Summary

新增 `tools/check_terms.py`：解析术语登记册（`yi-zhe-shuo-ming.md` 多分节表格）与发布词汇表（`qian-yan/ci-hui-biao.md`），报告两表译法冲突与登记册自洽性违例（废弃链、必填列、重复）；提供 `--docs` 定点核销模式（登记册驱动的正文术语核对）。冲突与违例为硬错误（退出码 1），可接入 `checks.yml` 门禁。

## Technical Context

**Language/Version**: Python 3 仅标准库（与 specs/001 管线一致，零第三方依赖）
**Storage**: 只读两表与给定文档，不改任何数据文件
**Testing**: unittest，fixtures 为两表的最小样本（含冲突、废弃链断链、重复、合法多译法分行）
**Target**: 本地与 GitHub Actions（ubuntu）均可运行；UTF-8、LF

## Design Decisions

* **D1 键规范化 **：术语键 = 原样文本剥 `*` 斜体标记、去首尾空格；比对大小写不敏感、展示保留原样。不做词形归并（宁可漏报不误报）。
* **D2 冲突定义 **：同一键在两侧译法集合互斥才报冲突；一侧为另一侧子集视为“词汇表滞后”，列为告警（报告项）而非硬错误。
* **D3 解析策略 **：只认 `|` 分隔且列数匹配的行；表头/分隔行跳过；解析失败行计入告警不致命。
* **D4 门禁分级 **：冲突（两表互斥）+ 自洽性违例 = 硬错误；词汇表滞后、解析告警、`--docs` 比对 = 报告项。

## Risks

* 登记册分节标题文字可能变化 → 解析按“表格行”而非“节名”驱动，节名仅作展示。
* 词汇表按字母排序而登记册按拼音/字母混排 → 与排序无关，逐行解析。
