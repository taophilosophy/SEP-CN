# 018 — yuanwen ↔ en 原文转换逐段人眼审计战役

## 背景与意图复述

用户指令（2026-11-13）：

> 逐个、逐段比较 yuanwen 与 en 的格式转换一致性，完整性，禁止抽查，禁止编程、逐段比较，同时纠正到已经在译或完成的译文。

一句话转述：对 `yuanwen/<letter>/<slug>.md`（由 `yuanwen.py` 从 `en/<slug>/index.html` 确定性转换而来）与原始 HTML，**每个词条、每个段落**做人工（非脚本）比对，核验格式转换一致性与完整性；发现缺段、走样、错配即修复 yuanwen，并同步把修正落入**已在译或已完成**的中文译文（顶层 `<letter>/<slug>.md`）。

## 目标 / 非目标

**目标**

1. 覆盖 `yuanwen/` 全部 md 文件（正式词条 → 别名 → 补充材料，字母序），每个文件与对应 `en/<slug>/index.html` 逐段人眼比对。
2. 比对维度：①完整性——HTML 正文每个可见块（标题、段落、引块、列表、表格、脚注、书目条目、Academic Tools、OIR、Related Entries）在 md 中有对应；②格式一致性——斜体/加粗/链接/锚点/脚注标记与定义/引块/列表层级按转换契约如实呈现；③无凭空多出内容。
3. 修复：缺件补入、走样改写，均在 yuanwen md 与受影响译文两侧落盘。
4. 全程留痕：每个词条一行台账（execution-log/），发现项与修复可回溯。

**非目标**

1. 不重译、不润色译文语体（那是 011/015 战役的职责）；只纠正因源文转换缺陷导致的译文偏差。
2. 不写任何自动比对脚本（用户明令禁止编程比对）；现有检查器照常跑，但不作为比对证据。
3. 不重抓上游（en/ 为不可变快照，礼貌抓取约束下本轮不联网复核）。
4. 不动 en/ 原始 HTML。

## 方法（人工比对协议，每词条）

1. Read en html 正文区（`<h1>` 至页脚前）全文。
2. Read yuanwen md 全文。
3. 逐节逐段走查：标题层级、每段文字、引块、列表、表格、脚注引用/定义、书目子节、四固定节。核对 md 格式元素与 HTML 对应关系。
4. 发现项登记 → 修 yuanwen md → 查译文是否存在（在途/done）→ 修正落入译文 → 台账记一行。

## 验收判据

1. execution-log 台账覆盖 yuanwen 全部 md 文件，无词条缺行。
2. 台账中每一发现项均有修复留痕（yuanwen 侧与译文侧）。
3. `python tools/check_all.py` 全绿（收工时）。
4. 译文侧修正遵守体例规则（rules/02、03、07）。

## Assumptions（用户裁定登记处）

- A1 [假设，待用户裁定可推翻]：执行顺序为字母序全量推进（正式词条→别名→补充材料）；对存在译文（在途/done）的词条同步纠正译文，对无译文词条仅修 yuanwen。「逐个」不做子集抽查。
- A2 [假设]：en/ 原始 HTML 为不可变事实源，比对时以 HTML 正文为基准判定 md 缺陷；转换契约以 specs/001 contracts cli.md 的 yuanwen.py 条目为准。
- A3 [假设]：yuanwen/ 为 gitignore 本地库，修复不产生 git 提交；译文与台账入库提交。
- A4 [用户指令，2026-11-13]：**同步修正转换脚本并重转，避免回归**——审计发现的系统性转换缺陷修进 `tools/yuanwen.py`（人工逐段比对不受影响，仍为审计裁判），随后全量重转 yuanwen 并重登记哈希（baseline/entries.json）。已修三类：①`<br>` 在引块内并行 → 行标记保行结构（引块外行为不变）；②em/strong 标签内空白剥失 → 空白外移（`*abductive*ones`→`*abductive* ones`）；③纯 `<b>` 被兜底剥标签丢加粗 → 转 md 粗体（星交错复杂内容维持既有降级）。回归防线：单测 5 例 + 重转后全库逐行差异分类扫描（bin/regression_scan.py），非预期差异类 = 0 才收口。
