# 独立形态审校流程（specs/030）

**版本** v1.0 ｜ **状态** 生效（批次未启动）｜ **日期** 2026-11-15 ｜ **权威** ADR-0047 ｜ **工具** `tools/indep_review.py`

## 1. 目的

把**横向缺陷类**——跨词条、与单件翻译状态正交的形态/正典化/引用一致性项——从零散挂账（W7/W8/O1/O2 式的散件待办）收编为**可复算、可并行、有台账**的独立审校流程。此前的形态修改（如 W7 已处理 173 件、W8 已处理 95 件）完成了工作却没有可重复的判据与残余复算口径，缺陷类会在新入件上复发；本流程把「判据—扫描—裁定—修复—复算」固化下来。

**非目标**：不评价译文质量（那属 s2.5 逐段三向审校与 r1–r3）；不改进度状态机（横向项与状态正交）；不做批量机械改写替代人工裁定。

## 2. 适用范围（输入）

* **对象**：`<letter>/<slug>.md` 中任务状态落在已译集合者（`drafted`…`done`，见工具 `TRANSLATED`）；存根与未动工件不在范围。
* **对照面**：`en/<slug>/index.html`（正典形态与节集合来源）、`yuanwen/<letter>/<slug>.md`（底稿镜像）。
* **基线**：`results/baseline-20261115.json`（421 件已译，六类共 338 处）。

## 4. 执行规则

1. **按字头分批并行**：以 `--letter A` 起逐字头推进，与 s3 同（各字头批次互不阻塞）；同字头内按类推进，一类收口再进下一类。
2. **扫描 → 裁定 → 修复 → 复算**四步闭环，每批留三份凭证：
   * `results/scan-<letter>-<date>.json`：`indep_review.py` 原始输出（复算基准）；
   * `results/adjudication-<letter>.md`：逐处裁定表（真缺陷／照录豁免／工具误报），误报须写清成因以便回修工具；
   * `results/manifest-<letter>.jsonl`：逐行 `{path, class, rule, line, action, before_sha256, after_sha256}`。
3. **改成品须留证据链**：形态类改动是外科手术式正典化（节名、行形态、空格），不得连带改动译文措辞；跨件机械改写遵守 rules/05 五条纪律（残余归零前置门、幂等、逐行身份追踪、基线还原、探针调试）。
4. **豁免登记**：直接引文与照录外文内部的引号/间隔属豁免（rules/02 豁免条款），须逐处登记，不得以「批量豁免」略过。
5. **实质翻译缺陷转口径**：审校中发现漏译、增译、术语错、数字错等**内容类**缺陷，不在本流程内修，转该件 s2.5/s3（update 口径，`changes:` 登记）。
6. **门禁**：本流程为**告警级**，不进 `check_all`/CI（形态项全库口径成本高且含豁免判定）；批次收口判据＝该字头该类「残余 0 或全部登记豁免」。
7. **工具误报必须回修**：同类误报累计 ≥3 处即修工具并重跑基线（O2 实例：脚注键撇号误报 397→50）。

## 5. 与状态机的关系

* 独立审校**不改** `tasks/*.json` 的 `state`：横向项与「该件译文走到哪一步」正交，混入状态机会把横向批次绑进逐件流程，重演散件挂账。
* 例外：若某件因横向缺陷无法进入 s3（如文献分类丢失导致节集合不符），则该件按 s2.5 复核口径停留，并在任务 steps 以 evidence 引用本流程凭证。

## 6. 收口与结案

全部 26 字头批次收口，且重跑 `python tools/indep_review.py --scan` 六类残余为 0（或全部登记豁免）时，本 spec 转入结案并并入 rules/05 常规检查器表；此后新入件在 s2.5 机检网按同六类自查。
