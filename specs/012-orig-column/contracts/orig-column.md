# 契约：登记册「原文」列

本文件是 `012-orig-column` 的**结构契约**：列语义、判定口径、检查器行为与工具兼容边界。
与实现冲突时以本契约为准，改契约须先改本文件并在 [execution-log](../execution-log.md) 留痕。

## 1. 表结构（六列，两表一致）

```
| 键 | 原文 | 译法 | 出处 | 依据 | 日期 |
```

| 列序 | 名称 | 语义 | 约束 |
| ---- | ---- | ---- | ---- |
| 1 | 键 | 术语/人名的检索键（英文、拉丁转写或原词） | 非空，唯一性由检查器按「同键同译法重复=硬错误」判定 |
| 2 | **原文** | 该词在其源语言中的书写形式 | 非英语：**必填**（阶段 4 后为硬约束）；英语：`—`；不得留空字符串 |
| 3 | 译法 | 中文主形（可含「亦作…」变体） | 主形唯一（ADR-0020） |
| 4 | 出处 | 首现词条 / 语料回收范围 | — |
| 5 | 依据 | 裁定依据与凭证（ADR-0012 档位） | 必填（缺则告警） |
| 6 | 日期 | 裁定日期 `YYYY-MM-DD` | — |

**形态不变量**

* 数据行（`line.startswith('| ')` 且非分隔行）满足 `line.count('|') == 7`（六列）。
* 单元格不得跨行、不得含未转义 `|`。
* 分隔行（`| --- | ... |`）若存在，列数须与表头一致（当前两表无分隔行）。

## 2. 原文列的取值规则

| 源语言 | 原文列填什么 | 例 |
| ---- | ---- | ---- |
| 英语 | `—`（U+2014） | `reliable cognition` → `—` |
| 拉丁语 | 原拼写 | `a priori` → `a priori`；`ampliation (ampliatio)` → `ampliatio` |
| 德语 / 法语 / 意大利语 / 西语 / 波兰语 / 匈牙利语等拉丁字母语言 | 原拼写（保留变音符） | `Dasein` → `Dasein`；`différance` → `différance`；`Petőfi` → `Petőfi` |
| 希腊语 | 希腊字母（含重音符） | `aretê` → `ἀρετή` |
| 阿拉伯语 / 波斯语 | 阿拉伯字母 | `taṣdīq` → `تصديق` |
| 梵语 / 巴利语 | 天城体 | `apoha` → `अपोह` |
| 藏语 | 藏文（含 tsheg） | `tshad ma` → `ཚད་མ` |
| 汉语 | 汉字（与本站简体一致；古典著作用书名号） | `dao` → `道`；`Analects` → `《论语》` |
| 日语 | 汉字/假名（依原词） | `wabi` → `侘` |
| 朝鲜语 | 谚文或汉字（依原词；括注已给者取括注） | `chuin’gong（주인공）` → `주인공` |
| 俄语 | 西里尔字母 | `Cheka` → `Чека` |
| 希伯来语 | 希伯来字母 | `Sefer ha-Zohar` → `ספר הזוהר` |

**多形与复合键**

* 键含 `A / B`（两个名并行）：原文取**首名**的原文；若两名语言不同（如 `Ibn Sīnā / Avicenna`），取首名（阿拉伯语）原文，拉丁化形不入原文列。
* 键为拉丁化名（`Avicenna`、`Averroes`、`Alhazen`）：原文列填该拉丁形本身（其源语言即拉丁学术传统）。
* 键含人名消歧括注（`dictum (Abelard)`）：原文取**主形**（`dictum`），括注不是原文。
* 键含原形括注（`ampliation (ampliatio)`、`sophism（sophisma）`）：原文取括注内原形。
* 键含汉字/谚文括注（`hwajaeng（和諍）`）：原文取括注内文字。

## 3. 非英语判定口径（检查器）

一条「非英语」当且仅当满足任一：

1. 键含非 ASCII 的 Unicode 字母类（`L*`）或组合附加符（`M*`）字符（全角标点、弯引号不算）；
2. 键含拉丁转写标记：`ā ē ī ō ū ṣ ṭ ḍ ḥ ṃ ṇ ṛ ś ʾ ʿ`；
3. 键（整键、去括注主形、括注内容、`/` 拆分变体，casefold 后）命中内置 `FOREIGN_WORDS` 词表（拉丁惯用语/德/法/阿拉伯/梵巴/藏/日/朝/汉/俄）；
4. 键匹配阿拉伯人名转写模式 `\b(ibn|bint|abu)\b` 或 `\bal-[a-z]`。

**反例（不应判为非英语）**：`justified true belief（JTB）`（全角括号）、`Gödel’s theorem`（人名变音符，但英文术语——仍计入待补，填自身拼写即消）。

## 4. 检查器行为（`tools/check_terms.py`）

| 项 | 行为 |
| ---- | ---- |
| 解析 | `parse_registry_full` → `(term, orig, trans, first_seen, basis, date, lineno)`；六列标准，旧五/四列兼容（`orig=None`） |
| 兼容签名 | `parse_registry` 保持旧六元组返回，`term_audit.py` / `tl_browser_batch.py` 无需改列位 |
| 告警 | 「非英语术语缺原文」：`orig` 为 `—`/空/None 且判定非英语 → 告警（**不计硬错误**） |
| 清单 | 每次全库运行重写 `specs/008-terminology-campaign/results/orig-missing.txt`：`表\t键\t行号` + 末行 `汇总\tN\t…` |
| 硬错误 | 仅「三表互斥冲突」「同键同译法重复」「自洽违例」；本工程**不得**新增硬错误 |
| 退出码 | 0 无硬错误（`--docs` 模式恒 0） |

## 5. 工具兼容边界

* `tools/term_audit.py`、`tools/tl_browser_batch.py` 通过 `from tools import check_terms` 复用解析——**列位变更只改 check_terms 一处**。
* `tools/tl_browser_batch.py --emit` 取键列 `cells[0]`、译法列 `cells[2]`；扩列后须复核 emit 计数不异常（行数 × 变体数）。
* `qian-yan/ci-hui-biao.md`（发布视图，三列）**不在本契约范围**；其与登记册一致性仍由 check_terms 的「冲突/滞后」规则约束（比较译法集，与原文列无关）。

## 6. 阶段 4 升级条件

以下同时满足时，把「非英语缺原文」由告警切为硬错误：

1. `orig-missing.txt` 仅剩汇总行（告警 0）；
2. 阶段 3 的「外源不可得」结论已在 execution-log 登记，且对应行已在依据列注明（或经用户裁定豁免）；
3. 全库 `check_all` 7/7 绿；
4. 在 rules/03 更新条文并提交后，规则开关随条文同时生效。
