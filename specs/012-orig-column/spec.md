# Feature Specification: 登记册「原文」列（非英语术语原文规范）

**Spec ID**: `012-orig-column` | **Created**: 2026-11-06 | **Status**: In progress

**Input**: 用户指令（2026-11-06）：「术语表，人名表新增一列原文：如果术语非英语，必须同时增加原文。」同日问询答复三项裁定：①**原文字形**＝原生文字（希腊语 ἀρετή、阿拉伯语 تصديق、梵语 अपोह；拉丁/德语/法语填原拼写；英语填 `—`）；②**列位置**＝键列之后（第 2 列）；③**存量补齐**＝先落表 + 检查器告警，分批核实（不一次性硬错误，避免为凑门禁编造原文）。

## 目标

1. 两登记册结构统一为六列：`| 键 | 原文 | 译法 | 出处 | 依据 | 日期 |`（`yi-zhe-shuo-ming.md` 术语表、`ren-ming-biao.md` 人名表）。
2. 非英语条目「原文」逐一**核实回填**：原生文字优先；拉丁/德/法填原拼写；英语填 `—`。
3. 检查器规则：**非英语缺原文 = 告警**（不计硬错误），全量清单落 `specs/008-terminology-campaign/results/orig-missing.txt`，作为本工程的工作队列。
4. 长期：告警清零后，规则升级为硬错误（阶段 4 验收），使「非英语必有原文」成为门禁事实。

## 非目标

- 不改译法、不改「出处/依据/日期」列内容（本工程只动第 2 列）。
- 不改发布词汇表 `qian-yan/ci-hui-biao.md` 列结构（发布视图三列另论）。
- 不为凑门禁编造原文：**无证据者留 `—` 并留队**，零信任（宪法 I）。
- 不翻译新词条、不推进词条翻译状态机。

## 裁定与假设

* **列语义**（[contracts/orig-column.md](contracts/orig-column.md)）：`原文` = 该术语在其源语言中的书写形式；英语条目填 `—`；旧五列格式（无该列）由解析器视为 `orig=None`（兼容，不判错）。
* **判定口径**：非英语判定 = ①键含非 ASCII 字母/变音符（`unicodedata` L*/M*）；②拉丁转写标记（ā ē ī ō ū ṣ ṭ ḍ ḥ ṃ ṇ ṛ ś ʾ ʿ）；③内置小语种词表命中（拉丁惯用语/德/法/阿拉伯/梵巴/藏/日/朝/汉）；④阿拉伯人名转写（`ibn`/`bint`/`abu`/`al-`）。
* **阿拉伯人名通俗译名交叉核对（2026-11-07 用户提醒）**：阿拉伯人名多有通俗中文译名，且常有「拉丁名 / 阿拉伯名 / 通俗中文名」三方对应（阿维森纳=Avicenna=ابن سينا；拉齐=Rhazes=أبو بكر الرازي；法赫鲁丁·拉齐=فخر الدين الرازي；鲁米=مولانا；鲁拜集=رباعيات 等）。同名异人（Abū Bakr al-Rāzī 与 Fakhr al-Dīn al-Rāzī、Naṣīr al-Dīn al-Ṭūsī 与 Ṭūsī 系）极易错配——核实原文时须先用通俗中文译名确认「同一人」，再落键。012 只动第 2 列；译法列若发现通俗译名问题，另行立任务。
* **逐条联网复核（2026-11-07 用户裁定，覆盖阶段 3 全部批次）**：非英语原文必须**逐词联网复核**，原生字形须**读自来源页面**（检索结果/词条页同页显式给出「转写 ↔ 原文」配对）；**禁止正推或逆推**——即禁止以任何「转写↔字母」标准映射表（IAST、DIN 31635、Wylie、ISO 15919 等）机械转换得出原名，即便该映射在学界公认可逆。据此，2026-11-07 以 IAST 映射推进的梵语批 51 行**作废回退**（`script/_revert_orig_batch.py`），改逐词复核重做。
  **Why**：映射表转换属推演，单条出错（同音异形、连写、非标音位）无从发现，违背零信任与「证据而非篇幅」的宪法判据；
  **How to apply**：每词一条检索/抓取记录为证据（`键 → 原文 → URL`）入 execution-log；来源未显式给配对者留 `—` 并登记「外源不可得」，不得以映射补齐。
* **证据档位**（沿用 ADR-0012 精神）：仓库语料（`yuanwen/` 镜像与中文词条正文）内的原生文字共现 → 权威工具书/审订库 → 学界惯例。**每条原生文字回填须在 execution-log 留证据出处**；无据不发。
* **语料可证性实测**（2026-11-06，全库字符统计）：Greek 9260 字/360 文件、Cyrillic 998/20、Hangul 522/7、Hebrew 139/13；**Arabic 仅 49 字/3 文件、Devanagari 6 字/1 文件、Tibetan 0**——故阿拉伯/梵/藏条目语料不足，归阶段 3（外部权威源核实），不得凭记忆直填。
* **共享文件并行风险**：两登记册为多会话共享事实源；并行会话若仍按五列写入将造成列错位。检查器对 `>6 列` 行列告警（`parse_registry_full` 已内置），提交前必核 `git status`。

## 验收判据（总）

1. `python tools/check_terms.py` 硬错误 0；「非英语缺原文」告警数单调下降并最终 0（阶段 4 后转硬错误）。
2. `python tools/check_all.py` 7 项全绿，全程不回退。
3. 两表六列不变量：所有数据行 `line.count('|') == 7`；无 `>6 列` 告警。
4. 每条原生文字回填均可追溯到 execution-log 的证据行（文件+行号，或外部凭证 ID）。
5. 英语条目原文列恒为 `—`；无「空字符串」单元格。

## 标准作业（SOP）

1. **取队列**：读 `specs/008-terminology-campaign/results/orig-missing.txt`（每行 `表\t键\t行号`，末行汇总）。
2. **分批**：按阶段 1→2→3 顺序；单批 ≤ 50 条，批间提交一次，便于回滚定位。
3. **执行**：脚本一律写到 `script/`（已 gitignore）并以 `python -I` 运行；**禁 bash heredoc 写中文**（会损坏字符）。写回只允许「按 (表,键) 定位 + 仅当原文列为 `—`」的幂等替换。
4. **验证**：`check_terms`（硬错误 0 + 告警下降计数）→ `check_all` → 抽查 10 行六列形态。
5. **留痕**：`execution-log.md` 记批号、条数、来源档位、剩余计数；证据不足的键记「留队 + 原因」。
6. **提交**：只 `git add` 两登记表 + 本 spec 文件；中文一行提交信息，注明阶段与条数。

## 纪律与红线

* **零编造**：任何原文都必须能说出出处；记忆推断不作为证据（尤其希腊重音符、天城体、藏文 tsheg）。
* **幂等**：重跑脚本不得覆盖已填值、不得重复插列。
* **逐行身份**：同键多行（如 `Mullā Ṣadrā` 两形、`ʿAyn al-Quḍāt` 两形）按行号定位，不做全局替换。
* **并行会话**：两表是共享事实源；提交前 `git status --short` 核对，若发现他人未提交行一同入表，提交信息注明「含并行会话新增行」。
* **不升硬错误**：阶段 4 之前，任何人不得把该告警改成硬错误来「催活」。
