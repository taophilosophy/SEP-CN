# specs/042-progress-model-v2：进度模型重建（v3 · 三段 · 节点可插 · 类型定判据）

**状态**：草案（待用户裁定）｜**日期**：2026-11-17｜**承办**：pc6 主会话
**版本**：v3 修正 v2 的核心错误——v2 把"可插性"绑在阶段类型上（P 固定／S 可插），导致 1 段无法新增环节。v3 改为：**段固定、节点可插、类型只决定判据来源**。v2 原文见 git 历史。

## 方向声明（rules/08 §1）

* **意图复述**：用户指出——任意段都可新增插入；整体分三段（1 英语文本提取，内含格式处理；2 翻译中文，内含格式处理；3 审阅校对，内含格式处理）。若插入发生在 1 段，v2 的"S 只插在 P4–R1"无法表达。
* **目标**：把"可插性"与"判据来源"彻底解耦，重建 29 条公理，并给出 1 段插入的三个具体例子。
* **非目标**：不改工具与任务数据；不裁定三段内既有环节的归属（给出默认映射，调整走 ADR）。
* **验收判据**：① 任意相邻节点之间均可插入，且既有节点相对序不变；② 插入节点的判据来源由其类型唯一决定；③ 每段以格式闭合节点收口，格式问题不跨段；④ 1 段插入三例可通过结构校验。
* **作废条件**：若"段内任意插入"导致段间契约无法定义（下段输入不确定），则退回"段内只在指定位置插入"。

## 一、三级结构（v3 的核心修正）

流程不是"一条线上有若干同类节点"，而是**段 ⊃ 节点 ⊃ 类型**三层：

| 层 | 数量 | 可变性 | 作用 |
| --- | --- | --- | --- |
| **段 Segment** | 3，全序 | **固定**（增段须改 ADR） | 粗粒度分期，定义段间契约 |
| **节点 Node** | 段内若干，全序 | **任意相邻位置可插** | 具体环节，插入不重编号 |
| **类型 Type** | 4 种 | 固定 | 只决定**判据来源**与**降级策略**，不决定能否插入 |

**这是 v2 错误的根源**：v2 把"类型"当成"可插性开关"（P 不可插、S 可插、R 不可插），于是 1 段（全为 P 类）被锁死。v3 明确：**任何类型都可插入；类型只回答"这个节点的判据由谁定、存量怎么处理"**。

### 1.1 四类节点

| 类型 | 判据来源 | 典型节点 | 插入代价 |
| --- | --- | --- | --- |
| **pipe** 管线型 | ADR ＋ 工具 docstring | P1 抓取锁钉、P2 转换、P3 反校、P4 预处理 | 插一个须同时改 ADR（判据无正文锚则效力悬空） |
| **stage** 生产型 | 该三位一体的 `criteria` | draft、s1、s2、s2.4、s2.5、s3 | 低：一份 Spec 即可 |
| **review** 验收型 | rules/04 ＋ ADR-0054 | R1、R2、R3 | 中：不可减，只能增 |
| **format** 格式型 | 该段的格式判据 | F1、F2、F3 | 低：每段一个，段末闭合 |

### 1.2 三段与既有环节的默认映射

| 段 | 名称 | 节点序列（默认） |
| --- | --- | --- |
| **Seg1** | 英语文本提取 | P1 抓取锁钉 → P2 转换 → P3 反校 → **F1 格式闭合** |
| **Seg2** | 翻译中文 | P4 预处理 → draft → s1 → s2 → **F2 格式闭合** |
| **Seg3** | 审阅校对 | s2.4 → s2.5 → s3 → R1 → R2 → R3 → **F3 格式闭合** |

* 归属可调：`s2.4`／`s2.5`／`s3` 归 Seg2 还是 Seg3，按"由谁执行"判——译者自校归 Seg2，独立校者归 Seg3。调整须走 ADR，不改编号。
* **段间契约**：`Seg(n+1)` 的输入 = `Seg(n)` 的出口产物。Seg1 出口是"锁定钉的 HTML ＋ 通过反校的 markdown ＋ 已闭合的格式差异"；Seg2 出口是"中文译文 ＋ 账本 ＋ 已闭合的中文格式"；Seg3 出口是"三审签字 ＋ CI 全绿"。
* 段的顺序固定：`Seg1 → Seg2 → Seg3`，不得跳段、不得换序。

## 二、1 段插入：三个具体例子

v2 无法表达的情形，在 v3 里都是合法的节点插入：

| 插入位置 | 新节点 | 类型 | 判据 | 对下游的影响 |
| --- | --- | --- | --- | --- |
| P1 与 P2 之间 | HTML 实体与编码规范化校验 | pipe | 实体表覆盖率、乱码零容忍 | **改变输入**：规范化若修正了实体，P2 的转换结果变 → 下游重走 |
| P2 与 P3 之间 | 表格结构规范化（列数／对齐／空单元格） | pipe | 表列数一致、`&#124;` 保义 | 只改格式 → 按 3.1 走虚拟补丁，下游不重走 |
| P3 之后（F1 之前） | 图注编号与 alt 文本核对 | pipe | 图注序号连续、alt 非空 | 只补记录 → 下游不重走 |

三个例子的共同点：**都是 pipe 型**（判据要写进 ADR），但**都可以插**。v2 把它们误判为"不可插"，因为它把 pipe 当成了"固定骨架"。

插入后的三条保证：
1. **相对序不变**（C8）：既有节点的先后关系不因插入而改变。
2. **标识不变**（C8）：既有节点的 id 永久保留，新节点用可插序（fractional index）。
3. **降级按三型判**（D 系列 ＋ 判据变更三型）：改变下游输入则重走，只补记录则原地补。

## 三、格式处理：段内闭合，不跨段

用户指出每段"内含格式处理阶段"。形式化为：

* 每段以**格式闭合节点 F_i** 收口，`Seg_i = [内容节点…] ++ [F_i]`。
* `F_i` 的判据是"本段产生的格式问题已全部处置"，**不是**"全文格式统一"。
* **格式不跨段**：Seg1 的格式问题不得留给 Seg2；Seg2 的中文格式不得留给 F3。

理由：格式问题在段内可见、可复现；跨段传递后，发现者与产生者分离，归因成本陡增。这也解释了为什么 `check_style` 在 s2.4／s3／CI 三处重复执行——它是**段末闭合缺失**的补偿。

## 四、公理（29 条，七组）

### 组 I · 真相

* **C1 锁源一致**：Seg1 的 P1 完成即锁 `Pin(e)`，此后不得改 `en/` 字节。〔承 v2〕
* **C2 源唯一裁决**：译文命题唯一裁决对象是 `En(e)`；旧译／缓存／记忆不作底稿。
* **C3 markdown 禁实质变动**：`yuanwen` 只许格式层偏离；`substantive` 禁入 markdown。

### 组 II · 记录

* **C4 三元钉可追溯**。
* **C5 事件只追加**：撤销以 `invalidate` 追加。
* **C6 派生禁回写**：`Done`／`Head`／`stale`／进度比为派生量。

### 组 III · 结构（v3 重写）

* **C7 三段固定**：流程分 Seg1／Seg2／Seg3，全序，不得跳段或换序；增段须改 ADR。
* **C8 节点可插**：段内**任意相邻节点之间**均可插入新节点；插入不改变既有节点的相对序与标识。〔**v3 修正**：v2 限"S 只插在 P4–R1"，错在把可插性绑在类型上〕
* **C9 类型定判据**：节点类型（pipe／stage／review／format）唯一决定其判据来源与降级策略；**类型不决定能否插入**。〔**v3 新增**〕
* **C10 R 最小集**：`{R1,R2,R3}` 为必选最小集，**可增不可减、不可跳过**；S 与 P 的数量不影响 R。〔修正 v2 的"R 不可扩展"，实为"不可缩减"〕
* **C11 段间契约**：`Seg(n+1)` 的输入必须等于 `Seg(n)` 的出口产物；跨段直接取更早产物视为违约。
* **C12 格式段内闭合**：每段以 `F_i` 收口，格式问题不得跨段。〔**v3 新增**〕

### 组 IV · 进度

* **C13 阶段单调**：`Done(e)` 只增不减，除 `invalidate` 扣除。
* **C14 饱和相对性**：`saturate(e) ⟺ Done(e) ⊇ 全部段的全部节点`；节点可插，故饱和随时可变假；进度报比值，不设毕业位。

### 组 V · 前置链

* **C15 单钉输入**：Seg1 之后的一切环节输入必须是 P1 锁定的同一 sha。
* **C16 转换可重放**：`yuanwen = convert(en ⊕ patches)` 可确定性重算。
* **C17 双向保真**：正向验转换等值，反向验渲染结构同构。
* **C18 差异二分**：差异必属 `format_only` 或 `substantive`；无法归类从宽判 3.2。
* **C19 格式不外溢**：`format_only` 只以虚拟补丁表达，物理文件均不改。
* **C20 实质不落 md**：`substantive` 只入勘误表与中文译注。

### 组 VI · 并发与分支

* **C21 写单元单写者**：并发以 `(entry, section)` 为单元。
* **C22 分支隔离**：返工在独立 attempt，merge 前不影响主干。
* **C23 合并单向**：merge 只追加事件。
* **C24 认领互斥**：同一写单元认领唯一且有租期。
* **C25 分支最小化**：返工分支只含需返工条目。

### 组 VII · 机器

* **C26 判官只读**。
* **C27 显式失败**。
* **C28 先登记后使用＋禁机械替换**。〔承 A13〕
* **C29 可追溯写**：结构化落盘写后读回核验。〔承 A14〕

## 五、推演规则（D1–D8）

D1 钉→门禁；D2 单源→校验；D3 失配→拒绝；D4 人判→留痕；D5 语义变更→回源；D6 不可逆→方向声明；D7 分支→只追加；D8 并发→单元锁。
（用 D 不用 R：`R1–R3` 已被三审占用。）

## 六、定理

* **T1 单调性**：无 `invalidate` 时 `Done` 单调；有则按失效集扣除，日志仍只追加。
* **T2 扩展不重做**：新增节点后已完成节点不需重做，除非新节点插入位置早于该节点且其判据能推翻其结论（三型：放宽不动、收紧补做、更换重走）。
* **T3 R 强制**：`saturate` 必含 R1–R3；段内节点为空时同样成立。
* **T4 并发可交换**：异写单元的事件可任意交错，派生结果一致。
* **T5 分支等价**：merge 后 `Done` 等于"主干事件 ∪ 分支事件 − invalidate"派生值。
* **T6 二分穷尽**：`format_only ∪ substantive = 全部差异`，互斥。
* **T7 反校不增语义**：P3 只发现与分类，不得修改内容。
* **T8 可插完备**（新）：对任意相邻节点对 `(n_i, n_{i+1})`，存在合法插入位；插入后段间契约不变。此定理即 v2 缺陷的形式化否定。

## 七、与 v2 的差异（修正记录）

| v2 | v3 | 原因 |
| --- | --- | --- |
| C7 阶段分 P／S／R，P 与 R 顺序不可变，S 可插 | C7 三段固定；C8 节点任意可插；C9 类型定判据 | v2 把可插性绑在类型上，导致 1 段锁死 |
| 可插域限定 P4–R1 | 取消可插域，全段可插 | 用户指出任意段都要能插 |
| R 不可扩展 | R 可增不可减 | 不能排除新增专项审核 |
| 无格式闭合概念 | C12 每段以 F 收口 | 用户指出每段内含格式处理 |
| 无段间契约 | C11 段间契约 | 段要能独立重跑，必须有明确接口 |

## 八、迁移

1. `rules/stages.json` 记录三段、节点、类型、判据、`replay_on_change`。
2. `task_ops` 的 `state` 由节点派生；节点 id 用可插序。
3. 既有六道三审映射到节点，不改编号；`s2.4`／`s2.5`／`s3` 的三段归属按 §1.2 默认值，调整走 ADR。
4. 存量 2 件 done、395 件 s2.5_checked 无损换算。
5. `check_stages` 的谓词：三段齐、节点序合法、类型有判据来源、每段有 F 节点、R 最小集在。

## 九、风险

* **段内插入过多 → 段失去意义**：缓解，每段节点数上限 12，超出即考虑拆段（拆段走 ADR）。
* **F 节点形式化**：若某段无格式问题，`F_i` 仍须存在并记"零差异"，否则无法区分"没查"与"查了没问题"（C27 显式失败）。
* **归属争议**：`s2.4`／`s2.5`／`s3` 的段归属会影响段间契约。缓解：默认按执行者划分，争议走 ADR，不在会话内自行决定。
