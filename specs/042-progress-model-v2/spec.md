## 一、模型转换：从游标到日志

旧模型把进度表达为**单一游标**（`state` 取 ORDER 中一值）。它无法同时满足"永不毕业"与"返工不回退"：游标只有一个位置，回退就必须覆盖原位置。

新模型把进度表达为**只追加的事件日志**，游标降级为派生视图：

| 旧 | 新 | 性质 |
| --- | --- | --- |
| `state`（当前位置） | `Done(e)`（已完成阶段集合） | 派生量，单调累积 |
| `revert-state`（回退） | `rework`（开分支） | 追加事件，不改写 |
| `done`（终态） | `saturate(e)`（相对当前 S 饱和） | 相对量，分母可变 |
| `ORDER`（唯一序列） | `S`（全序可插阶段集） | 主干序保持，允许插入 |

一句话：**日志是事实，进度是视图，毕业是相对于当前 S 的判定**。

## 二、原语

`Entry`（词条）、`En(e)`（原始字节）、`Pin(e)`（版本钉三元组）、`Section`（条目内的节，`## N.` 锚）、`S`（阶段集，全序可插）、`R`（验收集，固定 `{R1,R2,R3}`）、`Event`（完成事件）、`Attempt`（一次走查，含分支）、`Head`（当前 attempt 指针）、`Gate`（只读判定谓词）、`Session`（会话）、`Claim`（写单元租约）。

事件结构：

```
Event = (entry, stage, attempt, actor, at, evidence, kind)
kind ∈ {complete, invalidate, merge, claim, release}
```

`complete` 记录某阶段完成；`invalidate` 显式声明某次完成失效（不删除原事件）；`merge` 记录分支并入；`claim`／`release` 记录写单元租约。

## 三、公理（20 条，五组）

### 组 I · 真相

* **B1 钉一致**：`∀e: bytes(En(e)) = Pin(e)`。`en/` 与原始钉逐字节一致，偏离唯一出口是格式补丁池。〔承 A1；宪法 I；ADR-0062〕
* **B2 源唯一裁决**：译文命题的正确性唯一裁决对象是 `En(e)`；既有译文、缓存、中间产物、模型记忆均不作底稿。〔承 A2〕

### 组 II · 记录

* **B3 三元钉可追溯**：每件成品可回溯 `(pubinfo, archive_edition, sha256)`。〔承 A3〕
* **B4 事件只追加**：一切进度以事件表达；日志不可改写、不可删除。撤销以 `invalidate` 追加表达。〔强化 A4：从"状态只追加"升为"事件只追加"〕
* **B5 派生不得回写**：`Done`／`Head`／`stale`／进度百分比均为派生量，禁止把派生结果写回日志或任务 JSON。〔强化 A5：单一事实源下沉到事件层〕

### 组 III · 过程

* **B6 流程先行**：无方向声明（意图／目标／非目标／验收判据／作废条件／规范基线）不入质量门。〔承 A6〕
* **B7 阶段单调**：`Done(e)` 只增不减——除 `invalidate` 事件显式扣除；不存在"取消完成"的静默路径。〔新〕
* **B8 S 全序可插**：S 在主干上是全序集；新增阶段只能**插入**，不得改变既有阶段的相对序；插入不改既有阶段的编号标识。〔重构 A7：禁跳步由"S 全序 ＋ 饱和判定"蕴含〕
* **B9 R 不变量**：任何有效 attempt 必须完成 `{R1,R2,R3}`；S 的数量、种类、插入位置**不影响** R 的要求。R 不属于 S，不参与 S 的扩展。〔新，用户主张④〕
* **B10 终审主权**：R3 仅由用户显式指定的会话执行（`--mandate`，缺失即拒）。〔承 A9〕
* **B11 饱和相对性**：`saturate(e) ⟺ Done(e) ⊇ S_current ∪ R`。因 S 可扩展，饱和永远可能变假；进度以 `|Done(e) ∩ S| / |S|` 与 `|R 完成| / 3` 两维报告，不设布尔毕业位。〔新，用户主张①〕

### 组 IV · 并发与分支

* **B12 写单元单写者**：并发以写单元 `(entry, section)` 为粒度；同一写单元全局单写者，不同写单元可并行。原 A10 的"全局单写入者"下调为"单元单写者"，其实质（避免并发写交错）保留。〔修订 A10，用户主张⑤〕
* **B13 分支隔离**：返工在独立 `Attempt` 中进行；`merge` 之前，分支事件不进入主干派生视图，不影响其他条目。〔新，用户主张③〕
* **B14 合并单向**：`merge` 只向主干追加事件并记录来源，不改写主干既有事件；合并冲突不得以覆盖解决。〔新〕
* **B15 认领互斥**：同一写单元的 `Claim` 全局唯一且有租期；租期到期未 `release` 视为可抢占，抢占须记 `invalidate` 理由。〔新〕
* **B16 分支最小化**：返工分支只包含需返工的条目（写时复制）；未涉条目共享主干完成状态，不复制事件。〔新，ZFS clone 语义〕

### 组 V · 机器

* **B17 判官只读**：判定器不得同时具备写回能力；规则升门须填机检谓词／预期命中数／幂等证明／一行回退。〔承 A11〕
* **B18 显式失败**：禁静默跳过与静默兜底降级；前置失配即硬失败；抓取相邻请求 ≥5 秒并留痕。〔承 A12〕
* **B19 先登记后使用＋禁机械替换**：术语／人名先登记后使用；语义层变更禁以脚本批量套改，修复以句／段为单位回源。〔承 A13〕
* **B20 可追溯写**：结构化落盘一律写后读回核验，不符即抛错。〔承 A14〕

## 四、推演规则（R1–R8）

* **R1 钉→门禁**：机检面公理的可执行谓词必须入 GATES 或步级挂钩。
* **R2 单源→校验**：每个登记源须有对应性校验工具。
* **R3 失配→拒绝**：前置谓词失配即拒绝推进（exit 3），禁降级放行。
* **R4 人判→留痕**：语义结论必须落 evidence 且可机检其存在。
* **R5 语义变更→回源**：词面／句法／术语变更必须回 `En` 对照后逐处人工改。
* **R6 不可逆→方向声明＋护栏**：结构重排、批量改写、数据格式、对外发布前置方向声明与回退保障。
* **R7 分支→只追加**：任何返工以分支表达；合并只追加事件，冲突走人工裁定而非覆盖。
* **R8 并发→单元锁**：任何并行写必须先 `claim` 写单元；无认领的写入视为无效事件，不入日志。

## 五、定理

* **T1 单调性**：无 `invalidate` 时 `Done(e)` 单调不减；有 `invalidate` 时按失效集扣除，而日志仍只追加。二者不矛盾——单调性属于日志，非单调性属于派生。
* **T2 扩展不重做**：新增阶段 `S'` 后，已完成阶段不需重做，除非 `S'` 插入位置早于某已完成阶段且其判据能推翻该阶段结论（此时按判据变更三型处理：放宽不动、收紧补做、更换重走）。
* **T3 R 强制**：任何 `saturate(e)` 判定必含 `{R1,R2,R3}` 的完成事件；S 只有 1 个阶段时同样成立。
* **T4 并发可交换**：若两个会话的写单元不同（异 entry 或异 section），其事件可任意交错，派生结果一致。
* **T5 分支等价**：`merge(a')` 后主干的 `Done(e)` 等于"主干事件 ∪ a' 事件 − invalidate"派生值；旧事件不被修改。

## 六、S 环节的扩展协议（三位一体 → S）

* **定义**：`S_i = (spec_i, plan_i, tasks_i)`，一个 S 环节由一份三位一体定义；映射 `σ: Spec → S` 允许合并（多对一），不允许一 Spec 派生多 S。
* **判定新 S 还是并入**：比较判据集合——新 Spec 的 `criteria ⊄` 任何既有 `S_j` 的 `criteria` → 新增 S；可被子集覆盖 → 并入；部分重叠 → 新增并标注依赖。
* **插入位置**：由 `entry`／`exit_to` 声明；序用可插序（fractional index，字典序字符串），**不重编号**，既有阶段标识永久不变。
* **主干不变**：插入只增加节点，不改变既有节点相对顺序（B8）。
* **每条 S 必带三字段**：`criteria`（含检查器与档位）、`replay_on_change`（`none`｜`patch`｜`from:<stage>`｜`full`）、`authority`（正文锚）。
* **R 恒定**：S 的插入不影响 R 的构成与顺序（B9）。

## 七、并发模型（写单元与认领）

* **写单元**：`(entry, section)`。`section` 取 `## N.` 锚；补充材料以文件为单元。
* **认领**：`Claim = (unit, session, at, lease_until)`，存 `tasks/<letter>/<slug>.claims.json`（入库，随批次提交）。
* **并行边界（关键修正）**：并行只适用于**可分片环节**——`draft`（分节起草）与 `s1`（分节对照）。`s2`（语体）、`s2.4`（术语与体例）、`s2.5`（全局密度与节集合）、`s3` 及 R 链必须**全文串行**，理由：语体一致性、术语主形锁定、密度统计、节集合对账都是全文属性，分片会引入局部最优。
* **合并**：按 section 序拼接，逐节校验 section 哈希；哈希不符即拒绝合并（B18），不得覆盖。
* **认领粒度建议**：条目级认领与节级认领并存，条目级优先（减少同一词条内多会话的语体漂移）。

## 八、返工模型（分支 · 克隆 · 合并）

* **触发**：上游修订、判据更换、审计发现系统性缺陷、用户裁定。
* **分支**：`rework(e, cause)` 创建 `Attempt a'`，`base = snapshot(e, head)`；`a'` 只记录 `e` 的新事件（B16）。
* **隔离**：`a'` 未 `merge` 前，主干 `Done(e)` 不变（B13）；其他会话仍见旧状态。
* **合并**：`merge(a' → main)` 追加 `a'` 的事件与一条 `merge` 事件（含来源 attempt、diff 摘要、actor、at）。
* **失效**：若返工证明某历史阶段结论错误，追加 `invalidate(e, stage, reason, by)`；`Done` 派生时扣除该阶段。
* **禁止**：不得删除事件、不得改写 `attempt` 归属、不得以"重跑覆盖"代替 `invalidate`（B4、B14）。

## 十、迁移路径

1. **只读换算**：由现有任务 JSON 的 `steps` 派生事件流（`step` → `stage`，`at` → `at`，`evidence` → `evidence`，`actor` → `actor`）。`revert-state` 记录转为 `invalidate` ＋ 新 attempt。
2. **并行运行**：`task_ops` 保留 `state` 作为派生视图（由事件流计算），不改变现有命令面；`advance` 内部改为追加事件。
3. **认领上线**：先做条目级认领（复用 `campaign` 的 claim/release），节级认领随后。
4. **分支启用**：`rework` 命令先支持"单条目分支"，验证合并与失效语义后再扩到批次。
5. **S 表**：`rules/stages.json` 记录 `S ∪ R`，`R` 另立字段并置 `locked: true`。
6. **旧模型退场**：`ORDER` 降级为"S 的默认序"参考实现，不再是唯一事实源；保留一个版本周期供对照。

## 十一、代价与风险

* **代价**：事件日志比单字段游标多出一次派生计算（每次 `show` 需聚合）；`tasks/` 体积增长约 1 个数量级；并发认领引入租期与抢占语义，需要新的失败处置条款。
* **风险一（最高）**：条目内并行与语体一致性冲突。缓解：并行只到 `draft`／`s1`，`s2` 起全文串行；条目级认领优先于节级。
* **风险二**：S 无限制扩展会让分母膨胀、进度长期低位，产生"永远做不完"的心理压力。缓解：分母只计"当前活跃 S"，归档 S 单列。
* **风险三**：分支合并的冲突处置若无明确裁决者，会退化为人工拉锯。缓解：冲突一律转 `rules/06` 的并发纪律，由用户裁定，不以覆盖收场。
