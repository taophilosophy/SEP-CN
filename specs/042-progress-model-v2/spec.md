## 方向声明（rules/08 §1）

* **意图复述**：用户给出六阶段主干——① 拉取／比较／更新 HTML，完成后锁 sha；② 由 ① 更新英文 markdown；③ 由 ② 的渲染结果反向校对 ① 的 HTML（3.1 格式变动＝虚拟补丁，转换时自动打入；3.2 实质文字变动＝勘误表＋译注，翻译时打入）；④ 正式翻译预处理；⑤ S 阶段；⑥ R1–R3 恒定。并重申：无 done、只有阶段完成标记；三位一体必对应 S 或并入；返工是只处理需返工条目的平行世界；条目间与条目内均并行。
* **目标**：把六阶段划为三类（P／S／R），给出"实质文字变动"的可机检定义，重建 26 条公理与 8 条推演规则，并给出与 ADR-0062／0063／0052 的对接。
* **非目标**：不改任何工具与任务数据；不裁定 3.1／3.2 的具体判定阈值（由 `norm` 的实现另立卡）；不删除 `specs/041`。
* **验收判据**：① 六阶段每段有类型（P／S／R）、判据与产物；② `substantive` 与 `format_only` 二分为全划分（无第三类、互斥）；③ 每条公理有判面与载体；④ 主干顺序在 S 插入前后保持不变。
* **作废条件**：若 `norm` 无法在不误判中文与数学公式的前提下实现二分，则 §四 作废，退回"差异全入勘误表"的粗粒度方案。

## 一、三类阶段：P / S / R

阶段不是一个平面上的六个点，而是三种**性质不同**的对象。混为一谈正是旧模型"done 说不清""环节重复看不见"的根源。

| 类 | 定义 | 扩展性 | 判据来源 | 实例 |
| --- | --- | --- | --- | --- |
| **P**（Pipeline，管线） | 全库统一、与上游同步的机械步骤 | **不可由单个 Spec 扩展**；改则改 ADR | ADR ＋ 工具 docstring | P1 锁源、P2 转换、P3 反校、P4 预处理 |
| **S**（Stage，工位） | 与词条内容相关的生产环节 | **可插**：一份三位一体增设一个 | 该 Spec 的 `criteria` | 既有 draft／s1／s2／s2.4／s2.5／s3 及将来新增 |
| **R**（Review，质检） | 恒定验收链 | **不可扩展、不可跳过** | rules/04 ＋ ADR-0054 | R1、R2、R3 |

**主干**：`P1 → P2 → P3 → P4 → [S₁ … Sₙ] → R1 → R2 → R3`

* `[S₁…Sₙ]` 是**可插域**，S 只允许插在 `P4` 之后、`R1` 之前。
* P 与 R 的顺序**永久不变**；S 的数量与内容可变，但内部全序（B8 → C8）。
* 返工分支可自 `P3` 或任意 `S_k` 起算，不影响主干顺序。

## 二、P 段定义

### P1 锁源

* **动作**：抓取 `index.html`／`notes.html`／补充材料与图片；与既有钉比较；有变则更新并登记。
* **判据**：包完整性（引用闭包）、页面真实性（签名／非截断）、哈希登记。
* **产物**：`en/<slug>/`（物理不可变）＋ `baseline/entries.json` 的钉 `(pubinfo, archive_edition, sha256)`。
* **锁**：P1 完成即锁 sha；此后 P2–S–R 全部以该 sha 为唯一输入（C12）。
* **对应**：`fetch_entry`／`fetch_audit`／`en_integrity`／`divergence`。

### P2 转换

* **动作**：由 P1 的 HTML 生成英文 markdown（`yuanwen/`），**格式层虚拟补丁在此打入**（3.1），文字层不做任何变动（3.2 禁入，C3）。
* **判据**：`convert(en ⊕ patches)` 可重放等值（I2）、文字流等值（I3）、补丁命中计数等于 `expect`。
* **产物**：`yuanwen/<letter>/<slug>.md`、转换登记（md 哈希＋源哈希）。
* **对应**：`yuanwen.py`、`en_patch_lib`、`check_yuanwen_fidelity`、`check_en_patches`。

### P3 反校

* **动作**：把 P2 的 markdown **渲染**回结构（标题层级、列表、表格、脚注、数学块），与 P1 的 HTML 逐结构比对。这是**反向**核验：不是问"转换是否忠实于字节"，而是问"渲染结果是否还原了原文的结构语义"。
* **判据**：结构树同构（节层级、列表层级、表列数、脚注序号、数学块位置）；差异按 §四 二分。
* **产物**：差异清单（每条标 `format_only` 或 `substantive`）＋ 处置记录。
* **对应**：新增能力；现有 `check_yuanwen_fidelity` 只做正向等值，不做渲染反校。

### P4 预处理

* **动作**：建任务、写方向声明、注入登记册术语摘录、建段落账本、确认 `errata(e)` 条目已就绪。
* **判据**：任务 JSON 的 `evidence` 首条为方向声明；账本段落数与源段数一致；`errata` 条目全部有"中文承载"判定。
* **产物**：任务记录、账本、注入清单。
* **对应**：`task_ops create`、`fan-yi-mu-ban` §6。

## 三、S 段（可插生产）

* 每个 S 由一份三位一体（spec／plan／tasks）定义，判据取该 Spec 的 `criteria`。
* 新增或并入的判定：`criteria ⊄ 任何既有 S_j` → 新增；否则并入（图三）。
* 序用可插序（fractional index），既有 S 的标识永久不变。
* 既有 S 清单（首批）：`draft`、`s1`、`s2`、`s2.4`、`s2.5`、`s3`。它们由既有 ADR 追认，不重编号。
* **每条 S 必带**：`criteria`（检查器与档位）、`replay_on_change`（`none`／`patch`／`from:<stage>`／`full`）、`authority`（正文锚）。

## 四、3.1／3.2 的形式化（差异二分）

### 4.1 定义

设 `norm: Text → Text` 为规范化函数，依次执行：折叠连续空白为单空格、去行尾空白、去行首列表标记（`^\s*(\d+[.)]|[-*+])\s+`）、统一缩进为层级数、去空行。

对同一内容的两份表示 `t₁`（HTML 文本节点序列）与 `t₂`（markdown 文本流）：

* **格式变动**（3.1）：`norm(t₁) = norm(t₂)` 且 `t₁ ≠ t₂`
* **实质文字变动**（3.2）：`norm(t₁) ≠ norm(t₂)`

**二分律**：任一差异必属且仅属其一（互斥、穷尽）。不存在"既非格式又非实质"的第三类；若出现无法归类的差异，判为 3.2 并从宽——宁可登记勘误，不可静默放行（C24）。

`norm` 的边界：中文全半角、数学定界符、实体反解、代码块内空白**不折叠**（否则误判）。这些排除项进白名单，白名单缺项即判 3.2。

### 4.2 处置

| 类 | 处置 | 写入位置 | 是否改物理文件 |
| --- | --- | --- | --- |
| 3.1 格式 | 虚拟补丁，P2 转换时自动打入（作用于 P1 的 HTML 逻辑视图） | `baseline/en-patches/<id>.patch` ＋ `INDEX.json` | **否**（HTML 与 markdown 均不改） |
| 3.2 实质 | 入全局勘误表；中文侧由译注承载；翻译时按正确读法呈现 | `specs/001/results/en-errata.md` ＋ 中文 `## 译者注释` 节 | **否**（markdown 禁改，C3） |

**虚拟补丁的语义**：补丁不改变 `en/` 的字节，只在 P2 读取时形成"逻辑上的 HTML'"；`yuanwen` 由 `convert(HTML')` 产出。补丁失配即硬失败（命中计数不符），不降级。

### 4.3 与既有条款的对接

* ADR-0062 的"三出口"（文字→勘误＋译注；格式→补丁池；转换器缺陷→改转换器）与本节同构，本节补的是**判定谓词**与**反校方向**。
* ADR-0063 的 I2／I3 是"正向等值"；P3 补"反向结构同构"。两者共同构成双向保真。
* 补丁准入谓词沿用 `en_patch_lib` 的"去空白后 find ≡ replace 或剥标签后 find ≡ replace"；与 §4.1 的 `norm` 保持同一口径，禁两套实现。

## 五、公理（26 条，六组）

### 组 I · 真相

* **C1 锁源一致**：P1 完成即锁定 `Pin(e)`；此后一切派生以该 sha 为唯一输入，锁后不得再改 `en/` 字节。〔承 A1／B1〕
* **C2 源唯一裁决**：译文命题的唯一裁决对象是 `En(e)`；旧译、缓存、中间产物、模型记忆不作底稿。〔承 A2／B2〕
* **C3 markdown 禁实质变动**：`yuanwen` 相对 `convert(en ⊕ patches)` 只允许格式层偏离；任何 `substantive` 变动禁止写入 markdown。〔新，用户主张"英文 markdown 禁止做实质性文字变动"〕

### 组 II · 记录

* **C4 三元钉可追溯**：成品可回溯 `(pubinfo, archive_edition, sha256)`。〔承 A3／B3〕
* **C5 事件只追加**：进度以事件表达；撤销以 `invalidate` 追加，不删事件。〔承 B4〕
* **C6 派生禁回写**：`Done`／`Head`／`stale`／进度比均为派生量，不得回写日志或任务 JSON。〔承 B5〕

### 组 III · 阶段结构

* **C7 三类阶段**：阶段分为 P／S／R 三类；P 与 R 的顺序不可变，S 可插；类型混用即违规。〔新，用户六阶段划分的形式化〕
* **C8 S 全序可插**：S 在可插域内全序；插入不改变既有 S 的相对序与标识。〔承 B8〕
* **C9 R 不变量**：任何有效 attempt 必须完成 `{R1,R2,R3}`；P、S 的数量与内容**不影响** R 的要求。〔承 B9，用户"无论如何 R 都强制"〕
* **C10 阶段单调**：`Done(e)` 只增不减，除 `invalidate` 显式扣除。〔承 B7〕
* **C11 饱和相对性**：`saturate(e) ⟺ Done(e) ⊇ P ∪ S_current ∪ R`；因 S 可扩展，饱和随时可变假；进度报比值，不设布尔毕业位。〔承 B11，含 P 段〕

### 组 IV · 前置链

* **C12 单钉输入**：P2–P4、S、R 的所有输入必须是 P1 锁定的同一 sha；钉外输入视为无效。〔新〕
* **C13 转换可重放**：`yuanwen = convert(en ⊕ patches)` 必须可由原始物与补丁集确定性重算，同输入必得同输出。〔承 I2〕
* **C14 双向保真**：正向验"转换等值"（I2／I3），反向验"渲染结构同构"（P3）；两者皆过方为保真。〔新〕
* **C15 差异二分**：`en` 与 `yuanwen` 的任何差异必属 `format_only` 或 `substantive` 之一；无法归类者从宽判 3.2。〔新，§4.1〕
* **C16 格式不外溢**：`format_only` 的修正只以虚拟补丁表达，物理 `en/` 与 `yuanwen/` 均不改写。〔新〕
* **C17 实质不落 md**：`substantive` 的修正只入勘误表与中文译注，不写入英文 markdown；中文侧必须按正确读法呈现且译注存在。〔新〕

### 组 V · 并发与分支

* **C18 写单元单写者**：并发以 `(entry, section)` 为写单元；同单元单写者，异单元可并行。〔承 B12〕
* **C19 分支隔离**：返工在独立 attempt；merge 前不影响主干派生。〔承 B13〕
* **C20 合并单向**：merge 只追加事件并记录来源，不改写主干。〔承 B14〕
* **C21 认领互斥**：同一写单元认领全局唯一且有租期。〔承 B15〕
* **C22 分支最小化**：返工分支只含需返工条目（写时复制）。〔承 B16〕

### 组 VI · 机器

* **C23 判官只读**：判定器不得写回；升门须填谓词／命中数／幂等／回退。〔承 A11／B17〕
* **C24 显式失败**：禁静默跳过与兜底降级；失配即硬失败。〔承 A12／B18〕
* **C25 先登记后使用＋禁机械替换**：术语先登记；语义变更逐处回源。〔承 A13／B19〕
* **C26 可追溯写**：结构化落盘写后读回核验。〔承 A14／B20〕

## 六、推演规则（D1–D8）

> 用 D（derivation）而非 R：`R1–R3` 已被三审占用，二者不得共用编号（本体系自检时的第一处冲突）。

D1 钉→门禁：机检面公理的可执行谓词必须入 GATES 或步级挂钩。
D2 单源→校验：每个登记源须有对应性校验工具。
D3 失配→拒绝：前置谓词失配即拒绝推进（exit 3）。
D4 人判→留痕：语义结论必须落 evidence 且可机检其存在。
D5 语义变更→回源：词面／句法／术语变更必须回 `En` 对照后逐处人工改。
D6 不可逆→方向声明＋护栏。
D7 分支→只追加：任何返工以分支表达；合并只追加事件，冲突走人工裁定。
D8 并发→单元锁：任何并行写必须先 `claim` 写单元；无认领的写入视为无效事件。

## 七、定理

* **T1 单调性**：无 `invalidate` 时 `Done` 单调；有 `invalidate` 时按失效集扣除，日志仍只追加。
* **T2 扩展不重做**：新增 S 后已完成阶段不需重做，除非新 S 插入位置早于该阶段且判据能推翻其结论（三型：放宽不动、收紧补做、更换重走）。
* **T3 R 强制**：`saturate` 必含 R1–R3；S 为空时同样成立。
* **T4 并发可交换**：异写单元的事件可任意交错，派生结果一致。
* **T5 分支等价**：merge 后 `Done` 等于"主干事件 ∪ 分支事件 − invalidate"派生值。
* **T6 二分穷尽**：`format_only ∪ substantive = 全部差异`，且 `format_only ∩ substantive = ∅`。〔由 §4.1 定义直接得〕
* **T7 反校不增语义**：P3 只能发现差异并分类，不得修改内容；任何"顺手修正"违反 C3 与 C17。

## 九、迁移

1. **P 段命名**：`fetch／yuanwen／en_integrity` 的行为不变，只在 `rules/04` 增"P1–P4"小节，把既有工具挂到对应段。

## 十、风险

* **P3 误判率**：结构树比对对数学块与表格极易误报。缓解：先只读、分批标定、白名单显式登记，禁"为了全绿而放宽 `norm`"。
* **`norm` 双实现**：若 P3 与 `en_patch_lib` 各写一套规范化，必然漂移。缓解：`norm` 唯一实现放 `en_patch_lib`，P3 引用它。
* **S 无限制扩张**：分母膨胀。缓解：只计"活跃 S"，归档单列。
* **条目内并行与语体一致性**：并行只到 `draft`／`s1`；`s2` 起全文串行（同 v1 结论）。
