## 网站结构事实基础（2026-10-27 实测）

* **上游目录**：SEP 官方目录快照含 1872 个正式条目与 654 条别名；本地 SUMMARY 含正式条目 1799、别名 604、导航节点 137。
* **en/ 词条包**：正文 index.html（BEGIN/END ARTICLE 界定）+ 脚注 notes.html（存在性因词条而异）+ 补充材料 + 词条图片；引用闭包已经审计收敛（1724/1724 包内资产完整）。
* **公式**：SEP 使用 MathJax 源码文本（行内 `\(...\)`、行间 `\[…\]`），无 MathML；转换只统一定界符不改内容。
* **中英结构对应**：词条目录 `<letter>/<slug>.md`（中文）与 `yuanwen/<letter>/<slug>.md`（英文）逐字符镜像；SUMMARY 条目链接两侧同构。
* **已知缺口**：上游增量 74 条未接入；137 个导航节点与 24 个派生 slug 待裁定；VitePress 发布站未在新结构下构建验证。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - SUMMARY 目录与上游完全一致（Priority: P1）

对全部条目（含别名、递归条目、mu-lu-s 分类对应）执行"SUMMARY ↔ 官方快照 ↔ mu-lu-s"三方一致性核验：每个上游条目在 SUMMARY 有对应行（或显式登记为增量/豁免），每个别名链到正确的目标词条，递归条目不产生断链，mu-lu-s 分类覆盖 SUMMARY 全部正式条目，中英两侧目录结构逐字符一致。核验按 a–z 批次并行执行，结果逐批出具报告。

**Why this priority**: 目录是全流程的单一事实源；目录不一致则后续一切环节的"对应关系"失去裁判依据。

**Independent Test**: 任取一个批次，运行三方核验，输出差异清单（缺失/多余/别名错链/分类缺口），零差异或差异全部有显式裁定记录。

**Acceptance Scenarios**:

1. **Given** 任一字母批次，**When** 执行三方核验，**Then** 差异清单中每一条都指向：显式裁定（豁免/增量登记/待处理任务）或修正提交，无静默差异。
2. **Given** 一条别名条目，**When** 核验，**Then** 其链接指向目标词条目录且目标真实存在。
3. **Given** mu-lu-s 分类目录，**When** 核验，**Then** SUMMARY 每个正式条目在 mu-lu-s 有分类归属（或登记为刻意不收录），链接文本与 SUMMARY 一致。

### User Story 2 - 抓取内容完全离线（Priority: P1）

对每个词条包（en/）确认应抓取的内容完整离线：正文、脚注、补充材料、图片，且包内被引用的资产无一缺失。缺失项区分"上游本就没有（缺省件）"与"应抓未抓（可补）"，后者补抓并登记。核验按批次并行，全库收敛后出具覆盖率报告。

**Why this priority**: en/ 是翻译与复核的唯一依据源；离线不完整则复核环节无法回原文。

**Independent Test**: 任取批次执行完整性审计，报告"审计数/完整数/缺省件/可补抓"四项计数，可补抓项为 0。

**Acceptance Scenarios**:

1. **Given** 任一词条包，**When** 审计其引用闭包，**Then** 被引用资产 100% 在包内或登记为缺省件。
2. **Given** 一个含脚注/图片/公式的词条，**When** 审计，**Then** 脚注文件、图片文件在包内，公式源码在正文中原样可见。
3. **Given** 断网环境，**When** 打开词条包，**Then** 翻译与复核所需的全部材料可离线获取。

### User Story 3 - 转换保真与中英结构一致（Priority: P1）

确认 HTML 到 markdown 的转换"完美"：正文章节集合与英文原文一致（节不增不减不重排）、公式内容逐字符保留（仅定界符规范化）、表格/脚注/图片引用齐全、中英两侧文件一一对应且结构（节序列）一致。核验按批次并行，出具逐词条保真报告。

**Why this priority**: yuanwen 是三审三校的对照底稿；转换失真会直接进入译文。

**Independent Test**: 任取词条，比对其 markdown 节序列与英文原文节序列（数量、顺序、标题），并抽查公式/表格计数一致。

**Acceptance Scenarios**:

1. **Given** 任一词条，**When** 比对中英节序列，**Then** 节数量与顺序一致（特殊节差异逐一登记）。
2. **Given** 重数学词条，**When** 抽查公式，**Then** 每条公式的源码内容在转换产物中原样可见（定界符除外）。
3. **Given** 含脚注/表格词条，**When** 抽查，**Then** 脚注定义与引用一一配对、表格数量与原文一致。

### User Story 4 - 后续修订机制（Priority: P2）

建立"上游修订可被本地吸收"的常设机制：定期检测上游目录与内容变化，每条变化产出变更记录并定位到受影响的中文文档与节；变更进入任务队列，按"仅变更段重校"原则处理；处理完成后变更记录闭环（处理人与结果可追溯）。

**Why this priority**: 修订吸收机制决定存量翻译的长期正确性；依赖前三个故事建立的对应关系。

**Independent Test**: 用一次模拟上游变更（或真实变更）验证：变化被检测、变更记录产出、受影响文档被定位、任务建立并可跟踪至闭环。

**Acceptance Scenarios**:

1. **Given** 上游某词条实质修订，**When** 检测流程运行，**Then** 该词条进入变更队列且变更记录含节级定位。
2. **Given** 一条变更记录，**When** 处理完成，**Then** 记录含处理人、处理方式与验证证据，状态闭环。
3. **Given** 无上游变化，**When** 检测流程运行，**Then** 报告"无变化"且不产生空任务。

### User Story 5 - 复核与校对机制强化（Priority: P2）

每个环节的产物都有独立于产出者的复核：复核人对"结论是否超出证据"负责，发现存疑（史实、引文、年代、译法）时必须提问并回原文核对，禁止凭常识改写或静默取舍；提问与裁定全程留痕。复核按批次抽查（含换命令/换环境的独立重算）。

**Why this priority**: 复核是零信任原则在人的环节的落地；依赖前三者提供的可对照材料。

**Independent Test**: 任取一批已复核产物，抽查复核记录：每条存疑有提问与裁定，每条结论有证据锚点。

**Acceptance Scenarios**:

1. **Given** 一批复核记录，**When** 抽查，**Then** 存疑项 100% 有提问与裁定留痕，无静默取舍。
2. **Given** 复核人未回原文核对的改写，**When** 抽查对照英文源，**Then** 该改写被标记为违规并回炉。

## Requirements *(mandatory)*

### FR-001 三方目录一致性核验（SUMMARY ↔ 官方快照 ↔ mu-lu-s）
* 优先级：P1；每批次独立可验。
* 验收判据：差异清单零静默项；别名 100% 链接有效；递归条目不产生断链；mu-lu-s 覆盖全部正式条目或显式登记。
* 证伪条件：任一上游条目既不在 SUMMARY 也无增量/豁免登记。

### FR-002 抓取完整性审计与补齐
* 优先级：P1。
* 验收判据：引用闭包收敛（审计轮次直到 0 可补抓）；缺省件 100% 显式登记；全库覆盖率报告出具。
* 证伪条件：任一被引用资产缺失且无缺省件登记。

### FR-003 转换保真核验（节序列/公式/表格/脚注/图片）
* 优先级：P1。
* 验收判据：中英节序列一致（差异显式登记）；公式源码原样可见（定界符规范化除外）；脚注配对 0 孤儿；表格计数一致。
* 证伪条件：任一公式内容在转换产物中缺失或被改写。

### FR-004 中英结构一致核验
* 优先级：P1。
* 验收判据：目录逐字符镜像（文件名与相对路径）；节序列对照报告按批次出具。
* 证伪条件：任一词条中英两侧文件名或节序列不一致且无登记。

### FR-005 修订吸收机制
* 优先级：P2。
* 验收判据：变化检测→变更记录（节级定位）→任务队列→闭环，全链留痕；无变化时零噪音。
* 证伪条件：真实修订未被检测或变更记录无节级定位。

### FR-006 复核留痕机制
* 优先级：P2。
* 验收判据：存疑 100% 提问留痕；复核记录含证据锚点；批次抽查含独立重算。
* 证伪条件：任一改写无英文源锚点且无译注说明。

## Success Criteria *(mandatory)*

### Measurable Outcomes

* **SC-001**：三方目录核验报告按批次出具，静默差异 0（每条差异有裁定）。
* **SC-002**：全库抓取完整性收敛——可补抓 0，缺省件登记 100%，覆盖率报告出具。
* **SC-003**：中英节序列对照报告覆盖全部词条，不一致项 100% 显式登记或修正。
* **SC-004**：模拟修订全链演练通过（检测→记录→任务→闭环），留痕完整。
* **SC-005**：批次复核抽查通过——存疑留痕 100%、证据锚点 100%、独立重算 0 差异。

## Key Entities

* **条目（Entry）**：slug、别名链、所属批次、目录状态（SUMMARY/mu-lu-s/上游三方）。
* **词条包（Entry Package）**：正文、脚注、补充材料、图片、缺省件登记。
* **转换产物（Conversion）**：节序列、公式清单、表格计数、脚注配对、中英对照关系。
* **变更记录（Change Record）**：检测时间、节级定位、受影响文档、任务、闭环状态。
* **复核记录（Review Record）**：存疑提问、裁定、证据锚点、复核人、独立重算结果。

## Assumptions

* 上游目录快照（官方内容清单）为"上游一致"的裁判基准；快照自身的缺口（如个别条目缺失）按增量登记处理，不阻塞核验。
* "完美转换"的判定基准是转换产物的可复算性与内容保真，不是版式复刻（版式由本地发布体系提供）。
* 设计与执行允许不同会话分批并行：批次按 a–z 拆分，沿用既有批次账本与会话协议（认领互斥、断点续上、账本经版本库同步）；会话间无共享进行中文件。
* 项目由版本库管理，不建立任何备份文件（用户 2026-10-27 裁定）。
