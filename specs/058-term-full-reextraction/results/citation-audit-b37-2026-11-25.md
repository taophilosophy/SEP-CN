# 审定依据对账（批 37，2026-11-25）

## 一、为什么要对

术语表有 1,408 行依据写“审定名词库（termonline-all·学科，日期）”。凭证在本地缓存里，但缓存会被覆盖、键会被并、译法会被改——依据与凭证一旦脱节，就是“凭证失实”，比没依据更坏。

## 二、怎么对

`bin/audit_termonline_citations.py`（只读）。逐行取键与译法主形，按三种落名找缓存（整键 → 去括注 → 逐段），再把缓存里的 `hits[].cn` 与译法主形、以及依据里“审定作‘X’”的 X 比对；`hits` 只存每库前 20 条，故同时查原始回包全文。

三档结论：

* **ok**：凭证里有同形或所引之形。
* **page1-miss**：有凭证但所引之形不在首屏 80 条内——不足以判失实，列待复核。
* **no-cache**：三种落名都没有凭证文件——真缺位。

## 三、结果

| 档 | 行数 |
| ---- | ---- |
| ok | 1,327 |
| page1-miss（待复核） | 78 |
| no-cache（缺位） | 3 |

缺位三行已就地标注“待通道恢复补证”：`halting problem`（缓存落在旧键 `halting function` 下）、`right inverse`、`selector`。

## 四、过程中的两处修正

1. 首版只按“/”分段找缓存，把并键后的整键行全判成无凭证；改为**整键优先**后再分段。
2. `operational semantics (program theory)` 一类带括注的键，缓存落在去括注名下；补“去括注”候选后这类归零。

76 条首版“cn-mismatch”也随之更名 `page1-miss`——它们不是失实，只是对口条目不在首屏。

## 五、待办

* 78 条 page1-miss：通道恢复后按 key 翻页（`pageNo`）复核，或直接用界面“精确匹配”逐条看。
* 3 条缺位：通道恢复后补抓；抓不到则在依据列如实改记为文献依据，不能保留“审定命中”的表述。
