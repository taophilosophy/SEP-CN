# 术语在线通道行为与取数方法（2026-11-25）

## 一、现象

同一 token、同一 URL、同一浏览器页面，连续请求的返回在“有数据”与“全零”之间跳变。

| 时刻 | 请求方 | 词 | 结果 |
| ---- | ---- | ---- | ---- |
| 午后 | 浏览器（站点自身搜索按钮） | abduction | 第 1 次 0 条，第 2 次 1032 条 |
| 午后 | 浏览器（页面内注入 fetch） | abduction | 0 条 |
| 稍后 | 浏览器（页面内注入 fetch） | moral practice / quantum entanglement / informed consent | 626–4695 条，连发 3 次稳定 |
| 稍后 | 浏览器（拦截 XHR） | abduction | 第 1 次 0，第 2 次 1351 |
| 批量 80 词 | 页面内注入 fetch | 前 21 词 | 全部首查即回数据（241–8425 条） |
| 同上 | 同上 | 第 22–80 词 | 全部三次重试仍为 0 |
| 数分钟后 | 同上 | ability hypothesis / abduction | 仍 0；再隔一段时间恢复 |

## 二、结论

1. **不是 token 问题。** 同一 token 在浏览器里能取到数据；`getUserInfo` 一直返回 success。localStorage 的密文解密后是 JSON `{"value": “…”, "time": …, "expire": …}`，真正的 JWT 是其中 `value`（139 字符），直接把 195 字符整串当 token 会得到“token非法无效”。
2. **不是分库 id 变形。** `tmDatabase/listFront` 返回的 id 本就是 32 位补零形（`000…0000` 审定公布、`000…0001` 海峡两岸、`000…0002` 其他来源、`000…0006` 预公布、`000…0007` 站点默认）。按末位数字归一即可，此前把补零形当 UUID、判成“通道故障”是误判。
3. **是接口侧的间歇全零与节流。** 全零回包外层仍 `success:true`、HTTP 200，各库 `totalRecords=0`、`sourceStats/yearStats` 空；连发二十余次后进入长时间全零，隔数分钟至数十分钟恢复。表现为“前 N 次正常、之后一律空”，与限流窗口相符。

## 三、取数方法（现行）

以**浏览器页内 fetch**为主通道：页面同源发请求，带 `X-Access-Token`（JSON 的 `value`），不被前端指纹差异影响；抓到的结果按 `cnki_query` 的凭证结构写盘，审计仍走离线重放。

节流规则（据实测设定）：

* 单批不超过 20 词即停，批次之间留出恢复窗口；
* 词间间隔 ≥3 秒，遇全零立即重查一次（同词第二次常能命中预热），仍零则退避 15 秒、30 秒；
* 连续 5 词全零即判“进入限流”，停批等恢复，不写任何凭证；
* 每批开工先查 `abduction` 作正控制（应上千条），探针为零直接不写盘。
