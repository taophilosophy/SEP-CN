# 064 — 节点文档承载与全流程规格完备性审计（建议书）

- 编号：specs/064-flow-spec-audit；立项日期：2026-11-26；状态：评估类（结论＋证据＋建议，`rules/08` §14）；**不实施**，用户裁定后另立实施卡
- 承办：主会话（ADR-0034 主代理单干）
- 上位：`rules/pipeline.json`（22 节点结构事实源）、`rules/naming.json`（标识）、specs/061（标准矩阵）、specs/063（阶段轨）、`rules/09-process-standard.md`（过程与信息项凭证）、`.specify/templates/`（三件套模板）
- 方法：全库实读（不做推测）；每条结论附计数与文件位置

## 1 结论摘要

1. **三件套在库内不是常态**：62 个 spec 目录中仅 5 个齐全（spec＋plan＋tasks）＝8%，56 个只有 spec.md＝90%，1 个 spec＋plan。这不是遗漏，而是从未规定过“何时必须三件套”——**缺判据**，不是缺文件。
2. **没有一个节点有专属 spec 卡**：节点文档由四层承载（pipeline.json 结构、naming.json 标识、tools 判据、rules/04 作业规范），无一份 `specs/*-ex-04-*` 形态的卡。对节点要求“三件套”的前提本身不成立。
3. **最大缺口是源侧规则真空**：ex-01／ex-02／ex-03／ex-05 在 `rules/` 下**零条款**（ex-01 仅出现在 ADR-0080 的命名说明里，不是作业规范）；`rules/04` 只覆盖 ex-04 与 tr/rv/sg 链。整个源侧四工序没有规则家。
4. **3 个节点零判据**：ex-05、tr-05（tr-02 初译可判为零判据是设计合理，人工翻译无判据面）。ex-05 与 tr-05 同时零判据、零规则条款——存在性本身待复核。
5. **4 个判据无工具**：`errata_check`（应有，属漏建）、`review-verity`／`review-coherence`（审计类，合理）、`ci_all`（聚合类，合理）。
6. **标准锚点双写**：specs/061 §5 矩阵与 specs/063 §1.3 阶段表各写一套 22 节点标准；两处内容目前一致，但无双写校验，属单一事实源隐患。
7. **测试覆盖 7/22（32%）**：仅 ex-01／ex-02／ex-04／tr-01／tr-04／rv-02／rv-09 有可识别单测；其余 15 个节点的判据无测试。

## 2 事实一：三件套分布（实读）

| 组合 | 目录数 | 占比 | 代表 |
| ---- | ---- | ---- | ---- |
| spec＋plan＋tasks | 5 | 8% | 001 管线、002 术语检查、003 学术规范、006 一致性验证、060 六轴 |
| spec＋plan | 1 | 2% | 005 翻译战役 |
| 仅 spec | 56 | 90% | 其余专题／战役／评估卡 |

`contracts/` 仅 5 处（001、006、008、012、054）。

**判定**：齐全的 5 个全部是**带可执行判据的工具型卡**（检查器落地需要 plan 分解与 tasks 清单）；仅 spec 的 56 个多数是**战役／评估／叙事型卡**（spec 内含目标、验收、执行记录，plan/tasks 会与执行账重复）。形态差异有内在合理性，但**没有成文判据**，导致两种风险：工具型新卡可能漏建 tasks（实施步骤散在对话里），叙事型卡可能被机械要求补三件套（形式主义）。

## 5 必要性复核（逐项裁定建议）

| 对象 | 复核问题 | 建议裁定 | 理由 |
| ---- | ---- | ---- | ---- |
| 22 节点各建三件套 | 是否必要 | **否** | 节点已有四层承载（结构／标识／判据／规则），再建 66 份文档与 pipeline.json 重复；节点是**结构单元**，不是工程项 |
| 56 张单卡补 plan／tasks | 是否必要 | **否** | 战役／评估卡的实施步骤已在 spec 的 §执行记录与 `results/`，plan/tasks 是重复记账（001 的 tasks 与 execution-log 已有此问题） |
| 三件套判据 | 是否需要 | **是** | 仅需一条规则：**含可执行判据的新卡必须三件套**；评估／叙事卡 spec 单卡合法 |
| ex-05 存在性 | 是否必要 | **保留但必须给出判据** | markdown 语法层检查与 rv-09 的 check_style 有重叠；若确认零判据，则应并入 rv-09 或给 ex-05 明确检查清单，不能留“三无”（无判据／无测试／无规则） |
| tr-05 存在性 | 是否必要 | **并入候选** | tr-05（段内格式闭合）与 rv-09（体例终校）职责高度重叠，且零判据；建议二选一：并入 rv-09，或降为 tr-04 的检查项 |
| tr-02 零判据 | 是否缺口 | **否（设计合理）** | 初译为人工创作，无机判据面；其质量由 tr-03／tr-04 兜底；标为 audit 类即可 |
| errata_check | 是否必要工具 | **是** | rv-01 硬门包含勘误轴（ADR-0062/0065），无工具则硬门名不副实 |
| 061 与 063 标准双写 | 是否合并 | **是（单源）** | 061 §5 为权威矩阵；063 改为引用式（`std_ref` 指向 061 条目），S7 加一致性校验；否则改一处漏一处 |
| rv-03–08 无测试 | 是否补 | **是** | 六轴是现行判据的核心，无测试则“机检为筛”的筛选质量不可证 |

## 6 建议书（分级，不计成本口径）

### P0 结构完备（必须先做，否则后续判据无家）

1. **新增 `rules/11-source-side.md`（源侧工序规范）**——给 ex-01／02／03／05 一个规则家，与 ex-04 的源审计节并列。内容：抓取与钉的纪律（含并发与重试）、转换的保真边界（补丁生成与应用）、保真校验的 I2/I3 判据引用、格式层闭合的检查清单与 rv-09 的分工。同时在 `rules/README.md` 规则地图加一行。
2. **补 `errata_check` 工具**（或明示其判据载体现为 `check_en_patches --strict` 的勘误轴），使 rv-01 的硬门有实指。
3. **标准单源化**：061 §5 为权威；063 的 standards 列改为 `std_ref` 引用；check_stages 增加“063 标准引用可在 061 矩阵解析”校验。
4. **三件套判据成文**：写入 `specs/README.md` 头部与 `rules/09`——“含可执行判据（gate/工具）的新卡必须 spec＋plan＋tasks；评估／战役／叙事卡以 spec 单卡为合法形态”。现 5 张齐全卡全部符合此判据，56 张单卡亦符合，规则只是把既成事实明确化。

### P1 判据强化（补齐“三无”与测试）

5. **ex-05／tr-05 二选一处置**：给出两案供裁——
   - 案 A（保守）：保留节点，但必须给出判据清单（ex-05 挂 markdown 语法子集，tr-05 挂段内格式 5 项），并写入 rules/11；
   - 案 B（精简）：ex-05 并入 rv-09 的 check_style 面，tr-05 并入 rv-09；22 节点减为 20，阶段表同步（sg 预留不变）。
   建议案 A：节点是结构单元，删除会破坏 ADR-0080 的号段稳定与历史引用；但“三无”必须消除。
6. **六轴测试补齐**：rv-03–08 每判据至少 1 正 1 反例（沿用 tools/tests 现有模式），使 T1 升硬有回归网。
7. **stage_of 的节点覆盖**：对 tr-02 等 audit 类节点，stage_of 输出 `audit` 标记而非“无判据”。

### P2 精简与防复发

8. **check_stages 第 ⑩ 谓词：文档承载矩阵机检**——把本报告 §3 六列变成常设检查（缺项按列分级告警：规则缺＝红，测试缺＝告警，判据缺＝红）。这是防“节点悄悄长出来却没有文档”的结构防线，与 ADR-0079 的 S6 双登记同构。
9. **061／063 标准引用一致性纳入 CI**（随 ⑩ 谓词）。
10. **tr-05 与 rv-09 的重叠清单化**：列出两者检查项交集，作为案 A 的边界依据，避免今后重复检查。

### 不建议做的（明确非目标）

- 不为 22 节点各建 spec 三件套（与 pipeline.json 重复，违反单一事实源）。
- 不为 56 张单卡补 plan／tasks（形式主义，且与执行账重复）。
- 不废除 g0 级别以外的历史卡（历史凭证，ADR 只追加原则）。

## 7 验收判据（建议书自身）

1. 每条结论有实读计数与文件位置（§2–§4），无“凭印象”的判断。
2. 三件套分布、节点承载矩阵、覆盖率均可复算（附命令见 §8）。
3. 每条建议标明落点文件、成本档（P0/P1/P2）与不做的理由。
4. 不实施任何改动；P0–P2 待用户裁定后另立实施卡。
