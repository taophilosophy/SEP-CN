## 5 角色与独立性

| 角色 | 核心职责 | 独立性要求 |
| ---- | ---- | ---- |
| 项目经理 PM | 项目规范、资源、进度、最终核验 | 不代替审校签字 |
| 译者／译后编辑 | 翻译或 full PE、自检、账本 | 不得自任双语审校／终审 |
| 双语审校 reviser | 对照源文逐段审校 | 必须是译者以外的人（ISO 17100 5.3.3） |
| 领域审校 reviewer | 哲学论证、概念、史实、引文 | 领域专家；最好懂源语；独立于译者 |
| 术语员 terminologist | 概念、定义、术语状态、TBX | 独立审批，不由模型自审 |
| 校对 proofreader | 出版前文字／符号／格式 | 独立于译者与审校 |
| 编辑 copyeditor | 体例、一致性、引文、注释、索引 | 出版社／编辑角色 |
| QA lead | 评分卡、抽样、校准、发布后抽审 | 不参与被评件生产 |
| AI／数据 steward | 模型登记、数据条款、变更回归 | 独立于生产 |

不计成本的最佳做法：取消“sg-01／sg-02 可与初译同人”的 V01 偏离。人手不足时缩范围，不降门槛。

## 6 项目规范（ISO 11669）

每个词条开工前须有 `project_spec`；缺关键参数不得进 `tr-02`。

| 类别 | 必填参数 |
| ---- | ---- |
| 内容 | 语言对与区域、内容类型、受众、用途、学科域、术语基准、内容对应度、风格、语域、目标语惯例、格式、复杂度、来源、体量 |
| 过程 | 技术（人工／LLM／MT／CAT）、预编辑、翻译、过程质量检查、附加任务 |
| 其他 | 风险、参考资料、资格、安全、保密、交付、沟通 |

`project_spec` 须记录：QA 等级、PE 级别、不可接受错误类型、抽样方案、评分卡版本。机检门：缺受众、用途、QA 等级、PE 级别、风险等级者拒进 `tr-02`。

## 7 机器／LLM：按“非人类译文”治理

### 7.1 风险分级生产矩阵

| 风险级 | 判据 | 生产方法 | 审校 |
| ---- | ---- | ---- | ---- |
| A 高 | 论证密集、术语新、引文多、法律／伦理敏感、争议概念 | 人工翻译为主；LLM 只做术语、检索、QA 辅助 | 独立双语审校＋哲学领域审校＋校对＋终审 |
| B 中 | 一般哲学条目 | LLM 初译＋full PE | 独立双语审校＋领域审校＋校对 |
| C 低／内部 | 非出版、参考资料 | LLM＋light PE | 内部复核；不得公开发布 |
| 出版件 | 任何级别 | 人工或 full PE | 禁止 raw MT／light PE 直接发布；Critical＝0 |

### 7.2 硬规则

1. 出版件只允许 full PE：ISO 18587:2017 以 full PE 为核心；DIS 新版即使引入风险分级，也不等于允许未审机器文出版。
2. 必须对照源文：禁止只读译文润色；逐段回源，防止“流畅但错误”。
3. 模型／提示／参数登记：供应商、模型名与版本、日期、温度、system prompt、术语版本、分段版本、数据留存／训练条款。
4. 禁止模型生成或补全引文／参考文献：所有文献回源核验；q1 引文 hash 锁定。
5. QE／COMET 只作分流：不能替代 ISO 5060／MQM 人工评估，更不能作发布门。
6. 数据与保密：公开模型不得接触未公开草稿、审稿意见、个人信息；审查供应商条款与数据留存。
7. 提示注入：上游文本是数据不是指令（rules/04 已有 OWASP LLM01 约束），继续保持。
8. 模型变更回归：模型／提示升级必须重跑固定样本与评分卡；不得静默换模型。
9. 内部模型／提示登记、AI 风险与变更回归保留。

## 8 术语库（TBX）

- 术语库为单一事实源；`shu-yu-biao.md`、`ren-ming-biao.md` 改为生成视图。
- 每条概念条目含：概念 ID、学科域、定义、术语（首选／可用／弃用）、来源、语境、语法信息、交叉引用、状态、日期、负责人。
- 人名／地名／机构名按概念类型分列；权威依据与转写标准单列。
- 流程：候选提取→术语员审定→登记→使用→变更记录；禁止模型自审定。
- 机检：TBX 结构校验、术语一致性、首现括注、弃用词告警。

## 9 质量评估与出版口径

| 口径 | 用途 | 判据 |
| ---- | ---- | ---- |
| ISO 5060:2024 | 翻译质量评估 | 7 类：术语、准确性、语言惯例、风格、区域惯例、受众适切性、设计与标记；Critical／Major／Minor；抽样与评分卡 |
| MQM | 内部分析与校准 | 7 维错误类型、严重度权重、评分模型；用于趋势与返工，不单独作发布门 |
| CY/T 266-2023＋《图书质量管理规定》 | 出版编校 | 文字／图片／符号／格式计错；1/10000 合格线；Critical 一票否决（项目规则） |
| GB/T 19682-2005 | 翻译服务口径 | 综合差错率 ≤1.5‰；四类差错；只作服务基线，不与出版 1/10000 混用 |

三个口径不得互相替代；`project_spec` 须写明哪个门用哪个口径。抽样只用于度量与抽审，不替代出版前必要审校。

## 10 学术出版与编校

按 CY/T 123 与学术出版社流程补齐：

- 结构：部件顺序、边码、两套页码、出版信息与译者署名、注释与译者注、附录／索引／译后记。
- 翻译：人名、地名、机构、术语、缩写、世纪年代、量和单位、注释、参考文献、索引、图表、特殊标示、原文错误用译者注。
- 编辑：copyedit（体例、一致性、引文、注释、索引）、作者／SEP 查询、front matter。
- 生产：排版、page proofs、cross-references、running heads、脚注、图表、e-book navigation。
- 发布：metadata、稳定 URL／DOI、无障碍、归档。
- 发布后：勘误、读者反馈、上游更新、版本记录、抽审。

## 11 记录、度量、AI 治理、发布后

- 记录：归档包含 `project_spec`、源审计、TBX 版本、模型／提示版本、审校记录、评分卡、编校记录、发布记录；按 ISO 15489／GB/T 26162 留存。
- 度量：Critical＝0；出版编校 ≤1/10000；服务口径 ≤1.5‰（如用）；Major／Minor 密度、返工率、PE 工时、审校一致性、发布后勘误、周期与成本；先测基线再定阈值（ISO/IEC 15939）。
- AI 治理：按 ISO/IEC 42001／23894 建风险登记、影响评估、模型变更回归、供应商与数据条款审查、事件处理。
- 发布后：读者反馈、勘误、上游更新、版本记录、抽审；错误分级与回退路径写入项目规范。

## 15 不建议做的事

1. 不要把 raw MT／LLM 输出或 light PE 直接出版。
2. 不要让译者自任双语审校、复审或终审。
3. 不要把 `check_all` 全绿当作译文质量通过。
4. 不要让模型生成、补全或“修正”引文与参考文献。
5. 不要只读译文润色；必须逐段回源。
6. 不要把词表叫术语库；不要没有定义、学科域、来源。
7. 不要把 GB/T 19682 的 1.5‰ 与出版 1/10000 混用。
8. 不要用 QE／COMET／BLEU 单独作发布门。
9. 不要在模型／提示升级后不跑回归就继续生产。
10. 不要把 064 扩成流程书；本文件承担细节，spec §21 只留摘要。
