## 方向声明（rules/08 §1）

* **意图复述**：用户要求"为整个项目，基于当前软件工程理论和规则，工具链，建立公理体系，形式化充分性审计"。
* **目标**：①从宪法七原则、rules/09 已映射的软件工程理论（ISO/IEC/IEEE 12207/15289/1028/1044/15939、ISO 17100/18587、GB/T 1.1、CY/T 系列、MQM）与现行工具链中提炼一套公理体系（原语＋公理＋推演规则）；②对其做形式化充分性审计——公理层（锚存在、无冲突、非冗余）、接地层（规范↔公理、门禁↔公理双向 grounding）、目的层（Φ1–Φ8 可由公理导出）三面全绿；③缺口如实登记。
* **非目标**：不改任何规则、工具与门禁（纯审计层，判官只读）；不重述 specs/040 已完成的缺陷台账（其复算结果作为本审计的输入事实）。
* **验收判据**：`bin/axiom_audit.py` 跑通且 `results/axiom-report.json` 全绿（或缺口逐条登记于 findings）；登记册 `results/axioms.md` 每行机检通过。
* **作废条件**：发现公理间不可消解冲突，或 Φ 某子目标无法由公理集导出且无补偿控制。
* **适用规范基线**：GB/T 1.1-2020（助动词）、ISO/IEC/IEEE 12207 §技术过程、15289 §信息项、ISO 17100 §5.5.4（复核独立）——均已在 rules/README"规范性引用标准"节登记版本钉，按 rules/08 §13 引条款号不重读全集。

## 零·层级模型（2026-11-17 用户定位）

**公理是最高层；AGENTS.md 是入口和目录；软件工程理论是哲学和方法论。**

| 层 | 内容 | 效力 | 与本体系的关系 |
| ---- | ---- | ---- | ---- |
| L0 哲学与方法论 | 软件工程理论：ISO/IEC/IEEE 12207（过程架构）、15289（信息项）、1028（评审）、1044（异常）、15939（度量）、ISO 17100 §5.5.4（复核独立）、ISO 15489（记录）、GB/T 1.1-2020（条文起草）、MQM（错误维） | **不具约束力**——提供"为什么这样定公理"的论证 | 公理的正当性基底（见 §二·基底） |
| L1 **公理层（最高）** | 现为 `rules/axioms.json` 的 P1–P28（原 A1–A14 已并入） | **最高**：一切条文、门禁、不变量须可上溯至此（S3）；公理自身不靠下位条文取得效力 | 本体系正文（移入 `rules/axioms.json`） |
| L2 展开层 | 宪法七原则、`rules/01–09`、`rules/adr/` 裁定 | 公理的操作性展开与判定细节；修订走 ADR | 公理的正文锚（S1） |
| L3 工程规格 | `specs/<NNN>-*/`（含本 spec） | 只约束该工程 | 公理的落地证据 |
| L4 **入口与目录** | `AGENTS.md` | **无规则效力**——入口与目录：指向公理表、规则地图、必读表；自述"规则正文一律以 `rules/` 为准""不复制数字" | 公理的索引面（`index:` 行，不计权威锚） |

效力方向单向向下：L1 由 L0 获论证、由 L2 获展开、由 L3 获落地、由 L4 获指路；**反向不成立**——L4 的速览文字不能新增或改写义务（S6 机检其自述）。
