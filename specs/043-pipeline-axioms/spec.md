# 总执行书的公理化验证

**日期**：2026-11-18｜**性质**：形式验证（可执行）｜**对象**：`jian-yi-shu/pipeline-17.json` 与 `jian-yi-shu/journal-schema.json`
**判定器**：`bin/verify_pipeline.py`｜**机读结果**：`results/verify-report.json`

## 方向声明

* **意图复述**：对每一步与全部步骤做公理化计算，验证总执行书的融洽性（一致性、无矛盾）与充分性（覆盖、无遗漏）。
* **目标**：把“融洽”与“充分”从断言变为**可执行判定**——每条性质写成返回布尔的纯函数，对真实数据求值。
* **判据**：①35 条谓词全部通过；②判定器可被证伪（负向样本必失败）；③明确划出无法用本方法证明的部分。
* **反目标**：不以“看起来合理”代替计算；不把语义正确性伪装成结构定理。

## 一、形式系统 𝔖

### 1.1 基本集合

| 符号 | 含义 | 基数 |
|---|---|---|
| `N` | 作业节点 | 16 |
| `M` | 强制最小集 | 6 |
| `G` | 判据 | 19 |
| `R` | 要求登记册 | 18 |
| `P` | 产出节点 | 4 |
| `T` | 时间戳（全序） | — |

`N ∩ M = M`（强制节点是节点的子集，公理 C1）。
`P ⊂ N`，`M ∩ P = ∅`。

### 1.2 函数

* `prev : N → N ∪ {⊥}`，`prev(n)` 唯一（每节点至多一个前驱）。
* `seg : N → {1,2,3}`。
* `type : N → {pipe, stage, review, format}`。
* `hard : N → 2^G`，硬拦判据集；`hard(n) = ∅` 当 `gate_owner(n) = false`。
* `own : G → 2^N`，登记表中的归属。
* `cover : R → 2^N`，要求承接映射。
* `produce : P → 2^N`，产出节点的被检对象。

### 1.3 事件与派生

事件 `x = (e, a, n, k, t)`，`e ∈ E`（条目），`a ∈ A`（分支），`n ∈ N`，`k ∈ {lock, pass, fail, rework, merge, import}`，`t ∈ T`。

`last(e,a,n) = argmax_t { x | x = (e,a,n,k,t) }`——由 `T` 全序保证唯一。

`D(e,a) = { n | last(e,a,n).k = pass }`（已通过集）

`sat(e,a) ⟺ D(e,a) ⊇ N ∪ M`

## 三、定理与证明

### T1 唯一路径

**命题**：存在唯一的节点序列 `σ = (n₀, …, n₁₅)`，`prev(n₀) = ⊥`，`n_{i+1}` 是 `n_i` 的唯一后继，且 `{n_i} = N`。

**证明**：由 A1，`n₀` 唯一。由 A7，每个节点出度 ≤1，故后继唯一，`σ` 唯一确定。由 A3，`prev` 无环，故 `σ` 有限。由 A4，遍历覆盖全部 `N`。∎

**推论 T1.1**：`|σ| = |N| = 16`，且 `σ` 的次序即判据执行的偏序。

### T2 判据归属是部分单射

**命题**：`own = hard⁻¹`，即 `n ∈ own(g) ⟺ g ∈ hard(n)`，且每个 `g` 至多一个硬拦节点。

**证明**：B2 给出 `g ∈ hard(n) ⟹ n ∈ own(g)`；B3 给出反向。故 `own = hard⁻¹`。B1 给出 `|hard⁻¹(g)| ≤ 1`，故部分单射。∎

**推论 T2.1**：一个判据的失败只定位到一个节点，不存在“两处都该管”的歧义。

### T3 强制不可绕过

**命题**：`sat(e,a) ⟹ M ⊆ D(e,a)`。

**证明**：`sat` 定义为 `D ⊇ N ∪ M`。由 C1，`M ⊆ N`。故 `sat ⟹ D ⊇ M`。∎

**注**：此定理是定义的直接推论，不提供额外信息；它的价值在于把“R1–R3 必须过”从口号变成定义的一部分——**任何不满足 `D ⊇ M` 的状态在定义上就不叫饱和**。

### T4 覆盖充分

**命题**：`∀ρ ∈ R: ∃n ∈ N` 使 `ρ` 由 `n` 承接，且 `n` 的承接体非空。

**证明**：D1 给出 `cover(ρ) ⊆ N` 且非空；D5 给出 `cover(ρ)` 中每个节点 `gate_owner ∨ does ≠ ∅`。取 `cover(ρ)` 任一元素即得。∎

**这是“充分性”的核心**：18 个要求无一落空，且每个承接都是可执行的（有判据或有明确动作）。

### T5 必要性三分

**命题**：`∀n ∈ N`，下列三者至少一成立：(a) `n` 独占某个要求；(b) `n ∈ P`（产出被检对象）；(c) `type(n) = format`（结构闭合）。

**证明**：D3 给出 `N = ⋃cover(R) ∪ P`。对 `n ∈ ⋃cover(R) ∖ P`，若 `type(n) ≠ format`，由 D6 得 (a)；若 `type(n) = format`，得 (c)。对 `n ∈ P`，得 (b)。∎

**说明 (c) 为何不算豁免**：`format` 节点的必要性来自 G2（段末闭合）这一**结构公理**，不是来自要求覆盖。它们承接的 R18 由两个节点分担，任何单个都不独占——这是设计（两段各闭合一次），不是遗漏。

### T6 一致性

**命题**：不存在 `e,a,n` 使 `pass` 与 `fail` 同时属于 `D(e,a)`。

**证明**：`D` 定义为 `last(e,a,n).k = pass`。`last` 由 `T` 全序保证唯一。函数值唯一 ⟹ 不可能同时为两种事件类型。∎

**注**：这是构造性结论——**一致性不是靠纪律维持的，是靠“取最后一次事件”这个定义保证的**。同一节点先 `fail` 后 `pass` 是合法的，状态由后者决定。

### T7 可判定

**命题**：`sat(e,a)` 可在 `O(|N|)` 内判定。

**证明**：`sat` 是对有限集 `N ∪ M`（基数 16）的包含判定，需对每个节点查询 `D` 的成员资格。∎

### T8 放宽单调

**命题**：若判据由 `C` 放宽到 `C'`（`C'_n ⊆ C_n`），则 `D_C ⊆ D_{C'}`。

**证明**：`D_C(e) = {n | e 满足 C_n}`。`C'_n ⊆ C_n` 故满足 `C_n` 必满足 `C'_n`。∎

**推论 T8.1**：`widen` 档的状态搬迁量为 0，且既存 `pass` 继续有效——不需要重算，不需要迁移。

### T9 契约传递

**命题**：沿 `σ` 前进，访问 `seg_{i+1}` 的段首之前必经 `seg_i` 的全部节点。

**证明**：由 T1，`σ` 唯一。由 G1，`prev(seg_{i+1} 段首) = seg_i 链尾`。故段首在 `σ` 上的位置 = 链尾位置 + 1，其前驱链完整覆盖 `seg_i`。∎

### T10 判据隔离

**命题**：不同硬拦节点的判据标识互不相同。

**证明**：由 T2，`hard` 与 `own` 互逆且 `own` 是部分单射。故 `n₁ ≠ n₂ ⟹ hard(n₁) ∩ hard(n₂) = ∅`。∎

**这正是“五组重复归零”的形式表达**：重构前 `check_style` 出现在三个节点，`hard` 不是单射，T10 不成立；重构后成立。

## 六、可证与不可证的边界

这是本规格最重要的一节。35 项定理证明的都是**结构性质**，以下四类不在其中：

### 6.1 判据的语义有效性（不可由本方法证）

`check_style` 在形式上被证明“唯一挂在 `S3`”，但它**是否真能查出体例问题**，是工程问题，不是结构定理。形式系统只能保证“每个判据有唯一归属”，不能保证“这个判据是有效的”。

验证手段：`check_style` 自身的单测与误报率统计，属另一层验证。

### 6.2 人工节点的执行质量（不可由本方法证）

`R1` 被定义为“受众适切性”，但会话是否真的按这个维度判断，无法由 JSON 结构推出。形式系统只能保证“这个节点存在且强制”，不能保证“它被认真执行”。

### 6.3 事件日志的并发安全（需运行时验证）

`J4`（日志只追加）在结构上成立，但多会话同时写同一 `journal` 文件是否真的互斥，需要文件锁与并发测试。本规格不含运行时验证。

### 6.4 要求登记册 `R` 的完备性：相对完备，不是系统内不可证

**先纠正一处曾经的错误表述**。本规格初稿把这一条写成“任何公理系统都不能证明自己的要求集完整”，并暗引 Gödel。该表述**不成立**：

* Gödel 第二定理讲的是系统**不能证明自身一致性**，不是不能证明完备性；
* 第一定理的前提是「能表达一定量算术且可递归公理化」，`pipeline-17` 是有限数据结构，不满足该前提；
* SEP 对该类跨领域应用有明确保留，称其 `more controversial`。

**正确结构是相对完备（relative completeness）**，与 Cook 1978 对 Hoare 逻辑的处理同构：

| 类型 | 含义 | 本项目状态 |
|---|---|---|
| 语法完备 | 无占位符、无悬空引用、无需外部补充 | D1–D6 已证（35/35） |
| **相对完备** | 给定外部输入 `R`，系统内无遗漏 | **成立**：18 条要求全部有唯一承接 |
| 经验完备 | `R` 是否穷尽所有应有关切 | **不在形式系统能力范围内** |

三处独立依据（详见 `results/completeness-verification.md`）：

1. **Zave & Jackson（1997）**把「`R` 整体表达客户全部愿望」明确标为 `validated (checked informally)`；其框架里形式的只有 `K,S ⊢ R` 与 `K,S ⊬ ⊥` 两条。
2. **Glinz（2016）**指出面向真实世界（Lehman type E）的需求建模 `by its very nature is not formalizable`，不存在「描述所有可能输入」的终点。
3. **Cook（1978）**的范式：证明系统本身不贡献不完备性，缺失的力量全在断言语言。此处断言语言即 `R`。

**因此**：本体系能保证「给定 `R`，无遗漏、无空挂、无冗余」；不能保证「`R` 完整」。后者的保障只能是非形式的登记纪律——ADR 模板增加一项「本条是否引入新的可验收要求？若是，登记进 `REQUIREMENTS`」。

**这不是盲区，是分工。** 把 `R` 的有效性纳入形式证明范围，等于要求形式系统证明一个它无法触及的经验判断；把它显式划出，才能在 `R` 变化时知道该补哪里。

## 七、结论

**融洽性成立**：35 项结构公理对 `pipeline-17` 全部求值为真；六处真实矛盾已修正；判定器经四个负向样本证明可失败。

**充分性成立，但限于相对完备**：18 条要求各有唯一承接且承接体非空（T4）；每个节点都有必要性来源（T5）。**「`R` 是否穷尽所有应有关切」属经验完备，不在可证范围**，需靠 ADR 流程的登记纪律维持（§6.4）。

一句话：**这套结构能证明自己不矛盾、不遗漏已登记的义务；不能证明自己知道全部义务——而后者是分工划出去的，不是证明不出来的。**
