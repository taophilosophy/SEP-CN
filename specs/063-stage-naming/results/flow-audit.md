## 3 缺口详述

### G1 判据无阶段归属（可机检导出，但须禁手编）

26 个判据全部单 owner（pipeline 明文“每个检查器的硬拦点唯一”），故可由 `criteria_owner` 反查阶段。**但手编必错**——审计实测三处与直觉相反：

| 判据 | 直觉归属 | `criteria_owner` 实值 |
| ---- | ---- | ---- |
| `register_audit` | rv-01 术语 | **rv-06** 语域 |
| `check_pairs` | rv-02 全局 | **tr-03** 一校 |
| `check_academic` | rv-09 体例 | **rv-02** |

处置：stages 增 `criteria` 字段，**只由 `criteria_owner` × σ 派生，禁手编**；check_stages 增第 ⑨ 谓词做双向校验（每条判据恰一阶段；每阶段 criteria 集合与反查结果相等）。

### G2 工具无归属（判定：不单独挂靠）

工具是判据的**实现**，不是流程站。85 个工具中进入 `check_all` GATES 的约 21 个，与判据名一一对应；其余为运维／生产脚本（fetch、compare、wipe、progress…）。

处置：**不入阶段轨**，随判据挂靠；`tools/` 与判据的对应由 `check_all.py` 的 GATES 表承载（既有事实源，不复制）。在 §1.12 声明。

### G3 规则无归属（判定：不入阶段轨）

`rules/01–10` 是规范文本，不是作业：01 结构、02 体例、03 术语、04 流程、05 工具、06 治理、07 学术、08 意图、09 过程、10 条款。

处置：**不入阶段轨**；规则的作用面在规则自身头注（如 02 管 tr-04／rv-09），阶段条目只引规则号不反向登记。在 §1.12 声明。

### G4 阶段跃迁缺失（结构性，最严重）

任务书只回答了“词条在哪一站”，没回答“站与站之间怎么走”。而全流程的日常操作恰恰是跃迁：

| 操作 | 依据 | 阶段效应 |
| ---- | ---- | ---- |
| `advance --step <id>` | 状态机 | 前进一站（stage(state) 单调增） |
| `revert-state --to rv-02_checked` | ADR-0043／0063 | **回退到 3.2**，重走 3.3–3.9 与 r 链 |
| `reopen --clear` | ADR-0050 | 回 1.3.2（置空），再走 1.3.3 起 |
| `reopen --upstream-sync` | ADR-0051 四闸 | 同上，附凭证审计 |
| `advance --unblock` | blocked 标志 | 解除阻塞，不改阶段 |
| `task_ops.py source-audit` | 存量补课 | 追加 ex-04 记录，**状态不迁移**（阶段不变） |
| 语体违规返工 | ADR-0033 | reopen → clear → 1.3.2 起重译 |

处置：新增 §1.11 跃迁表 + 定理 CT8（跃迁相容）。

## 4 新增定理

### CT8 跃迁相容

**陈述**：任何改变 `state(e)` 的操作后，`stage_of(e)` 自动反映新状态，无需额外写入。
**证明**：CT3 证明 `stage_of = μ ∘ state` 是全函数；μ 为静态表（不随操作变化）。故 state 变则 stage 随之变，且由 AX4（函数单值）不产生歧义。推论：`revert-state --to rv-02_checked` 后阶段自动回到 3.2，与“重走 3.3–3.8 与 r 链”的语义一致；`source-audit` 不改 state，故阶段不变——与“状态不迁移”的规范一致。∎
**意义**：阶段轨**不需要**跃迁引擎，跃迁语义由状态机＋μ 免费获得。这正是“阶段是派生视图”的收益首次被形式化。

### CT9 判据阶段可导出

**陈述**：∀c∈C，`stage(c) = stage(owner(c))` 唯一可导。
**证明**：pipeline 声明每个检查器硬拦点唯一 → `criteria_owner[c]` 是单元素集；σ 由 AX2 单值 → 复合函数唯一。∎
**反证其必要性**：审计实测三处手编会错（G1 表），故必须机读派生。

## 6 剩余风险（审计不能消除的）

1. **战役登记完备性**（B4 延续）：库内战役型 spec 多于登记的 6 项；归类需人判，`AX6` 只保证已登记者合法。
2. **`register_audit` 归属可疑**：owner 写作 rv-06（语域），但该检查器语义是“登记册审计”；可能是 pipeline 登记笔误。本卡不改（pipeline 是事实源，改动须另立卡），仅登记观察项。
3. **工具与判据的对应无单表**：`check_all.py` 的 GATES 是运行时清单，判据名与工具名并非总是一一对应（如 `divergence` 对应 `divergence.py`、`review-verity` 无工具）。此项不属本卡。
