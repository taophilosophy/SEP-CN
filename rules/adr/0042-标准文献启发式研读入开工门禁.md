# 0042. 标准文献启发式研读入开工门禁（知难行易的重要体现）

accepted | 2026-11-14

## 背景

用户指令（2026-11-14，两条）：“修订软件工程理论：干活前必须启发式阅读有关ISO ieee 国标 官方文档 规范 建议等标准化文献，必须吃透并落地。”“新增任务：将其作为知难行易的重要体现。”

前例与缺口：specs/025 两轮标准研读（ADR-0041）证明“启发式筛查→条款级研读→落地”可行且必要——研读前 GB/T 7714-2025 已全部代替 2015 版而本库零引用、连接号三形无条款可引。但该实践只存在于当次战役：知难行易理论底稿（doctrine 00b）与约束性规则（rules/08）均未把它立为开工前义务——知层只覆盖用户意图维度，规范基线维度缺位；研读成果不强制落地，报告完成即散。

## 决策

1. **知层扩维**：知难行易的“知”正式扩为两层——用户意图（要什么）与规范基线（依什么）。doctrine 00b 开工四问扩为**开工五问**，新增第 5 问“依哪些标准”。
2. **doctrine 00b 新增 §6 标准文献启发式研读**：三步“筛查→吃透→落地”及各步不合格形态；启发式边界（登记清单=研读缓存，命中即引不重读；新领域、新手段、新规则起草才触发检索义务）；极简任务一句话收口。反模式表增“无基线动手”，方向声明卡增“适用规范基线”字段。
3. **doctrine 01-process 门禁钩子**：G0 输入/活动/退出判据、G1 活动增标准筛查与条款引用要求；§7 过程自检增第 8 问。
4. **约束性条文入 rules/08**：§1 方向声明表新增“适用规范基线”行；新增 §13（三步的约束性要求、启发式边界、判例）；§7 判例表增行。
5. **登记清单=筛查缓存**：rules/README“规范性引用标准”节为筛查入口（命中即引条款号，不重读全集）；清单修订仍按 ADR-0041 代替关系核对纪律。
6. **AGENTS.md 开工第 0 步**加指针。
7. **落地形态与 00b 先例的关系**：本条沿用 ADR-0039 模式——理论入 reference 底稿，约束性条文入 rules/08；冲突时以 rules/08 为准。

## 后果

* **正面**：每次开工的方向声明含规范基线字段；新领域有检索义务；研读成果强制落地（条文/清单/机检/验收判据其一），偏离强制登记在案；标准代替关系漂移有版本钉防线。
* **负面/成本**：方向声明多一字段（极简任务一句话豁免口径已给）；未登记域检索依赖外网（守 rules/05 礼貌抓取）；启发式筛查靠会话判断、无机检——漏判风险由 01-process §7 自检第 8 问与复审兜底。
* **复审**：随 doctrine 00b 复审日期（2027-01-21）一并复审。
