# 0032. 工具链基线更新与图片引用入闸

accepted | 2026-11-10

> 补记说明（2026-11-10）：本 ADR 在提交 886351ed6 中只登记了索引行，正文文件漏提交；曾按该提交说明与 `rules/05-ci-and-tools.md` 的运行时基线节重构补记。同日原始正文在本机以未跟踪草稿找回，经核对与补记决策内容一致，现将本文件恢复为原始全文（补全“验证”“备选方案与被否理由”“影响面与回滚”三节，并补决策第 5 条），补记版的“后果”一节保留。

## 背景

本机运行环境升到 **Python 3.15.2**（`C:\Program Files\Python315`）与 **Node 26.13.0**（npm 12.2.2、bun 1.4.4）。复核发现两类问题：

1. **版本基线没有落盘**：`rules/05` 只写“Python 3 仅标准库”，CI 用 `python-version: '3.x'`（浮动）、`check-images.yml` 钉 3.10、`create-pdf.yml` 钉 3.13；`package.json` 无 `engines`，站点依赖 Vite 8（`engines.node: ^20.19 || >=22.12`）对 Node 版本有硬要求而无登记。环境升级后无人能判定“本地绿 = CI 绿”。
2. **图片引用无门禁**：`check_images.py` 早已存在，但只由 path-filter 的 `check-images.yml` 开 issue，不进 `check_all`、不设红灯。实测因此漏检 4 条悬空引用（`i/imprecise-probabilities.md` 两条、`e/ecological-genetics.md` 两条），**直接打断 `bun run build`**（`UNRESOLVED_IMPORT`，exit 1）。这是“报告型检查 ≠ 门禁”的典型缺口。

## 决策

1. **运行时基线钉死**：Python ≥ 3.15（本地 3.15.2）、Node ≥ 26（本地 26.13.0）、bun ≥ 1.4（本地 1.4.4）。
   * `package.json` 增 `engines`（node/bun）与 `packageManager: bun@1.4.4`；
   * `checks.yml`、`check-images.yml` 的 `python-version` 由 `'3.x'`／`'3.10'` 改为 `'3.15'`（工具全为标准库，无依赖面风险）；
   * `rules/05` 增“运行时基线”小节，`.vitepress/README.md` 增 Node 要求与构建内存说明。
2. **图片引用入闸**：`check_images.py` 增 `--gate`（悬空／大小写／外链任一 >0 退出 1；未引用资产仍只告警），纳入 `check_all.py`（八项门禁 + 单测共 9 项），并在 `checks.yml` 增加显式 step。默认（报告型）行为与退出码不变，`check-images.yml` 开 issue 的职能保留。
3. **PDF 导出线暂留 Python 3.13**：`create-pdf.yml` 依赖 weasyprint/mistune/ebooklib 等第三方包，未在 3.15 上验证；待上游支持后单独跟进，不在本 ADR 内冒险升级。
4. **补回缺失资产**：`assets/imprecise-probabilities/{two-by-two,joyces-diagram}.png`、`assets/ecological-genetics/figure{1,2}.svg` 从 `en/` 原件按字节复制（SHA-256 与原件一致），悬空引用清零。
5. **同步文档计数**：更新 `AGENTS.md`、`rules/05-ci-and-tools.md` 与 ADR 索引中的门禁计数与说明。

## 备选方案与被否理由

* **CI 继续用 `3.x` 浮动**：不可复现——本地升到 3.15 后无法判断 CI 是否同基；浮动版本还会让“CI 绿”随时间变化，违背版本钉精神。
* **图片检查保持 issue-only**：已被实测否决——报告没人看时构建照样断，属于“知难行易”中的手段错位（检查存在 ≠ 门禁生效）。
* **建全量构建内存优化（迁移 rolldown code-splitting）**：方向正确但不属本次范围；先写明内存前提，构建性能另案立项。
* **`create-pdf.yml` 一并升 3.15**：weasyprint 依赖面未验证，失败成本高于收益（PDF 为手动工作流，非 push 门禁）。

## 后果

* 正面：本地与 CI 基线一致，站点构建可复现；图片硬问题在合并前拦截，不再依赖事后 issue。
* 负面：PDF 导出线版本落后于主基线，需单独维护；旧环境需升级后才能跑全量门禁。

## 影响面与回滚

* 影响：`tools/check_images.py` 新增可选 `--gate`；`tools/check_all.py` 多一项门禁；`checks.yml` 多一个 step、Python 版本钉改 3.15；`package.json` 增 `engines`/`packageManager`；`assets/` 增 4 个文件；文档同步（`AGENTS.md` 计数 8→9、`rules/05`、`.vitepress/README.md`）。
* 回滚：`git revert` 本 ADR 对应提交即可；`--gate` 为增量开关，不影响既有调用（`check-images.yml` 的 wrapper 未传该参数）。
