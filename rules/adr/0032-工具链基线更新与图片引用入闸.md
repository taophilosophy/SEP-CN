# 0032. 工具链基线更新与图片引用入闸

accepted | 2026-11-10

> 补记说明（2026-11-10）：本 ADR 在提交 886351ed6 中只登记了索引行，正文文件漏提交；现按该提交说明与 `rules/05-ci-and-tools.md` 的运行时基线节补记，决策内容未改动。

## 背景

运行时基线多年未随工具链升级：CI 与本地 Python、Node、bun 版本不一致，站点构建与门禁在不同环境结果漂移；图片引用检查 `check_images.py` 只在 `check-images.yml` 中报告并开 issue，悬空引用、大小写错误与外链不会让 `checks.yml` 变红，图片问题无法在合并前拦住。

## 决策

1. 运行时基线（2026-11-10 起）：
   * Python ≥ 3.15（本地验证 3.15.2；`tools/` 仅标准库，`check_all` 与单元测试全绿），CI 同步钉 3.15；
   * Node ≥ 26（本地验证 26.13.0；满足 Vite 8 的 `^20.19 || >=22.12`；站点命令仍走 bun，见 ADR-0014）；
   * bun ≥ 1.4（`package.json` 的 `engines`/`packageManager` 钉住）；
   * PDF 导出线（`create-pdf.yml`）暂留 Python 3.13：weasyprint 依赖面未随 3.15 验证，待上游支持后跟进。
2. 图片引用检查 `check_images.py --gate` 入闸：悬空引用、大小写不符、外部地址为硬错误（退出码 1），`assets/` 未引用资产仅告警；同时接入 `tools/check_all.py` 与 `.github/workflows/checks.yml`。
3. 同步更新 `AGENTS.md`、`rules/05-ci-and-tools.md` 与 ADR 索引中的门禁计数与说明。

## 后果

* 正面：本地与 CI 基线一致，站点构建可复现；图片硬问题在合并前拦截，不再依赖事后 issue。
* 负面：PDF 导出线版本落后于主基线，需单独维护；旧环境需升级后才能跑全量门禁。
