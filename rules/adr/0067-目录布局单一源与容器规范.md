# 0067. 目录布局单一源与容器规范：layout.json、四谓词门禁、specs schema 与命名域冻结

accepted | 2026-11-17（权威＝用户指令"批准 P0-P2。加强复核"；依据＝`jian-yi-shu/mu-lu-fen-lei-gui-fan-jian-yi-shu.md`）

## 背景

目录审计（2026-11-17，`script/dir_audit.py`）实测：根目录 65 项全部在白名单内（存在性缺口 0），但 `rules/01` 目录职责表未覆盖 18 项，42 个目录无自述（扣除字母目录后实质 15），9 个目录无命名规则；`specs/` 41 个目录长有 8 种子目录名、0 份索引、`spec.md` 缺 2 份。诊断归为三机制：双轨清单无派生（存在性归属 `ROOT_ALLOW`、职责归属规则正文）、四轴混切产生多解（用途／入库状态／生命周期／所属工程）、二级容器无 schema。

用户批准 P0–P2（单一源、容器契约、命名域冻结），要求加强复核。本 ADR 记录实施中的两次改判与最终形态。

## 决策

1. **`rules/layout.json` 为根级布局唯一事实源**（`version 1`，69 条声明：42 条 entries ＋ 27 个字母/数字目录通配）。每条含七问字段：`domain`／`role`／`naming`／`lifecycle`／`retention`／`writer`／`gate`／`index`／`tracked`／`desc`。`tools/check_junk.py` 改为 `root_allow()` 从该文件生成白名单，**删除硬编码字典副本**；源缺失即退出码 3（A12 禁静默兜底）。
2. **新增 `tools/check_layout.py` 四谓词并接入 `GATES`**：L1 根目录实际集合 ⊆ 声明；L2 `rules/01` 职责表 ≡ 声明（双向）；L3 已入库容器有 index 或写明理由的 `index_exempt`；L4 `specs/<NNN>-<slug>/` 必需 `spec.md`、禁 `tmp/` 与 `__pycache__/`、规格根不得放 JSON、`execution-log` 两形态不并存。全部只读（A11 判官只读）。门禁数 12→13，CI 矩阵经 `--list-gates` 自动跟随（ADR-0061）。
3. **`rules/01` 职责表补录 22 项并修正入库状态**：补 `.git`、四个点文件、四个本地态目录、`AGENTS.md` 等七份顶层文档、`assets/`、`public/`、`rules/` 自身、包管理三项；`en/`、`yuanwen/` 的"是否入库"由"否（gitignore）"改为"是（ADR-0027 起入库）"——与宪法 II v1.3.0 对齐（前此条文滞后，见 2026-11-17 体系解读发现 #2）。
4. **specs 容器 schema 由白名单改为"必需 ＋ 黑名单 ＋ 目录命名"**（**执行期改判一**）。原议"仅允许 spec/plan/tasks/checklist/contracts/bin/results/execution-log"实测误判 **67 项**：spec-kit 的 `data-model`／`research`／`quickstart`、`rules/04` 明文要求的 `demo-log`、波次与子代理协议文档均属规格的合法组成。改为：必需 `spec.md`；黑名单 `tmp`／`__pycache__`／`node_modules`／`.ipynb_checkpoints`；目录名 `^\d{3}-`；已知子目录 7 种（`bin`、`results`、`contracts`、`checklists`、`execution-log`、`compare`、`dir-rebuild`），未知子目录**只告警**。
5. **迁移面改判为登记例外**（**执行期改判二**）。原议将 `specs/001` 的 9 个凭证 JSON 迁 `results/`。复核发现实际散落 **11 个**（001 九件＋005 两件），且 `en-integrity-full.json` 等被 `en_integrity.py`、`summary_sync.py`、`migrate_exec.py` 硬编码，被 `rules/05`、`rules/06`、`contracts/cli.md`、`RELEASE-NOTES.md`、`specs/007`、`specs/014` 引用，部分路径已写入历史执行记录（A4 只追加）。处置：`specs/001` 整目录 `allow_root_json`；`specs/005` 仅 `ledger.json` 单文件例外（`campaign.py` 的 `LEDGER` 常量＋`rules/06` 与 `specs/014` 引用）；`h-wave-monitor.json` 零引用，迁 `results/`。**新增规格一律用 `results/`**。
6. **索引由生成器产出，豁免须写理由**。新增 `tools/spec_index.py` 生成 `specs/README.md`（40 行，含编号／标题／状态／bin／results／执行记录形态；`--check` 供复算）。L3 的 `index_exempt` 只接受非空理由字符串：`.github`（工作流清单在 `rules/05` 单一源）、`baseline`（三账语义在 ADR-0045/0062）、`qian-yan`／`guan-yu`（入口由 SUMMARY 承载）、`public`／`assets`／`en`／`yuanwen`／`tools`（纯资产、冻结区或工具表已在 rules/05）。**不为过闸造空 README**。
7. **拼音命名域冻结**：`qian-yan`／`guan-yu`／`jian-yi-shu`／`fang-fa-lun` 在 layout 标 `frozen: true`，`rules/01` 命名节增一句"只减不增，新增一律英文 slug"。新增拼音目录＝未登记 → L1 红灯。
8. **计数口径改为引用清单**：`rules/05`、`rules/06`、`AGENTS.md` 不再写"十一项门禁／共 12 项"，改为"门禁清单以 `python tools/check_all.py --list-gates` 为准"。理由：本轮之前该计数已连续两次滞后（新增 fidelity、style 后仍写 11 项），与 ADR-0015"生成物不承载规则／不复制数字"同源。

## 后果

* **正面**：根级布局由两套清单收敛为一套，`check_junk` 与 `rules/01` 由 L2 强制同源；`specs/` 首次有索引与可判定容器契约；三个未定义容器（`specs/script/tmp`、`029` 缺 spec、`005` 根 JSON）清零或登记。新增 3 个工具（`check_layout`、`spec_index`、审计草稿 `dir_audit`）、1 个规格头（`029/spec.md`）、1 个索引（`specs/README.md`）、1 个 ADR。
* **负面／跟进**：`layout.json` 与 `rules/01` 表仍是"一源一视图"，靠 L2 绑定而非生成——若 L2 被移除则退回双轨；`specs/001` 的 11 个根 JSON 属历史债，待其工具引用面收缩后再迁；`layout.json` 新增条目须同步 `ROOT_ALLOW` 语义说明（已由 L1 实拦）。
* **回退**：`git revert` 本提交即整体撤销（layout.json、check_layout、GATES 一行、rules/01 补录、索引与迁移一并回滚）；单独撤销门禁＝删 `GATES` 的 `layout` 行，CI 矩阵自动跟随。
* **取代链**：补充 ADR-0023（根目录白名单）的实施方式，不改其裁定；未取代任何既有 ADR。

## 复核凭证（加强复核四轮）

1. **守恒**：迁移前后 `git diff --stat` 逐件核对；`specs/005/h-wave-monitor.json` 用 `git mv` 保历史；删除件 `register_metrics.json` 内容为 `[]` 且零引用（`grep` 全库仅命中根 `script/tmp/` 同名文件）。
2. **引用闭合**：`h-wave-monitor` 迁移后全库零引用悬挂；`ledger.json` 保持原位，`campaign.py` 常量未变。
3. **门禁**：`check_layout` L1–L4 全绿（声明 69 条）；`check_junk` 0 命中；`check_summary` 硬错误 0；`check_doc_size` 达标。
4. **负向**：伪造根级未登记目录 `_negtest_undeclared` → `check_junk` 退出码 1，删除后回 0；`check_layout` 在补表前实测 L2=22、L3=6、L4=4，补录后全归零。
