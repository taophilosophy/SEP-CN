# 0018. 知难行易全局规则（宪法 VII、rules/08 与理论底稿）

状态：accepted | 日期：2026-10-29

## 背景

用户 2026-10-29 指令：新增软件工程理论并落实为全局规则；从一刻哲学中提取“知难行易”——必须先明白自己的任务方向、目标，手段是次要的；必须清楚明白地理解用户到底要干什么。

现状缺口：

* doctrine 中“方向先于手段”的依据散落在 `00-philosophy.md` §3 六问、§8 推论与 `00a-yike-source.md` 总纲第十七、二十一、补充总纲 31，无独立文档，无法被直接引用与验收；
* `rules/01`–`07` 均无“开工前确认方向、目标与验收判据”的条款；`AGENTS.md` 开工五分钟直接进入 git 状态与门禁；
* 常见失败模式：先动手后理解、手段替代目标、猜测式实现、以工具或流程表演完成。

## 决策

1. 新增参考理论 `rules/reference/engineering-doctrine/00b-zhinan-xingyi.md`：明确“知难行易”为项目侧提炼（非源文原文），给出知与行的分层、四条命题、开工四问、六类反模式、方向声明卡与失效条件。
2. **修订宪法 v1.2.0**：追加 VII 条“知难行易（先明方向，后择手段）”；I–VI 编号与内容不动，避免破坏既有引用。
3. 新增约束性规则 `rules/08-intent-first.md`：方向声明、先问不猜、手段后置可替换、以验收判据验收、可逆分级、知与行闭环、判例；并同步 `rules/01`–`07` 各任务入口条款。
4. 同步登记：`rules/README.md`（索引、规则地图 `rules/01-08`、快速判例）、`rules/adr/README.md`、`AGENTS.md`（开工第 0 步、硬约束、必读表）、`README.md` 与 `CONTRIBUTING.md`（七项核心原则）、doctrine 的 `README.md` 与 `NOTICE.md`、`tasks/README.md`（任务方向声明）、`specs/005-translation-campaign/session-handoff.md`（开工前方向声明）、`specs/004-engineering-doctrine/spec.md`（复审登记行）。
5. 不引入新检查器：本条是流程判据，依赖既有门禁与会话执行；若后续需要机检，另开 ADR。

## 后果

* 正面：全部任务类型在开工前多一次低成本的意图复述与判据确认；手段表演有可驳回的判据；返工与误改他人工作的概率下降。
* 代价：每个任务增加一句话的方向声明成本；复杂任务需维护方向声明与假设标记。承担者：全部会话与贡献者。
* 失效条件：若本条未能改变任何决策、产物或门禁，按 doctrine §9 删除或降级；与可复现测量冲突时，以测量为准。
* 复审：2027-01-21（与 `specs/004-engineering-doctrine` 同期）。
* 跨界修改：`specs/004-engineering-doctrine/spec.md` 仅追加复审登记行，属 doctrine 落地登记的例行维护，理由即本 ADR。
