# 0050. 上游更新引发的置空返工（reopen 前置 clear、仅留 H1、全量重译）

accepted | 2026-11-15（用户裁定“reopen 的除了 H1 全部置空”并批准即刻执行）

## 背景

2026-11-15 全量回源核对（ADR-0045 跟进）发现 72 条真上游漂移；其中 9 件已译（5 件 done、4 件 s2.5_checked）需返工。派工单曾按 qa-rework 先例建议 done 件走“变更段作业”（保持 done、只改变更段落），用户裁定改为：**reopen 的除 H1 全部置空、按新源全量重译**。

实证依据（specs/001 results/actual-compare-20261115）：

* 72 条真漂移共 2828 个原始行级 hunk，其中 **847 个属性/链接级**（如 http→https 死链修整）——文本规范化补丁流程系统性不可见，变更段作业会把陈旧链接/属性原样带进“已更新”译文；
* 变更幅度谱系极宽（10→39 件节级变更、2 件整体换血重发），“diff 多大才算 update”的逐件判断不可持续；
* 制度记忆已外化（术语在登记册、勘误在分歧账与 en-errata、过程证据在 tasks/ JSON），置空文档不销毁知识；
* 重译将运行在当前更强的门禁与体例标准下。

## 决策

1. **reopen 语义统一**：因上游实质更新引发的 reopen，前置 `clear`（正文置空仅留 H1，基线 gate 照常），按 retranslate 语义全量重译——与 ADR-0033 语体置空返工同构；`task_ops reopen --clear` 原子两步（reopen→clear，append-only 历史完整）。
2. **变更文件降级为审读辅助**：`compare/<slug>.json` 用于重译时了解上游改了什么，不再是逐段补丁指令；update 任务的 `changes:` 证据要求保留。
3. **边界一（s2.5_checked）**：状态机 reopen 仅限 done（ADR-0043 禁跳步），在途件不适用本规则；其上游变更经派工单 A2 以 `changes:` 证据挂现有流水吸收，r 链终审对着已同步的新 en/ 校验。本规则自下批上游更新起全面适用。

> **2026-11-15 ADR-0051 修订**：在途件遇上游实质修订可经 `reopen --upstream-sync` 绕过「仅 done」限制打回置空重译（R3，四闸约束）；本条「挂流水吸收」路径作废。
4. **边界二（H1）**：置空保留 H1；换血重发件（上游同 slug 新写，如 closure-epistemic/saadya 2026-11-15 案）的 H1 作者行经 SUMMARY↔H1 同步硬门禁随新译落成更新，不单独改 H1。
5. **适用范围**：上游更新引发的返工一律本规则；语体不合规返工继续按 ADR-0033（同一两步流程）。

## 后果

**正面**

* 零信任闭环：reopened 词条的每一句都从新源重推，杜绝旧译错误沿袭与补丁流程的链接/属性漏损。
* 消除“diff 多大才算 update”的逐件判断；reopen→clear 原子两步无遗忘窗口。
* 与 FR-013 全量重译原则、ADR-0033 置空返工先例完全同构，规则体系收敛为单一模式。

**负面 / 需跟进**

* 已验证成品作废重写（如本轮 5 件 done 的三审定稿），纯时间成本；由任务 evidence 与登记册兜住制度记忆。
* done 词条置空后退出 done 计数，进度数字回落属诚实记账。
* 本轮 4 件 s2.5_checked 仍走挂流水路径（状态机所限），双层路径并存至其落成。
