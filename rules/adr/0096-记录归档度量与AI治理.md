# 0096. 记录、归档、度量与 AI 治理

状态：accepted　日期：2026-11-28（064 T174；CP-S14-26–31）

## 背景

`journal/` 与 `tasks/` 已有过程记录，T171–T173 已有角色、TBX、评分卡，但缺统一归档 manifest、留存与销毁规则、度量基线表、AI 风险／影响／变更回归登记、发布后流程；归档与发布后责任仍散在规则文字中。

## 决策

1. **归档 manifest**：`rules/archive-schema.json` 定 spec／source／tbx／model／review／scorecard／editing／release 八类；每件须有 path、sha256、date、owner、status；缺项即红。项目级示例 `results/t174-archive-template.json`；实际件示例 `results/t174-archive-habermas.json`（暂缺 scorecard／editing，验证红灯）。
2. **留存与数据保护**：`rules/retention.json` 逐类定 retention／destruction／access／owner；永久留存，销毁只走 ADR；对齐 ISO 15489-1／GB/T 26162。
3. **度量基线**：`rules/metrics-baseline.json` 定八项指标；`pending_pilot` 时 baseline／threshold 均为 null；未测基线不得设阈值，禁止预设 KPI。
4. **AI 治理**：`rules/ai-governance.json` 定风险登记、影响评估、模型变更回归、供应商与数据条款、事件处理；对齐 ISO/IEC 42001／23894；不设公开 AI 披露。
5. **发布后**：`rules/post-publication.json` 定勘误、反馈、上游更新、抽审、版本记录五项；每项有 owner／trigger／evidence。
6. **校验**：`python tools/check_governance.py`；正反例入 `tools/tests/test_governance.py`。

## 后果

* 正面：归档、留存、度量、AI 治理与发布后从散落文字变为可校验登记；缺 scorecard／editing 的件会被明确判红。
* 代价：项目级示例的 scorecard／editing 暂以项目级评分卡与编校清单代表；实际件需在 P5 后替换为件级产物；度量与 AI 影响评估待 pilot 填基线。
* 回退：`git revert` 本批；五个 JSON 与校验器为新增，不改变既有 task_ops 与 check_all 门禁。
