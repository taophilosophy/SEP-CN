# 0080. 节点标识三层与状态名统一

状态：accepted　日期：2026-11-25（用户批准 B1＋B2，要求先复核计算）

## 背景

`rules/pipeline.json` 的 22 个节点此前用一套混合字符串作标识：`P1–P4`、`F1–F2`、`s0`、`s1`、`s2`、`s2.4`、`global`、`q1–q6`、`S3`、`R1–R3`。它同时承担三个角色：节点标识（写进 journal 与 `tasks.steps`）、可读名称、状态名前缀（`s2.4_termchecked`、`s2.5_checked`、`r1_reviewed`）。由此产生的缺陷：

* 一实体多名且不互推：节点 `global` ↔ 状态 `s2.5_checked`；节点 `S3` ↔ 状态 `s3_checked`。
* 大小写混用（`s2` 与 `S3`）、编号断裂（`s0/s1/s2/s2.4/s3` 的小数插入）、裸单词作 id（`draft`、`global`）。
* 同前缀两种语义：`P1–P3` 是转换管线，`P4` 是译前预处理；而 `rules/axioms.json` 的 `P1–P33` 又是公理号，`rules/09` 的 `R1–R4` 是角色号。
* 改名即改标识：journal 只追加（P5）、`tasks.steps` 是过程凭证，改标识就意味着改写历史或永久锁死语义名。

标准依据：ISO/IEC 11179-5:2015（GB/T 18391.5-2009 等同采用）要求**标识与名称分离**，标识唯一、稳定、不复用；ISO 15489-1:2016 要求记录不可篡改；ISO/IEC/IEEE 12207:2017 要求配置项有唯一稳定标识。

**复核计算（本决策的前置）**：评估案曾主张“状态可由 journal 100% 重放”。`tools/replay_state.py` 对 1200 条任务实测：严格重放吻合 803／1200，差异全部可归因——

| 类别 | 条数 | 原因 |
| ---- | ---- | ---- |
| state-behind-journal | 376 | 强制集回补 pass 不迁移状态（ADR-0075） |
| terminal-vs-node | 16 | `cleared` 不是事件（clear 只写 steps） |
| state-ahead-of-journal | 3 | 缺 pass 事件的历史推进 |
| no-journal-evidence | 2 | 无 journal 文件 |
| match | 803 | 视图与日志一致 |

结论：**状态不可由 journal 严格重放**，因此迁移验收不能建立在重放上；但“状态可由映射改写”成立，历史记录不必触碰。原评估案的验收条款据此修正（见决策 4）。

## 决策

1. **三层分离**：identifier（`ex-01`…`sg-03`，永不变、永不复用；预留 `ex-06…09`、`tr-06…09`、`rv-10…19`、`sg-04…09`）／name（`extract.fetch` 式，可演进，带 `name_version`）／state（`<identifier>_checked`）。中文名作 label。
2. **单一事实源**：`rules/naming.json` 管命名（identifier／name／name_version／label／state／aliases）；`rules/pipeline.json` 只管判据、次序、`object_class`。`label` 已从 pipeline 移除，S7 禁止命名属性回写管线；`object_class` 不复制进登记表（与评估案表列的一处偏离，理由即单一事实源）。
3. **管线 id 改用 identifier**，`prev`、`criteria_owner`、`mandatory_minimum` 同步迁移；号段与 seg 绑定（ex＝seg1，tr＝seg2，rv/sg＝seg3）。
4. **历史不改写**：journal 的 4276 个 node 事件与 `tasks.steps` 原样保留，经 aliases 归一读取；旧命令行短名（`s0`／`s24`／`s25`／`audit`／`s3`／`r1–r3`）继续可用。`tasks.state` 按 `state_aliases` 迁移（435 条改写，765 条为 pending／cleared 无需改写），验收采用两档：**映射双档**（逐条 new == aliases[old]，实测 0 不符）＋**重放分类不变**（迁移前后分类逐条一致，实测 0 漂移）。重放器只作体检，不作门禁，理由见背景。
5. **状态名统一**为 `<identifier>_checked`：旧四种后缀（`drafted`／`_checked`／`_termchecked`／`_reviewed`）废止；`pending`／`cleared`／`done` 为非节点状态保留。
6. **S7 谓词**（`tools/check_stages.py`）：登记表自洽、与管线一一对应、号段与段一致、命名属性不在管线重复、历史节点名可归一、任务状态名在词表内。登记表缺项或历史名解析失败即红。
7. **角色号去代号**（`rules/09`）：原 `R1–R4` 角色改写为“译者／校者／评审线／管线会话”，避免与节点别名 `R1–R3` 冲突。

## 后果

* 正面：改名只动 name／label，标识与状态不动；历史可解析、可审计；S7 使“悄悄新增节点”“悄悄恢复旧名”两类漂移可机检。
* 代价：多一层别名与登记表；规则正文已按 identifier 重写（ADR 正文保留各自年代的名字，不追溯改写）；`specs/060` 的轴标签 `q1–q6` 与清单文件名沿用（轴标签，不等于节点 id，见该 spec 头注）。
* 约束：新节点必须先登记 identifier 与 name 再进 pipeline；退役号不回收；`name` 变更须升 `name_version` 并把旧名留在 aliases。
* 回退：命名与状态迁移集中在同批提交，`git revert` 可整体回退；`tasks.state` 可再由 `state_aliases` 逆向映射，journal 未动。

## 补记（2026-11-25）

本 ADR 背景所引 `ISO/IEC/IEEE 12207:2017` 已于 2026-04-29 废止，现行版本为 `ISO/IEC/IEEE 12207:2026`（2026-04 发布）；登记与 V5 校验见 ADR-0083。其余结论不变。
