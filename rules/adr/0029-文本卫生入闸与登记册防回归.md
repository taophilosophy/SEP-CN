# 0029. 文本卫生入闸与登记册防回归（七项门禁）

accepted | 2026-11-10

## 背景

2026-11-10 补遗轮集中暴露四类“无拦截即积累”的事故，均发生在门禁视野之外：

1. **直角引号**：`rules/02-style.md` 第 11 条早已明令禁用 U+300C/D/E/F，`tools/check_style.py` 亦实现了 curly-quotes 规则，但该具只对单篇词条跑（`--docs`），登记册、词汇表、规则与叙事文档从不经过它。结果三个受跟踪文件积出 664 处直角引号，`check_all` 仍全绿。
2. **译法列混入词条 slug**：2026-11-09 并行合并脚本列位错，把来源 slug 写进第 3 列共 143 行；slug 被当作译法变体参与比对，制造 3 项“词汇表滞后”伪欠账（`lvov-warsaw`／`cancer`／`logical-consequence`）。
3. **合并冲突标记入库**：`git stash pop` 冲突未清即提交，`ren-ming-biao.md` 一度同时含 `<<<<<<< Updated upstream` 标记与重复行（Pāṇini 两行），并触发 `check_terms` 自洽硬错误。
4. **生成物行尾翻转**：`check_terms.write_person_missing` 写盘缺 `newline='\n'`，Windows 下每次重生成把 `person-missing.txt` 翻成 CRLF，造成 5700 行伪差异，掩盖真实变更。

共性：**规则已立、检查已写，但未接入必跑链路**。规则不落闸即等同无规则。

## 决策

1. **新增 `tools/check_quotes.py`（文本卫生总检）**：全库扫描 `git ls-files '*.md'`，查两类问题——直角引号（U+300C/D/E/F）与行首合并冲突标记（`<<<<<<< `、`>>>>>>> `、`||||||| `；`=======` 是 setext 标题下划线，不查）。豁免：`j/japanese-aesthetics.md`（日文书名“切れ”の構造，日文正字法，ADR-0011 引文原文语言还原）；不扫 `en/`、`yuanwen/`（源语言文本）、`specs/`（历史执行记录）、`.zcode/`、`node_modules/`。
2. **入闸**：`check_all.py` 增第七项“直角引号总检”，`.github/workflows/checks.yml` 增同名独立步骤（落在术语门禁之后，便于定位）。计数口径自此为**七项门禁 + 单元测试 = 8 项**，`--all` 为 10 项。
3. **`check_terms.py` 增硬错误**：译法列尾段呈现“；+ 小写拉丁连字符词”即报“译法列混入词条 slug”（`SLUG_TAIL_RE`）。中文译法不会以拉丁词收尾，故不设白名单；夹具 `tools/tests/fixtures/check_terms/registry_slug.md` 固定该行为。
4. **生成物写盘统一 LF**：`write_person_missing` 补 `newline='\n'`，与 `write_orig_missing` 一致，消除双端行尾互翻。
5. **ADR-0015 的“六项门禁 + 单元测试（--all 共九项）”作历史表述保留**，不作为现行口径；现行口径以本条与 `AGENTS.md`、`rules/05`、`rules/06` 为准。

## 备选方案与被否理由

| 方案 | 否决理由 |
| --- | --- |
| 只加告警不加硬错误 | 143 行 slug 污染与重复行事故皆因“无拦截”而积累；告警在 `--quiet` 下不可见 |
| 把登记册与规则文档也塞进 `check_style.py --docs` | 该具面向单篇词条，bold-spacing／cjk-spacing 等规则在登记册表格上误报量大，且需逐篇传参 |
| 在 `check_style.py` 内扩充检测 | 其调用面是词条正文；全库扫描属另一职责，混入会让单篇检查变慢并模糊失败归因 |

## 影响

* 含直角引号或冲突标记的提交，CI 直接转红并给出 `文件:行`；历史 `specs/` 记录不受影响。
* 译法列若再被脚本写入 slug，`check_terms` 判硬错误，词汇表滞后不再出现伪欠账。
* 单元测试由 197 项增至 204 项（新增引号／冲突标记 6 项、slug 混入 1 项，另并入既有夹具）。

## 验收

`python tools/check_all.py` 8 项全绿；`python -m unittest discover -s tools/tests` 204 项 OK；`python tools/check_quotes.py` 全库 0 处（豁免 2 字符）。
