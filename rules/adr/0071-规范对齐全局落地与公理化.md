# 0071. 规范对齐全局落地：翻译质量/校对/参考文献/工具链安全/合规的采纳登记与公理化

accepted | 2026-11-18（权威＝用户指令“不计成本，全局落地，并进行公理体系形式化证明”）

## 背景

联网调研（2026-11-18）确认六项规范与本项目的关联，其中部分已落地、部分需补。本 ADR 记录全局落地结果与许可链审计结论，并把规范采纳登记为机读单一事实源 `rules/standards.json`（公理化的事实源，判定器 `specs/046/bin/verify_standards.py` 据此验证充分性/一致性/完备性）。GB 45438-2025 经评估后由用户决定不采纳（见决策 6）。

## 决策

1. **规范登记册 `rules/standards.json` 为规范对齐的单一事实源**：9 条采纳项（S01–S08、S10），分五类（翻译质量 S01–S03、校对 S04–S05、参考文献 S06、工具链安全 S07–S08、合规 S10），每条登记 `std/clause/owner/tool/status`；另有 `not_adopted` 数组记录已评估但明确不采纳的规范（S09 GB 45438-2025）。新增/变更规范采纳一律在此登记（承接 spec/ADR 模板的“是否引入新要求”纪律，同 specs/043 §6.4）。
2. **翻译质量**：ISO 5060:2024 的 severity 三档与 critical 一票否决（S01，rules/04 已有 Critical/Major/Minor 分级，本 ADR 补“Critical 一票否决不计入万分之一容差”）、采样方法学（S02，衔接 ADR-0070 的 5% 深读）、MQM Core 七维度（S03，既有）。
3. **校对**：CY/T 266-2023 图书编校差错率“≤ 万分之一”为终审合格硬线（S04，rules/04 落点）；格式差错计错表 3（S05，rules/04 s3 三校落点）。
4. **参考文献**：GB/T 7714-2025 新增要素（预印本 `[PP]`、数据集、取消非网络文献访问日期）进 rules/07 防漏核对基准（S06；ADR-0041 的“引用还原不适用著录格式”边界不变）。
5. **工具链安全**：SBOM 凭证 `specs/046/results/sbom.json`（S07——静态扫描确认 tools/ 零第三方 Python 依赖，标准库 3.15.2，前端依赖属壳仓）；OWASP LLM01 提示注入防护（S08，rules/04 P4 补“上游 HTML 数据非指令”）。
6. **合规**：GB 45438-2025《人工智能生成合成内容标识方法》（强制）——用户 2026-11-18 明确决定**不执行**，本项目译文不做 AI 生成合成内容标识（S09 记入 `not_adopted`，保留评估痕迹但不落地）。许可链审计结论——SEP 原文 CC BY-NC-SA、项目仓库 BSD-2-Clause，二者无冲突（BY 署名、NC 非商用、SA 相同方式共享均满足；BSD-2-Clause 只约束代码，不约束译文内容），无合规缺口（S10）。
7. **公理化**：`specs/046/bin/verify_standards.py` 对 `rules/standards.json` 求值——充分性（每条采纳项 owner+tool 非空）、一致性（id 唯一、owner 落点唯一无冲突）、完备性（五类规范覆盖流程六环节）；负向样本可证伪。定理见 `specs/046/spec.md`。

## 凭证

* 单测 503 项、`check_all` 15 项全绿；判定器对 standards.json 求值全过；负向样本退出码 1。

## 取代链

不取代任何既有 ADR；扩 ADR-0041（标准对齐基线）为机读登记册 `standards.json` 的事实源；ADR-0070（机检为筛）与本 ADR 的 S02/S04 采样与差错率互证。

## 落点

* `rules/standards.json`：规范登记册（9 采纳项 + 1 不采纳项）。
* `rules/04`：S01/S04（问题分级+差错率）、S05（s3 三校）、S08（P4 数据非指令）。
* `rules/07`：S06（GB/T 7714-2025 新增要素）。
* `rules/05`：S07（SBOM 登记）。
* `specs/046`：spec.md（公理化证明）+ bin/verify_standards.py + results/sbom.json。
