# 0053. 全量 done 回炉重走前置环节（取消台账补课豁免线）

accepted | 2026-11-15

## 背景

ADR-0043 建立受控回退原语（`revert-state --to s2.5_checked`）时划了一条豁免线：A1 波及件回炉重走，**非 A1 的 done 存量"不回状态机、台账补课"**（specs/023 先例）；specs/036 承接该口径（done 存量走 `makeup-<letter>.jsonl` 台账制，不改状态机）。

2026-11-15 实查推翻了这条线的实质基础：

1. 全库 219 件当前 done **无一携带 s24/s25 步记录**（ADR-0043 三环节 2026-11-14 才生效，其后没有新 done 完成）；s0（ADR-0052，2026-11-15）亦然。即"台账补课面"与"回炉面"覆盖的是**同一性质的存量缺口**——环节生效时点晚于存量产出，413 件（回炉池 194＋done 219）无一遍过 s0/s2.4/s2.5。
2. 豁免线只剩凭证形态差异（台账行 vs 状态机步），流程保证强度不同：台账制不拦后续推进，状态机回炉件受 s3 前置 s0 记录等硬门约束。同一缺口两套口径，正是单轨化的反例。

用户 2026-11-15 裁定：**所有 done 必须重走 s0、s2.4、s2.5**，取消豁免线；先行批次按字头 a（池内 27＋done 35）与 1（done 1）执行，共 63 件。

## 决策

1. **豁免线取消**：ADR-0043 决策中"非 A1 的 done 存量不回状态机（台账补课）"与 specs/036 "done 存量台账制补课（不改状态机）"两条自此**作废**。凡未经 s2.4/s2.5 环节的存量 done 一律经 `revert-state --to s2.5_checked` 回炉，按在途件通道补课。本裁定后新完成的 done 已含全部前置环节，不在此面。
2. **回炉件工序**（与 ADR-0043 回退件完全同构）：`revert-state` → `task_ops.py source-audit` 补 s0（进 s3 硬门，specs/036 在途通道）→ s2.4/s2.5 增项（specs/028 §4 六项＋面⑦；s24 无独立 advance 步，凭证随 s3 evidence 落账）→ s3（增补后）→ r1–r3 全重走 → done；旧凭证留史。
3. **先行批次**：字头 a＋1 共 63 件（回炉池内 27＋当前 done 36）；其余字头随后续批次滚动。批量回退走清单驱动脚本（specs/028 `bin/revert-done-batch.py`，快照＋manifest 落 `results/`）。
4. **面口径**：specs/028 回退面由 A1 波及面扩至存量全量面 413 件；specs/036 §3 的 done 行同步改注；台账制 `makeup-*.jsonl` 不再新增（已产出行保留为历史凭证）。
5. **归因登记**：specs/004 W 表追加 W12（ADR-0039 纪律：返工必归因）。

## 后果

* **正面**：全库出厂口径齐平——任何 done 都意味着走过 s0/s2.4/s2.5/s3/r1–r3 全链；补课凭证双轨（台账/状态机）归一为状态机单轨，消除两套凭证漂移风险。
* **代价**：done 计数阶段性回落（先行批后 219→183，随后全量置空），在途面扩大至 413；工作量按试点实测消化（“一个”节制逐例语义判定约 40% 违规率、单件近百判定点），按字头滚动推进。
* **规则面**：rules/04 "已完成条目回炉"条款改写；specs/028 增裁定追加节；specs/036 §3 口径注记；ADR 索引补 0049/0052/0053 行。
