# 0023. 根目录白名单与散件归置（门禁扩展）

状态：accepted | 日期：2026-11-06

## 背景

2026-11-06 用户指令：「不要在根目录放垃圾，同时形成规则门禁。现在开始清理。」

复核根目录发现三类问题，共 24 项越界：

* **已入库散件 18 个**：翻译会话中间产物（`trans_p1`–`trans_p8.json`、`ed_segments.json`、`ed_seglist.json`、`ed_refs.json`、`ed_body_segments.txt`、`ed_seg_sources.txt`、`step1_change.json`、`state_hume_blocks.json`、`seg_sources.txt`、`.tmp_segs.json`、`dev_null.json`、空文件 `diff_rmb.txt`）、一次性生成器 `gen_change_ledger.py`（硬编码 `D:\SEP-CN` 与词条 `change` 的 68 段）、Trae IDE 遗留 `.trae/specs/add-intent-first-doctrine/`（3 文件，内容已由 rules/08 + ADR-0018 + specs/004 吸收）。
* **本地脚手架/缓存 5 项**：`__pycache__/`（21 个根级散件脚本的字节码）、`_f_pipe/`、`_f_prompts/`、空目录 `.screenshots/`、根级 `SUMMARY.md.tmp` 与 `mu-lu-s.md.tmp`（写入中断残留）。

根因是门禁形态而非清理不力：`check_junk.py` 只扫 `git ls-files`——散件**入库之后**才报，而 `git add -A` 把它们扫进去的那一刻无人拦；同时 `.gitignore` 的 `/_f_pipe` 一类规则让根级脚手架在工作区隐身，`git status` 也看不见。

## 决策

1. **根目录白名单**（`tools/check_junk.py` 的 `ROOT_ALLOW`）：根层只允许五类条目——工具链配置（`.github`/`.vitepress`/`.specify`/`.zcode`/点文件）、顶层叙事文档（`SUMMARY.md`、`PROGRESS.md`、登记册、访客文档）、A–Z 词条字母目录与数字目录 `1/`（ADR-0009）、结构目录（`rules/`、`specs/`、`tools/`、`tasks/`、`baseline/`、`assets/` 等）、包管理文件（`package.json`、`bun.lock`）。新增根级条目须走 ADR。
2. **门禁双向核对**：跟踪清单 ∩ 白名单 + 工作区 `os.listdir` ∩ 白名单。根级散件无论是否被 `git add -A` 扫入、是否被忽略规则漏掉，一律红灯（退出码 1）。CI 侧只看到跟踪清单，恰好覆盖「已入库」；本地收工跑 `check_all` 时同时覆盖未入库散件。
3. **散件归置唯一路径**：本地会话草稿 → `script/`（忽略）、运行态 → `state/`（忽略）、批次工件与凭证 → `specs/<NNN>-*/bin|results/`（入库）；临时文件写 `state/`，不在根目录留 `*.tmp`。
4. **清理执行**（本 ADR 当日完成）：18 个入库散件 `git rm --cached` 并从磁盘删除（内容可由 git 历史 `5b6c476f` / `ad2b36f9` 回溯）；`gen_change_ledger.py` 归档 `specs/005-translation-campaign/bin/`；`.trae/` 退役；`_f_pipe`/`_f_prompts` 迁入 `script/`；删除 `__pycache__/`、`.screenshots/`、根级 `*.tmp`。
5. **规则落点**：`rules/01-repository-structure.md` 增「根目录白名单」节（结构规则的单一事实源）；`rules/05-ci-and-tools.md` 门禁表与 `checks.yml` 描述同步；`rules/README.md` 快速判例与 `AGENTS.md` 硬约束速览各增一条。

## 后果

* 根目录从此是可枚举的契约面：67 项白名单，越界即红；`git add -A` 扫入散件会在 CI 与本地同时咬住，不再依赖人工复核。
* 代价是新增根级文件须先改 `ROOT_ALLOW` 并留 ADR——刻意的摩擦，防止再次堆积。
* 白名单对**所有**根级条目生效，包括被忽略的本地目录；因此新会话不得在根目录创建 `_xxx/` 脚手架，须直接写在 `script/` 下。`en/`、`yuanwen/`、`node_modules/`、`state/`、`script/`、`.secrets/`、`.workbuddy/` 已在白名单内，仍按原忽略规则不入库。
* `rules/01` 中图片路径描述（`yuanwen/assets/`）与实际（正文以 `../assets/` 指向根层 `assets/`，词条图片就地入库）不一致，属既有文档债，另案处理，不在本 ADR 范围内。
