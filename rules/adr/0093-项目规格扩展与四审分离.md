# 0093. 项目规格扩展与四审分离

状态：accepted　日期：2026-11-28（064 T171；CP-S14-06–11）

## 背景

ADR-0086 已建 `project_spec` 六项并挂 `tr-02` 机检，但只覆盖 ISO 11669:2024 的部分内容参数，缺过程参数（PE 级别）与其他参数（风险等级、保密、沟通、资格）；`sg-01`／`sg-02` 仍允许与初译同人，登记为 V01 部分偏离。T171 要求三类参数齐全、缺项不得进 `tr-02`，并取消 V01，建立 RACI 与 competence 记录。

## 决策

1. **`project_spec` 三类 16 字段**：内容（language_pair、content_type、audience、purpose、subject_field、terminology_basis、register）、过程（workflow、pe_level、qa_level、pre_edit）、其他（risk_level、confidentiality、delivery、communication、qualifications）。建账写入项目默认值，允许逐项覆盖；未知字段或空值拒建账。
2. **`tr-02` 机检**：16 字段全部非空；`risk_level` 限 A 高／B 中／C 低／内部；`pe_level` 限 full／light／n/a（人工翻译），且须与 `translation_mode`／`task.pe.level` 一致；缺受众、用途、QA、PE、风险任一即拒。
3. **RACI 与 competence**：角色×P0–P7 矩阵入 `rules/09` §2.1；任务 JSON 增 `competences[actor]`，四项 qualification／experience／domain／training 必填；`sg-01`／`sg-02`／`sg-03` 推进前校验，缺项即拒；CLI 增 `task_ops.py competence`。
4. **四审分离**：译者（tr-02）≠双语审校（sg-01）≠复审（sg-02）≠终审（sg-03），actor 两两不同；冷置／密度补偿不适用于任何审校环节；V01 从 `standards.json.deviations` 移除，`rules/README` 偏离登记同步改写。
5. **兼容**：既有 done 任务的六字段 `project_spec` 不回填、不改写；如重开并推进 `tr-02`，须先补齐 16 字段，否则机检拒绝。

## 后果

* 正面：项目规格、角色、能力与独立性由文字约定变为机检；V01 取消后三审不再有同人例外。
* 代价：新增 10 个 `project_spec` 字段与 `competences` 记录；未来审校须使用不同 actor 并逐人登记能力。
* 回退：`git revert` 本批；`project_spec` 旧六字段仍可读，`task_ops` 的 `tr-02` 机检可单独回退到 ADR-0086 口径。
