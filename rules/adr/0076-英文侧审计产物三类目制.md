# 0076. 英文侧审计产物三类目制：模板契约、补丁、勘误装配分目

accepted | 2026-11-19（权威＝用户指令“批准053，同时：把 html 模板、补丁、生成勘误表的装配信息分别独立处理到按国标等存放到不同目录，具体目录结构执行国标等标准”；形态经三方案预览选定“三类目平铺”）

## 背景

specs/053（EN 语料模板审计与勘误装配线）立项，用户同时指令三族产物分目、目录结构执行国标等标准。标准筛查结论（依据 `jian-yi-shu/mu-lu-fen-lei-gui-fan-jian-yi-shu.md` 2026-11-17 条款级研读＋2026-11-19 条款回核）：**没有任何国标直接规定代码仓库目录结构**——ISO 15489-1/GB/T 26162 管“记录的分类与保留”，IEEE 828 管“配置项与受控库”，DA/T 22 管“件的整理与档号”，GB/T 18894 管“电子文件归档存储结构”。声称“某标准规定目录结构”的说法不可信；目录结构只能从四者**组合推导**。

现状的错位：模板契约无独立目录（散在 specs/001 正文、parser.py、specs/044 判官与 specs/039 实测基线）；勘误装配信息分居两处（人读册在 `specs/001-sep-sync-pipeline/results/en-errata.md`，机器账在 `baseline/divergences.json` 根级）；仅补丁池已独立成目（`baseline/en-patches/`）。ADR-0062 决策 3 曾明言勘误表“路径不变以免断引”——当时引用面未闭合迁移成本高；本轮引用面已实测收敛（代码常量 2 处＋活文档 5 份），迁移成本可控。

## 决策

1. **baseline/ 受控库内按职能设三类目**（GB/T 26162-2021 分类方案：按职能 function/activity 分类；IEEE 828 受控库概念——baseline 只收登记态记录）：
   - **T `baseline/en-template/`**：HTML 模板契约正典 `template-contract.md`（汇编 specs/001 顶部事实＋parser 契约＋B0 十谓词＋转换映射）＋例外/变异登记册 `anomalies.json`（人审登记，ADR-0070 建议④口径）。
   - **P `baseline/en-patches/`**：补丁池**原位不动**（一补丁一文件＋INDEX.json；`en_patch_lib` 解析三律、命中计数硬校验不变）。
   - **E `baseline/en-errata/`**：勘误装配——人读册 `en-errata.md`、机器账 `divergences.json`、译注挂载台账 `note-anchors.json`（specs/053 P4 建账）。
2. **收编两个错位件**：`specs/001-sep-sync-pipeline/results/en-errata.md` → `baseline/en-errata/en-errata.md`；`baseline/divergences.json` → `baseline/en-errata/divergences.json`（均 `git mv` 保历史）。**取代 ADR-0062 决策 3 的“路径不变以免断引”条款**——该条款的动因（引用面未闭合）已消失，本 ADR 落点节列明全部引用修复。历史 ADR 正文与执行记录按只追加原则不改写，路径以本 ADR 为准。
3. **命名**：英文 slug（ADR-0067 决策 7 拼音命名域冻结）；目录内编目以 `README.md` 卷内目录承载（DA/T 22-2015 §3.2 整理五步之“编目”）；档号沿用 `P-00N` 式（§5.4.1 档号五原则：唯一性、合理性、稳定性、扩充性、简单性）。
4. **受控库 vs 工作区分界**：机检工作产物（B0/B1 扫描、structure-scan、triage）留 `specs/*/results/`（工程执行记录，IEEE 828 工作区）；受控库只收“登记态记录”（契约正典、例外登记册、人读册、机器账、挂载台账）。
5. **元数据**：容器级元数据沿用 `rules/layout.json` 七问字段（对 ISO 23081-1:2017 元数据四维：writer=责任、gate=法规、retention/lifecycle=业务、naming=技术）；子目录不单独登记（layout.json 为根级声明，ADR-0067 决策 1），子目录职责由本 ADR 与各卷内目录承载。
6. **标准登记**：`rules/README.md` 规范性引用标准增补三行（GB/T 26162-2021、GB/T 18894-2016、DA/T 22-2015；核验 2026-11-19）。版本风险登记：ISO 15489-1:2016 在修订轨道（目标 2029），GB/T 26163.1 修订在批（建书先例）——引用条款号前回原文重核。

## 后果

* **正面**：三族各有唯一目录，装配信息不再分居两处；模板契约首次有正典文件（specs/001 顶部降为历史抽样记录＋指针）；E 类目内人读册/机器账/挂载台账同区，跨账核对成本下降。
* **代价**：INDEX.json 与补丁文件头注释中的 `source: en-errata.md §九` 字段为**相对节号引用**（非路径），节号迁移后仍有效，故不动（补丁文件 sha 钉在 INDEX，改头注释即破坏命中校验）；历史文档中的旧路径引用按只追加原则保留。
* **回退**：git revert 本提交即整体回滚（git mv 双向可逆；代码常量与文档引用同批回滚）。

## 取代链

取代 ADR-0062 决策 3 的“勘误表路径不变”存放位置条款（三出口语义本身不取代）；取代 ADR-0045/0062 文内 divergences.json 的 baseline 根级存放（账目语义不取代）。未取代 ADR-0067（本 ADR 是其在 baseline 子目录层的职能化延伸）。
