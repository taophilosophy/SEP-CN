# 0068. 日志为事实、状态为视图：三存储一视图、pipeline 判据源、事件日志迁移

accepted | 2026-11-18（权威＝用户指令"全部批准，按不计成本最佳建议执行"；依据＝`jian-yi-shu/zong-zhi-xing-shu.md`）

## 背景

进度模型重建系列（specs/042 三级结构、specs/043 公理化验证）经用户逐轮批准，收敛为总执行书：把挤在 `state` 单字段上的四种语义拆给四个载体，用事件日志取代会覆盖的游标。体检（`reset_audit.py`）实测：385 件曾走完全链（含三审），账上只记 1 件 done；828 次 revert 全部来自 3 次判据改进（单价 276 条/次）。本 ADR 记录总执行书 W0–W2、W1、W4 的实施与一次执行期发现（迁移不完整）。

## 决策

1. **三存储一视图**：`journal/`（事件日志，事实）＋ `rules/pipeline.json`（判据与节点，唯一源）＋ `specs/005-translation-campaign/ledger.json`（调度）＋ `tools/journal_view.py`（派生视图，只读）。`state` 与 `stale` 是视图派生量，不再作为事实。
2. **`rules/pipeline.json` 为判据唯一事实源**（`git mv` 自 `jian-yi-shu/pipeline-17.json`，保历史）：16 作业节点（三段：Seg1 提取 P1–s0、Seg2 翻译 P4–F2、Seg3 审校 s2.4–R3）、四类型（pipe/stage/review/format）、三档降级（widen/tighten/replace）、`criteria_owner`（每判据唯一硬拦点）。`jian-yi-shu/journal-schema.json` 的 `nodes_ref` 改指它；`specs/043` 验证器读它。
3. **新增 `tools/check_stages.py` 四谓词**（S1 链闭合／S2 判据唯一／S3 强制集／S4 类型值域，全部只读，A11）：对 pipeline 求值 11 项全绿。
4. **新增 `tools/journal_migrate.py` 一次性迁移**（W1）：只读 `tasks/**/*.json` 的 `steps`＋`version_pin`，派生 `journal/<letter>/<slug>.ndjson`（六类事件）。`done`／`clear` 不落 journal（`done` 是派生量，饱和由 `pass` 集合推导）；无阶段记录的条目合成 `import{synthetic:true, basis:state}`；只迁 `retranslate`／`update` 词条任务。
5. **新增 `tools/journal_view.py` 派生视图**（W4 的 journal 侧组件）：折叠 `pass` 集合现算核心段完成／强制集完成／完整饱和，只读不写（P6/P24）。`stale` 由 `drift_scan` 派生，不在此重复实现。
6. **`rules/layout.json` 登记 `journal/`**（evidence/record/slug/permanent，`writer` 为 journal_ops＋journal_migrate，`index` journal/README.md）；`rules/01` 职责表补 `journal/` 行；L1–L4 全绿（声明 70 条）。
7. **公理登记 `jian-yi-shu/axioms.json`（P1–P28，含补入 P28 单一事实源）**：整合 041 的 A 系列、042 的 C 系列、043 的 A–J 谓词组，三套撞号编号统一为 P 系列；C13/C14 降为定理 T1/T2。
8. **W3 双写与 W5 删硬编码（2026-11-18 复核后补遗）**：用户澄清——迁移的是**翻译流程（工具/规则/数据结构）**，不涉及实际翻译任务；W3/W5 是纯工程，可用测试词条验证，不需等待真实任务流经。据此补遗：① W3——`task_ops` 在每次状态推进（advance/revert/reopen/source-audit）后，经 `tools/journal_lib.append_event` 向 `journal/` 追加对应事件，`state`（tasks）与 `journal` 双写并行；② W5——`ORDER`/`STEPS` 从 `rules/pipeline.json` 节点链推导（`_derive_order_steps`），删除硬编码序列；`update` 死序列删除（`create` 拒绝非 retranslate，上游修订走 `reopen --upstream-sync`）；`revert-state` 目标态由 `REVERT_CHECKPOINTS` 推导。测试词条验证：新增 `test_journal_double_write_consistency`（完整流程推进后 journal 的 pass 节点序列与 state 一致），500 单测全绿。
9. **W0 打 tag `pre-reset-20261118`** 冻结任务写入（已推送远端）。
10. **W4 切读面（2026-11-18）**：`tools/progress.py` 的进度读数从 `tasks/**/*.json` 的 `state` 游标切到 `journal/` 的 `pass` 事件集合——完成=核心段完成（`CORE ⊆ passed`，`CORE={draft,s1,s2,S3,R1,R2,R3}`）、在途=有 pass 未走完 CORE、未开工=无 pass。`state` 不再作为进度事实，`tasks` 仅保留调度侧读源（例行任务判定、blockers）。`PROGRESS.md` 由 journal 派生重新生成；`load_journal` 加可注入路径并配 3 项单测。新旧读数差异逐条可解释：旧 `done=2`（state 游标被 828 次 revert 覆盖）→ 新核心段完成 `394`（journal 保留完整 pass 历史）。

## 执行期发现：迁移不完整（必须如实记录）

`journal_view.py` 对迁移产物求值，暴露三件执行书未预料的事实：

1. **task_ops 状态机只覆盖 16 节点中的 10 个**：`P1/P2/P3/F1`（管线，由 fetch/convert 工具承担）与 `P4/F2`（预处理与格式）不在 `task_ops` 状态机内，故迁移产物无其 `pass` 事件。**完整饱和（pass ⊇ 16 节点）恒为 0**，须 `journal_ops` 落地后由管线事件补齐。这是执行书 §3.3 saturation 谓词的实现缺口：饱和不能仅由翻译状态机的事件推导，管线段须由 `en/`、`yuanwen/` 文件存在性另行确认。
2. **`s0`（ADR-0052）、`s2.4`/`s2.5`（ADR-0040/0043）是后加环节，存量几乎未走**：411 件 `s2.4_termchecked` 是 `revert-state` 从 done/s3 回退到达的，不是 `advance --step s24` 通过。故 `s2.4`、`global` 节点的 `pass` 数≈1，强制集完成恒 0。迁移的忠实反映是 `pass(draft…R3) → rework(from_node=s2.4)`，而非造出 `pass(s2.4)`。
3. **`done` 是派生量，核心段完成 394 是其最优近似**（vs 精确 `done` 385）：394 个任务有完整的 `draft/s1/s2/S3/R1/R2/R3` 通过，385 个 steps 含 `done`。差异 9 来自停 r3 未 done 或 reopen 后再 done。

**迁移统计**（`tools/journal_migrate.py --dry-run`）：任务 1197、事件 5875、done 在位 401、synthetic 766（词条口径；reset_audit 的 768 含 2 个非词条任务）。

## 后果

* **正面**：`state` 单字段的语义过载被拆解，事实落 `journal`、判据落 `pipeline`、读数落 `journal_view`，各有一源；`check_stages` 把 pipeline 的结构一致性变成可机检门禁；`journal_migrate` 把 4,993 条 steps 忠实换算为六类事件，`rework` 的 `from_node` 与历史 828 次 revert 逐条对账（s2.4 411 ＋ global 417 ＋ None 46）。
* **负面／跟进**：① 迁移产物不含管线 6 节点事件，完整饱和恒 0，须 `journal_ops` 落地后补齐；② `s0`/`s2.4`/`s2.5` 存量未走，强制集完成恒 0，是 ADR-0052/0040/0043 增补环节的历史债，非迁移缺陷；③ W3/W5/W4 均已于 2026-11-18 完成（决策 8、10）：进度读面切到 `journal`（核心段完成 394），`state` 降为 task_ops 推进的游标载体与调度侧读源；`journal` 与 `state` 仍双写并行（W3 通道保留，`journal_ops` 接管推进前不撤）；④ `journal_view` 暂不实现 `stale`（由 `drift_scan` 派生）。
* **回退**：`git revert` 本提交即整体撤销（tag 单独 `git tag -d`）；单独撤销迁移＝删 `journal/` 目录与 `tools/journal_migrate.py`、`tools/check_stages.py`、`tools/journal_view.py`、`tools/journal_lib.py`，`rules/pipeline.json` 经 `git mv` 可逆。
* **取代链**：不取代任何既有 ADR；`revert-state` 的目标态推导与 `update` 死序列删除是对 ADR-0043/0063 回退原语与 ADR-0051 上游同步的**实现方式替换**，语义不变。

## 复核凭证

1. **守恒**：迁移只读 `tasks/`（`git diff tasks/` 为空）；`rules/pipeline.json` 经 `git mv` 保历史；journal 生成前后 `reset_audit.py` 数字一致。
2. **对账**：`rework.from_node` 分布（s2.4 411 ＋ global 417 ＋ None 46）与历史 revert 归因（411 ＋ 219 ＋ 198 ＋ 46）逐条一致；核心段完成 394 与 `done` 385 的差异可解释（停 r3 或 reopen）。
3. **门禁**：`check_stages` 11 项全绿；`verify_pipeline` 51 项全过（含 K 公理登记 10、L 自述 6）；`check_layout` L1–L4 全绿（声明 70 条）；`check_all` 15 项全绿（W2 增 stages 门禁）。
4. **负向**：`journal_migrate` 的 W1 判据（事件≥4993、done≥385、synthetic≥766）在 dry-run 与实跑均满足；synthetic 口径已修正（clear/done 不标 synthetic，只标无史任务）。
5. **W3/W5 补遗（2026-11-18）**：`ORDER`/`STEPS` 推导结果与删除前的硬编码逐字节一致（retranslate 13 态、STEPS 11 键、REVERT_TARGETS 二元组）；`update` 死序列删除后 `create` 拒绝非 retranslate（`test_create_rejects_update`）；双写一致性由 `test_journal_double_write_consistency` 验证（完整流程推进后 journal pass 节点序列 = s0/draft/s1/s2/s2.4/global/S3/R1/R2，state=r2_reviewed）；500 单测全绿、无 `test-*` 污染（journal 目录经 `JOURNAL_DIR` 注入隔离）。
6. **W4 切读面（2026-11-18）**：`progress.py` 进度读数切到 journal 后，核心段完成 `394`、在途 `37`、未开工 `766`、强制集完成 `0`、完整饱和 `0`。节点通过数呈自洽递减链（draft 425 → s1/s2/S3 431 → R1 407 → R2 402 → R3 400 → 核心段完成 394，每层 ⊇ 下层）。与旧 state 游标读数（done=2、s2.5_checked=395）的差异逐条可解释：state 被 828 次 revert 覆盖只留最后位置，journal 保留完整历史。`test_progress` 3 项（折叠、空目录、忽略非 pass）全过；`check_all` 15 项全绿、`check_doc_size` 达标、引号 0 违例。
