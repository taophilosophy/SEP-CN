# 0054. 终审须用户显式指定会话（R3 默认不进行）

accepted | 2026-11-15

## 背景

r3 终审是状态机 done 前最后一环（终稿验收＋CI 全绿）。此前口径下终审由执行会话自行推进：ADR-0020 裁定②只约束了执行形态（混合制 r2 交叉、r3 冷置重读），未约束"谁有权发起终审"——实操中终审与复核在同一会话内自走，验收签字实际由执行会话自签，用户对"什么算最终验收完成"没有把关点。

用户 2026-11-15 裁定：**R3 终审必须由用户显式指定会话进行，否则不进行 R3**。

## 决策

1. **会话门槛**：R3 终审仅当用户显式指定会话执行终审（指明范围——件或批次）时进行；未指定时不进行 R3，条目默认停 **r2_reviewed**，done 相应冻结（done 的前置仍是 r3_reviewed，不因本裁定放宽）。
2. **机检硬门**：`task_ops.py advance --step r3` 新增 `--mandate <用户指定记录>` 必填参数（缺失即 PreconditionError 拒绝），step 记录留 `mandate` 字段（何时/何范围）；指定记录的真实性属审计面（收工核对与用户当轮发言对得上），与 [ADR-0051](0051-reopen分类与在途上游同步绕过.md) `--upstream-sync` 凭证审计同构——不留痕迹的终审不存在。glossary-maintenance 类任务随既有 r3 门一样豁免。
3. **指定不继承**：指定只在被指定的会话与范围内有效，下一次终审须重新指定。
4. **取代关系**：本裁定就"r3 的默认执行"取代 [ADR-0020](0020-译文语言质量门禁.md) 裁定②的执行面（r2 交叉、r3 冷置重读的默认自走）；r3 真正执行时，复核独立性与冷置要求、学术挂钩（`check_academic --strict`）照常适用。
5. **不追溯**：已 done 件维持 done；在途件停 r2_reviewed 等待指定，或经 [ADR-0043](0043-s2.5-checked前置阶段合并与全量回退.md) `revert-state` 受控回退重走复核。

## 后果

* **正面**：终稿验收的把关权回到用户，done 成为用户显式放行的产物；机检实拦防执行会话自签终审。
* **代价**：done 吞吐受用户终审会话排期约束，r2 后积压面扩大成为常态，PROGRESS 的 done 计数相应滞后。
* **规则面**：rules/04 新增"终审会话门槛"节（状态机表、六道表 r3 行、复核独立性条款同步）；rules/06 done 定义、rules/07 校次衔接表、rules/09 P7 门禁同步；`contracts/cli.md` advance 行为注记与职责权属表、`tasks/README.md` 状态机节同步；`tools/task_ops.py`＋测试（新增缺 mandate 拒绝用例）落地。
