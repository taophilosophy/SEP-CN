# 0049. 孤立希腊字母文字化体例（正文孤立希腊字母不用公式定界符）

accepted | 2026-11-15（用户裁定：行间孤立希腊字母没必要以公式格式显示；试金石范围为 `specs/005-translation-campaign/dai-fan-yi-gong-shi-duo.md` 清单已译三件；同日用户浏览器验收试金石与渲染修复，批准通过，本 ADR 转 accepted）

## 背景

SEP 原文的作者惯例是把**一切**希腊字母（含正文行间的孤立字母）写进 `\(...\)` LaTeX 定界符，由 MathJax 渲染。实测四条词条原始 HTML，数学片段之外裸写希腊字母为零。三层链路逐层实测：

* **源头**：`en/belief-merging/index.html` 等原文正文即有 `\(\omega\)`、`\(\varphi\)` 这类整段仅含一个希腊字母的行内数学片段（belief-merging 24 处、axiom-choice 20 处、logic-dynamic 64 处）。
* **转换层**：转换器 TeX 抽取保真（specs/018 审计），`\(...\)` 原样带出为 `$...$`，yuanwen 与 HTML 一一对应。
* **译文层**：对账纪律要求照抄源形态，三件已译词条合计 109 处孤立希腊字母公式（含 5 处撇号变体 `$\omega'$`）。

全库影响面：`<letter>/*.md` 共 32 个文件 606 处孤立希腊字母公式。

渲染后果：阅读站 math-plugin 保护 `$…$` 交 MathJax 3 tex-svg，孤立字母渲染成数学斜体 SVG，与周围中文正文形成字体、字号、基线三重反差，阅读突兀。而既有译文对孤立**拉丁**变量早已写作斜体文本（`*p*`、`*q*`、`*n*`、`*E*`），希腊字母入公式只是源形态残留，并非刻意体例。

与既有规范的关系：[02-style](../02-style.md) 上下标裁定（2026-10-28）已确立“有 Unicode 原生字符的直接用原生字符”的 Unicode-first 方向；斜体裁定（2026-10-29）已承认希腊字母作逻辑符号保留斜体。本体例是该方向在希腊字母场景的落地。此前无任何 ADR 裁决过此点。

依据与筛查（[08](../08-intent-first.md) §13，ADR-0042）：GB 3102.11-1993《物理科学和技术中使用的数学符号》——变量与变动附标用斜体，算符用正体；中文学术出版对正文提及的单个希腊字母变量通行直接排希腊字母，不拉数学模式。

## 决策

1. **三分类判据**（只动译文层；`yuanwen/`、`en/` 原始物不动，[ADR-0045](0045-原始物双账语义与分歧账.md) 双账语义不受影响）：
   * **A 类（变量，转斜体文字）**：正文行间孤立希腊字母，无下标、无撇号、不与运算符邻接 → 裸 Unicode 加斜体（`$\varphi$` → `*φ*`）。
   * **B 类（保持公式）**：撇号/下标等派生形（`$\omega'$`）、含运算或记号的复合式（`$\neg\varphi$`、`$\varphi\in A$`）、行内与显示公式段（`$$…$$`）内的成分，一律不动。
   * **C 类（算子与专名成分，转正体文字）**：孤立的算子符号或专名成分（belief-merging 的融合算子 `$\Delta$`、logic-dynamic 的模态 `$\Delta$`、`μ`-演算专名的 `$\mu$`）→ 裸 Unicode **不加斜体**（GB 3102.11 算符正体）。
2. **字形映射**（转文字时的唯一映射表）：`\alpha→α`、`\beta→β`、`\gamma→γ`、`\delta→δ`、`\epsilon→ε`、`\zeta→ζ`、`\eta→η`、`\theta→θ`、`\kappa→κ`、`\lambda→λ`、`\mu→μ`、`\nu→ν`、`\pi→π`、`\rho→ρ`、`\sigma→σ`、`\tau→τ`、`\chi→χ`、`\psi→ψ`、`\omega→ω`、`\Gamma→Γ`、`\Delta→Δ`、`\Theta→Θ`、`\Lambda→Λ`、`\Pi→Π`、`\Sigma→Σ`、`\Phi→Φ`、`\Psi→Ψ`、`\Omega→Ω`；**`\phi` 与 `\varphi` 同归 `φ`（U+03C6）**，按中文出版惯例归一字形。例外：同词条兼用 `\phi` 与 `\varphi` 作不同变元时，`\phi` 转 `ϕ`（U+03D5）保区分（全库现无此例，试金石三件已核验）。
3. **工具协同**：
   * `tools/check_pairs.py` count-vs-source：两侧计数前对称剔除 A/C 类孤立希腊字母片段，避免回改触发对账告警；容差与告警级不变。
   * `tools/check_math_zh.py` 新增 **C10（告警级，不影响退出码）**：译文正文残留 A/C 类孤立希腊字母公式时提示转文字；B 类不在列。
4. **落地次序**：试金石三件（belief-merging、axiom-choice、logic-dynamic，A 类 100 处＋C 类 4 处）→ 用户渲染验收、本 ADR 转 accepted 并增补 [02-style](../02-style.md) 条款 → 铺开其余 29 件 497 处（另批立项）→ 未译条目翻译时即按本体例执行，不再产生新存量。
5. **回改作业形态**：批量改写，走 [05-ci-and-tools](../05-ci-and-tools.md) 五纪律（残余前置门、幂等、逐行身份追踪、基线还原、结构审计）；`$$` 行硬守卫（含 `$$` 的行禁止改写）；逐处台账入战役执行记录。

## 后果

* 正面：消除孤立字母的 SVG/正文视觉反差；与既有拉丁变量斜体体例对齐；未译条目（含 38 条清单其余 35 条）在翻译期即消化，避免译后回改（lambda-calculus 源头即有 450 处孤立 λ/β）。
* 代价与噪音：同段可能混排两种形态（`*ω*` 与 `$\omega'$`），`\varphi` 与 `\phi` 归一后与相邻公式的 MathJax 字形有微差（中文出版惯例内属可接受）；对账口径归一需工具同步，否则回改触发告警。
* 边界拍板项（验收时呈报，本役不动）：①撇号变体是否也文字化（`$\omega'$` → `*ω′*`，Unicode-first 方向支持，但同段公式密度高时保留公式更协调）；②带下标的孤立变量是否文字化（`$\alpha_1$` → `*α₁*`，Unicode 下标可用）；③同段混排的可接受度。
