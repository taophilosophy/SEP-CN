# 0001. 建立全局治理目录（rules / tasks / tools）

状态：accepted | 日期：2026-10-27

## 背景

仓库此前的规则散落且失位：根目录 `AGENTS.md` 的内容是另一项目（UNIX 书翻译）的规范，与本仓库（斯坦福哲学百科中文版）不符；体例、流程、术语规则无统一存放处；本地校验脚本散在 gitignore 的 `script/` 草稿区，不可审计；任务记录的协议只存在于 `tools/task_ops.py` 的 docstring 里。与此同时，`specs/001-sep-sync-pipeline` 已确立宪法（`.specify/memory/constitution.md` v1.0.0）、任务状态机与管线工具包，治理层需要与它们对齐而非另起炉灶。

## 决策

1. 新建 `rules/` 作为全局规则唯一存放处：结构（01）、体例（02）、术语（03）、翻译流程（04）、CI 与工具（05）、软件工程治理（06），外加 `adr/` 决策记录。规范层级为：宪法 > rules > specs/<feature> > README。
2. `tasks/` 维持既有 JSON 约定（`tasks/<slug 首字母>/<slug>.json`，`tools/task_ops.py` 状态机驱动），补 `tasks/README.md` 把协议显式化，不引入第二种任务格式。
3. `tools/` 为唯一入库脚本目录：既有管线包保持不动，目录治理类脚本（`check_summary.py`、`check_mulu_s.py`）从 `script/` 草稿区迁入；`script/` 保留为 gitignore 的个人草稿区。
4. `AGENTS.md` 改写为 AI 代理入口指针：只放仓库定位、规范层级、按任务类型的必读清单与硬约束速览，规则正文一律指向 `rules/`。原 UNIX 书内容废止。
5. 术语双文件关系定为：`yi-zhe-shuo-ming.md`（根目录，登记册）为译法决策源；`qian-yan/ci-hui-biao.md` 为发布词汇表视图。

## 后果

* 规则首次集中、可引用、可审计；AI 会话与人工贡献者有统一入口。
* 原 `AGENTS.md` 中不适用于本仓库的内容（UNIX 书章节结构、PDF 提取、`en/` 约定）不再误导；其中可迁移的体例规则已并入 `rules/02-style.md`。
* `script/` 中的一次性脚本不入库，其效果由 git 历史与 `specs/001/demo-log.md` 凭证追溯；后续沉淀工具时迁入 `tools/` 并登记。
* 待跟进：正文术语与登记册一致性的工具化校验；`mu-lu-s.md` 在宪法 III 中被表述为"不手改"，与其实际"手编分类目录"的定位存在措辞冲突，以本 ADR 与 `rules/01-repository-structure.md` 为准，宪法下次修订时一并澄清。
