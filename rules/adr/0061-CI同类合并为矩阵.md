# 0061. 同类 CI 合并为矩阵：门禁单一事实源、格式化三工具一条流、壳仓部署二合一

accepted | 2026-11-16

## 背景

`.github/workflows/` 曾有 14 条工作流、构建壳仓另有 3 条，逐条核对后发现两类问题。

**一、复制自前宿主（FreeBSD 书项目）或早期接线后未随本仓改造**：

* `check-images.yml` 触发路径写 `.gitbook/assets/**`——本仓从无 `.gitbook/` 目录，图片在根 `assets/<slug>/`（rules/01），该工作流只在手动触发时才有意义；
* `create-pdf.yml` 钉 Python 3.15，而 rules/05“运行时基线”写着导出线“暂留 3.13”，两处口径互斥；
* `render-artifact-audit.yml` 仍用 `NODE_OPTIONS=--max-old-space-size=12288` 全量单进程构建，而站点部署链 2026-11-16 已切 `SEP_SHARD` 四片并行＋`bun --bun x` 运行时（ADR-0014/0055）；
* `.github/lychee.toml` 的 `exclude` 留着 `ftp.freebsd.org`、`http://ip/.*` 等前宿主条目，`exclude_path` 只排除 `.github`，原样会去查 `en/`（375 MB 原始物）与 `yuanwen/`（312 MB 逐字符镜像）；
* markdownlint 两条工作流都用 `.github/.markdownlint.json` 副本，而权威配置是根 `.markdownlint-cli2.jsonc`（ADR-0002/0016）；autocorrect 的配置在根与 `.github/` 各存一份且逐字节相同。

**二、同类重复劳动**：

* `checks.yml` 先逐条跑 8 个门禁，再跑 `check_all.py --quiet`（内含同样 10 项＋单测），同一批检查做两遍；
* `sync-headers.yml`（`check_summary.py --headers`）与 `file-name-check.yml`（SUMMARY 缺件开 issue）都被 `check_summary.py` 的门禁覆盖（ADR-0024 已把 H1 一致性做成硬门禁）；
* `check-images.yml` 与 `checks.yml` 的 `check_images.py --gate` 同一逻辑两个入口；
* `markdown-lint2.yml`、`Markdown-lint2-pr.yml`、`md-padding.yml`、`AutoCorrect.yml` 四条都是“改 Markdown 空格/格式→开 PR”同类；
* 壳仓 `push_deploy.yml` 与 `sync_deploy.yml` 的 build/merge/deploy 三段几乎逐行重复，只有前置“是否先拉子模块”不同。

用户 2026-11-16 指令：把所有 GitHub CI 对本项目适配，同类合并为矩阵。

## 决策

1. **门禁矩阵，清单单一事实源**：`tools/check_all.py` 的 `GATES` 增加矩阵键，新增 `--list-gates` 输出矩阵 JSON（十项门禁＋管线单元测试，单行供 `GITHUB_OUTPUT`）。`checks.yml` 由 `plan` 作业生成 `fromJSON` 矩阵，每项一个作业，`fail-fast: false`；新增/改名门禁只改 `tools/`，CI 自动跟随。门禁命令不再抄进 YAML。
2. **退役三条被覆盖的工作流**：`sync-headers.yml`、`file-name-check.yml`、`check-images.yml` 删除，`.github/scripts/check_images.py` 一并删除；H1、缺件、图片分别由 `summary` 与 `images` 矩阵作业实拦，图片报告与失败日志改入运行工件（issue 通道退役，红灯即信号）。
3. **格式化三工具一条流**：新建 `format.yml`，`workflow_dispatch` 时矩阵跑 `markdownlint`／`autocorrect`／`md-padding`（各自 `--fix`、各开一条 PR），`pull_request` 时只读跑 markdownlint（告警级）。禁改区一律排除：`en/`、`yuanwen/`、`script/`、`state/`、`.zcode/`、`.specify/`、站点产物、测试夹具、`SUMMARY.md`、两本登记册。配置统一到根 `.markdownlint-cli2.jsonc` 与根 `.autocorrectrc`，删除 `.github/` 两份副本。合并仍须人工核 diff（禁机械替换译文，rules/05）。
4. **链接检查范围单点**：`links.yml` 只保留 `.github/lychee.toml` 的 `exclude_path` 作为范围事实源（排除 `en/`、`yuanwen/`、`script/`、`state/`、`.zcode/`、`.specify/`、`.vitepress/`、`node_modules/`、测试夹具、`.github/`、`SUMMARY.md`），并清掉前宿主 URL 条目。
5. **渲染残留审计矩阵化**：`render-artifact-audit.yml` 改四片矩阵（`SEP_SHARD=ad|ek|lp|qz`），逐片扫描 `dist-<shard>`、逐片上传报告；运行时切 `bun --bun x`，删 `NODE_OPTIONS`。
6. **导出线口径落定**：`create-pdf.yml` 保留外部 `gitbook-pdf-export`（只读使用、产物只上传工件），Python 钉 **3.15**（用户裁定，rules/05 原“暂留 3.13”注记作废）；SUMMARY 首字母过滤改为**按 `## <字母>` 小节走**——ADR-0057/0060 之后占位母行与别名行是无链接行，旧逻辑会把被排除字母的参见行留在产物里。
7. **`sep-sync-check.yml` 补登记**：该周检一直在跑但 rules/05 清单表漏登记；本次补行并钉 Python 3.15。
8. **壳仓部署二合一**：`push_deploy.yml` 与 `sync_deploy.yml` 合并为 `deploy.yml`，`workflow_dispatch` 输入 `sync_docs`（boolean）作前置开关；`sync` 作业只在开关打开时拉子模块并提交指针，`build` 作业按 `needs.sync` 结果决定是否构建（手动模式照旧取派发分支，同步模式取刚推送的 `main`）。build 四片矩阵、merge、deploy 三段只保留一份。

## 后果

* **正面**：门禁与 CI 不再两处维护（改 `tools/` 即生效）；红灯作业名就是具体门禁，失败日志按门禁分开；同类工作流从 14 条降到 7 条、壳仓 3 条降到 2 条，后续改动不会再落在“另一份副本”上；格式化改动只走人工复核的 PR。
* **代价**：门禁矩阵 11 个作业各自全量检出（`en/`＋`yuanwen/` 约 690 MB），runner 分钟数高于原单作业两遍跑；换来定位精度与并行墙钟。数字类收益不构成改回的理由，取舍理由记录在此。
* **退役面**：SUMMARY 缺件与图片的 **issue 自动开/自动关**通道取消；红灯 + 工件足以定位，需要跟踪时人工开 issue。
* **不改变**：`check_all.py` 本地一键复核语义（十项＋单测，`--all` 加本地数据项）；push 触发的门禁强度；ADR-0024 的“CI 不写回 main”。

## 落点

* `tools/check_all.py`：`GATES` 增矩阵键、新增 `UNIT_TESTS` 与 `--list-gates`；`tools/tests/test_check_all.py`（新增）守住单行 JSON、键唯一、命令指向真实脚本。
* `.github/workflows/checks.yml`（重写为矩阵）、`format.yml`（新增）；删除 `sync-headers.yml`、`file-name-check.yml`、`check-images.yml`、`markdown-lint2.yml`、`Markdown-lint2-pr.yml`、`md-padding.yml`、`AutoCorrect.yml` 与 `.github/scripts/check_images.py`、`.github/.autocorrectrc`、`.github/.markdownlint.json`。
* `links.yml`、`lychee.toml`、`render-artifact-audit.yml`、`create-pdf.yml`、`sep-sync-check.yml` 就地适配。
* 壳仓 `taophilosophy.github.io`：新增 `deploy.yml`，删除 `push_deploy.yml`、`sync_deploy.yml`（另仓提交，不改 `docs` 子模块指针）。
* `rules/05-ci-and-tools.md`：工作流清单表、运行时基线、lint 配置条；`rules/01-repository-structure.md` 图片门禁行；`rules/02-style.md` 检查行。
