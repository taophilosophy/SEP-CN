# 0019. 渲染产物级门禁与生成器源修复

状态：accepted | 日期：2026-10-30

## 背景

2026-10-30 会话实测出三类"源合法但产物错误"的静默渲染缺陷，七项门禁全部无法拦截：

1. **星内空格粗体**：A 批译文按体例（rules/02，中文强调用粗体）书写，但模板写成
   `** 内容 **`（星号内侧带空格）——CommonMark 翼规则使其**永不渲染**，页面显示
   裸 `**`。9 词条 237 对。`check_style` 的 `italic-cjk` 只拦斜体不拦无效粗体，
   `bold-spacing` 只管间距规范——**体例规则与语法有效性由两套互不重叠的检查器
   分管，形成双盲**。
2. **镜像星流错位**：`yuanwen.py` 把 `<em>`/`<strong>`/`<b>` 逐标签转 md 星号，
   em 先行转出的内层星与外层 `**` 组成三连星边界错乱；`<b>`（数学记号粗体）与
   `<em>`/字面星（如 `H*`）交错时星流奇偶错位并连锁整段——149 镜像文件 667 对。
3. **dev/build 渲染差异**：脚注引用在 dev 正常、build 产物字面化（1911 页
   2312 处，rationality-normative-nonutility 单页 122 处），头号假说是 markdown
   编译缓存与 footnote 插件 env 依赖不兼容（实验构建未完成，结论待重跑）。

同时实证两条结构规律：

* **静默失败永不立项**：attrs 吞花括号（kochen-specker 整页炸）当日修复，
  而只静默显示 `**` 的病存在多个批次从未被处理——错误可见性决定修复优先级，
  门禁必须把静默失败显性化。
* **修复必须落在生成器源**：SUMMARY 手改被生成器重写还原（实测）、镜像手改
  会被重转换回退——生成物层面的修正一律不持久。

## 决策

1. **新增渲染产物级扫描器** `tools/check_render_artifacts.py`（已登记 rules/05）：
   对构建产物 HTML 做文本级检查（裸 `**`、字面 `[^`、`]( ` 残留、哨兵 `@@M`），
   代码块内字面量豁免。分期转硬门禁：`literal**`/哨兵/链接残留先行；`raw[^`
   待镜像脚注问题定性后纳入。
2. **强调语法有效性入体例**（rules/02 附例）：`**` 星号内侧禁空格；强调形式以
   英文源标签为准映射（`<em>` → 中文粗体/拉丁斜体）；编号记号源无标签则纯文本。
3. **修复一律落在生成器源**：`yuanwen.py` 已按单层匹配 + `<b>` 保留 raw HTML
   修复（本次提交）；译文模板的星内空格由 A 批会话按 rules/02 附例自行修正。
4. **markdown 编译缓存**：`cache: false` 已在隔离构建配置试验，正式结论待
   重跑（实验构建因资源竞争未完成）；证实前镜像脚注缺陷不得归因于内容本身。

## 后果

* 门禁新增一类"产物级"检查：需要构建产物，CI 接入需在 build 之后（分期）。
* 豁免清单（代码块字面量、参考文献照录节）需随转换器演进而维护。
* 深读校对（009）的报告维度增加"渲染残留物"一项，由扫描器自动提供。
