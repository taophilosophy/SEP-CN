# 0081. 全库置空与进度纪元

状态：superseded（0082，2026-11-25：用户追加授权置空翻译历史，纪元机制撤除；置空正文与游标归零的决策仍有效）　日期：2026-11-25（用户当轮裁定：“既有中文翻译全部置空，除了 H1。所有进度全部置空。不计成本代价。”）

## 背景

六轴独立质量工序（ADR-0079）落地后，既有译文全部产生于旧三校体系之下——没有经过引文锁定、逻辑骨架、语域、计量、标点五道独立工序（q1–q6 成文时已判“此前的形态无效”，specs/060 §2）。用户裁定全库重译：不逐件修补旧译文，统一清零、按新六道流程重走。

复核计算前例（ADR-0080）已确立一条纪律：**改写历史不可取，声明边界可取**。journal 的 4,276 个事件与 `tasks.steps` 是过程凭证（ISO 15489-1、P5），不能为“进度归零”而删除；但“从哪一刻起算新进度”是一个可以声明的纪元事实。

## 决策

1. **正文置空**：SUMMARY 列出的正式词条正文全部截为 H1 一行（1,868 件中 427 件有正文被截、1,440 件本就只有 H1、1 件缺 H1 按词条名补回）；SUMMARY 之外的 8 件补充材料子文档同口径置空。执行器 `tools/wipe_translations.py`（试金石 3 件先行，再全量）。
2. **任务游标归零**：全部 1,200 条 retranslate 任务按状态机正规原语归零——done 走 `reopen`，在途走 `reopen --upstream-sync`，pending 直接 `clear`，cleared 有正文者截 H1；1 条 `clear` 基线 gate 未过（tarski-truth，缺 H1）按裁定强制置空并逐条留痕（不静默）。`blockers` 一并解除（unblock 留 evidence）。
3. **事实层不动**：journal 与 `tasks.steps` 历史**不删不改**；`reopen` 作为 rework 事件只追加。
4. **进度纪元**：`rules/epoch.json` 登记本纪元起点（2026-11-25T00:00:00Z）；进度视图（`progress.load_journal`、`journal_view.stage_done`）与账实不变量（`check_taskfile_invariant.journal_passed`）只统计纪元及之后的 pass 事件。旧 pass 是历史，不再是现行稿件的进度证据。
5. PROGRESS 重算：核心段完成、在途、强制集、饱和全部归零；账外 674、骨架 1,873、有正文 0。

## 后果

* 正面：全库处于统一的“待译”起点，六道流程（ex-04 源审计 → tr-02 初译 → tr-03/tr-04 两校 → rv-01 术语与体例 → rv-02 审计 → rv-03–rv-08 六轴 → rv-09 体例终校 → sg-01–sg-03 终审）从第一件起全量生效；置空是逐件留痕的（报告 `specs/060-*/results/wipe-2026-11-25.json`），可审计。
* 代价：既有 1,200 条的译文成果放弃重走（英文源、yuanwen、基线钉、登记册、勘误表全部保留，重译依据完整）；journal 体积增加约 1,054 个 rework 事件。
* 约束：进度视图不得无纪元直接读 journal（`epoch_lib.start()` 缺失即视为无纪元，此时视图回到全史口径——只应在复核历史时显式为之）；下一次置空须另立纪元条目并只追加修改 `epoch.json` 的历史记录（纪元自身也只追加：`epochs` 列表）。
* 回退：`git revert` 本批提交即恢复译文与任务游标；删除 `rules/epoch.json` 即恢复全史进度视图。journal 无需任何修补。
