# 0062. en 原始物文字冻结：只许格式变动，文字缺陷改由全局勘误表与译注承载

accepted | 2026-11-16

## 背景

`en/` 的不可变语义经历过三代口径：ADR-0027“已入库原始物只追加、不改写”→ ADR-0038（2026-11-14）开口“已核实四类可就地改正”（①明显排印／OCR 手误、②同页自相矛盾、③结构错位、④占位符未填），改正走“en-errata 登记→就地改→分歧账 register/patch→yuanwen 重转→baseline 重算→中文照录侧同步”五步链；至本裁定前，分歧账在册 112 件。

实测代价有三：

1. **“已核实”边界靠人判，越界反复发生**。2026-11-16 对全部 en 变动逐条复审即见一例：yorck 书目 `Renthe-Fink von, Leonhard` 被以①类名义改为 `von Renthe-Fink, Leonhard`——贵族介词姓在“姓, 名”倒序著录中本有多种合法惯例，上游形属**命名选择**，ADR-0038 决策 1 明文“不改 SEP 的命名选择”，该改属越界（已还原）。此类灰区（词序、体例、大小写、出版社与地名的先后）在批量作业中反复出现，人判不可靠。
2. **成本与冲突面高**。每一处 en 改动牵动 en/、yuanwen/、baseline/entries.json、baseline/divergences.json 四类共享文件与中文照录区，五步链加跨会话并行，冲突出现在每个环节；而收益仅是“让 en 看起来正确”。
3. **零信任语义本义被稀释**。`en/` 是上游字节事实（原始网页钉，`files[].sha256`）；本地“改正”使 en 不再等于上游，复查、比对、回溯都必须先读懂分歧账才能还原真相。

用户 2026-11-16 裁定（两轮补充）：新增门禁——**禁止除格式外的任何修改**；**新增全局勘误表**；**任何文字变动直接插入中文译文进行译注**；**全面回退任何文字变动**。续一轮更正：**HTML 格式变动也应一律以补丁形式嵌入**（便于批量转 en markdown 或其他派生物），**维持 HTML 禁止变动的最初禁令**——即 `en/` 字节零改动、连格式层修复也不落盘。

## 决策

1. **en/ 绝对冻结**：`en/**` 与 `baseline/entries.json` 的 `files[].sha256`（原始网页钉）**逐字节一致，任何变动禁止**——文字层（字母、数字、词序、标点、空格、条目增删与归位、节序、年份、人名与出版社拼写）与**格式层**（标签闭合、属性、注释配对等）一律不改。ADR-0027 的最初禁令全面恢复；ADR-0038 决策 1 的口子彻底关闭。`en/` 因此重新是“上游字节事实”：任何时刻可对钉直接比对，无需先读账。
2. **补丁层（仅格式）**：`en/` 中使页面不可解析的**格式层**问题（标签闭合、属性、注释配对等）以**补丁**形式登记于 `baseline/en-patches.json`（机读，结构 `{slug, file, find, replace, expect, category, source}`），由转换层在生成派生物时应用：命中计数必须等于 `expect`（不符即该件转换硬失败，防上游漂移静默失配，零信任同 022 marker 引擎）。**文字层修正一律不进补丁池**。当前池 3 条（均为缺空格类格式修正），随回退战役建立。`yuanwen/` 等英文 markdown **与 HTML 文字保持一致**（忠实转换，上游错字照录，文字层不设任何补丁）。
3. **全局勘误表（人读册）**：`specs/001-sep-sync-pipeline/results/en-errata.md` 升格为**全局勘误表**，作为上游缺陷（文字＋格式）的唯一人读登记处（路径不变以免断引 `tools/en_source_audit.py`、`specs/001/contracts/cli.md`、`rules/04`、ADR-0038/0045/0050/0052 的既有引用；不另建第二表，避免双事实源）。新条目列：`slug｜位置｜上游原文｜缺陷定性｜参考读法｜中文承载｜凭证`；格式层条目另记补丁池 id。历史各节保留，标注“2026-11-16 全面回退，仅存档”。
4. **译注承载**：文字层缺陷凡对读者可见或影响引用可追溯者（引文、年份、人名、书目条目、文献归属），在中文译文对应位置插入译注——`（译注：上游原文作“…”，系…之误，译文按…处理。）`；中文正文按正确读法呈现（译文不复制错字）。**纯排版空隙类**（`pp.` 后缺空格、多余空格、换行）只入表＋入补丁池，不强求译注。
5. **全面回退（逐件分类后覆盖）**：对与钉不一致的每一件，先比对本地↔上游并**把差异分类**——格式层入补丁池、文字层入全局勘误表（2026-11-16 补录见该表 §九）——然后**直接用上游 HTML 覆盖本地**（字节级），逐件校验 sha256 等于 `upstream_sha256`；覆盖后 `unregister`→tombstone（历史保留在 `baseline/divergences.json` 的 tombstones、全局勘误表与 git 历史）；`yuanwen` **忠实重转**（只经格式补丁，文字层不回填）、`baseline` 随转（`source_sha256` 复原为钉）。回退可回溯：全部改正内容已在全局勘误表、补丁池与 git 历史。
6. **s0 审计出口转向**：typo 候选定性后——入全局勘误表（§8 列式）＋按第 4 条决定译注＋（可机械表达者）入补丁池；**不再改 `en/`**。机检告警口径不变（告警不拦，ADR-0038 决策 2 的“机检不作裁判”继续有效）。
7. **中文侧不回退**：已完成的中文成品（含照录区按旧口径同步过正确读法的行）保持正确读法，不回退为错字；与 `yuanwen` 的差异由译注与全局勘误表解释。未完成件在 s3/r 链中按本裁定处置。
8. **门禁**：`check_all` 的 divergence verify 语义不变（en/ 与钉不一致且未登记即红）；en/ 绝对冻结后该账只用于**上游真变（carry）**与审计面，常态全绿。补丁池健康检查：每次重转即全量校验命中计数，另由 `tools/check_en_patches.py` 提供离线校验（上游漂移→补丁失配即报）。

## 后果

* **正面**：`en/` 恢复“上游字节事实”语义，零信任核对可对钉直接比对；单一事实源收敛（缺陷知识集中在全局勘误表，机器修正在补丁池，改动的读者可见面集中在中文译注）；en 改动的五步链与跨会话冲突面基本消失；派生物（yuanwen／未来 markdown 导出）只经格式补丁，文字层忠实于上游、改正读法集中在中文成品的译注。
* **代价**：①补丁池须与全局勘误表逐条贯通（人读/机读双账，新增登记成本）；②历史改正需一次性回退：112 件已逐件分类（格式 3 入池、文字 109 入表 §一至九）并以上游字节覆盖，`yuanwen` 忠实重转后其文字回到上游原始形（中文成品不受影响，改正读法保留并由译注解释）；③译注写作成为新的工量（读者可见缺陷的译注按全局勘误表“中文承载”列逐件补齐）。
* **取代链**：ADR-0038 决策 1 的“就地改正”授权**作废**（决策 2 的登记语义改为全局勘误表＋补丁池；决策 3–13 的转换器修正继续有效——它们改的是 `tools/yuanwen.py` 而非 `en/`；决策 10 的全量重转继续有效）。ADR-0045 的登记/verify 机制保留，但只适用于**上游真变（carry）**与审计面；文字改正不再登记为 divergence（回退后无 divergence）。
* **保留**：ADR-0027 的原始钉语义、ADR-0045 的 verify 门禁与 tombstone 机制、ADR-0052 的 s0 前置顺序。
