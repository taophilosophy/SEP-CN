# 0003. 垃圾清理机制（原始物不入库、门禁与清理器）

状态：accepted | 日期：2026-10-27

## 背景

复核发现三类垃圾/产物问题：① `en/` 目录失去忽略保护，28 个原始抓取物（含 `en/_catalog/` 下 8 份带时间戳的 contents.html 快照，每次同步新增一份，共 2.1MB）被演示期 `git add -A` 扫入版本库——与宪法 II / FR-014"原始物仅存本地"冲突；② 本地堆积 VitePress 依赖缓存（2.7MB）与 `__pycache__`；③ 无任何机制阻止构建产物再次入库（`git add -A` 习惯 + 忽略规则缺口）。

## 决策

1. **原始物不入库**：`.gitignore` 恢复 `/en/`；`git rm --cached` 全部 28 个已跟踪原始物（磁盘副本保留）。版本事实源不变：`baseline/entries.json`（SHA-256 版本钉）+ `.github/sep-baseline/official-snapshot.json`（刻意入库的比对基线）+ `baseline/catalog.json`（最新目录解析）。本地 `en/_catalog/` 快照仅保留最新一份，过期 7 份删除（可由 fetch_catalog 重新抓取）。
2. **入库门禁**：新增 `tools/check_junk.py`，push 时随 `checks.yml` 运行——扫描 git 跟踪清单，命中垃圾/产物模式（字节码、日志、临时/备份文件、系统杂物、node_modules、VitePress/Astro 构建产物、`en/` 原始物、sep-sync 运行时报告）即红灯。
3. **本地清理器**：新增 `tools/clean.py`（默认试运行，`--go` 执行）——只删未跟踪杂物，绝不触碰跟踪文件；跳过 `.git`、`node_modules`（可重建但删除需重装，不属垃圾）、`en/`（原始物受保护）、`script/`（个人草稿区自理）、`.specify/`、`.zcode/`。
4. **受控例外**：`PROGRESS.md` 与 `baseline/` 为"生成但受控入库"——生成物不等于垃圾，判据是：是否为审计索引/受版本钉管理、是否手改、增长是否有界。
5. 草稿区自理：`script/` 中各会话的完结一次性脚本由归属会话自行清理（本次已清理治理会话的全部完结脚本，保留 `script/tmp/`——任务凭证引用的证据文件）。

## 后果

* 克隆不再携带原始 HTML（省 2.1MB 且不再增长）；一切成品仍可经版本钉回溯，原始物可随时重新抓取复算。
* `git add -A` 不再可能把原始物/缓存扫入提交；命中门禁的文件需人工 `git rm --cached` 并补忽略规则（check_junk 输出已给出行数与类别）。
* 对 specs/002 实现的约束：正文比对不得以 `en/` 为库内数据源（不入库），登记者以 `yuanwen/` 镜像与 baseline 哈希为准。
* 待跟进：`.github/scripts/`（周检脚本）仍为未跟踪状态，CI 上的周检会因缺文件失败——归同步会话补提交。
