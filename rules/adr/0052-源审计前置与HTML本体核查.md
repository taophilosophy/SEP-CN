# 0052. 源审计前置：s0_source_checked 与 HTML 本体核查

accepted | 2026-11-15

## 背景

s2.5 审计已译（ADR-0040/0043）的三轴中，**镜像轴（yuanwen↔en 转换保真）与资产核验的源侧部分**排在三校之前——即译文已经译完、甚至已经三校之后，才回头核对"翻译依据的源本身是否可信"。这造成两代实测教训：

1. **源缺陷发现即返工放大**：specs/018 的转换器 12 类系统缺陷、ADR-0038 的 en 源头勘误（18 处/16 文件）与转换器九修（引称匹配、em 星号连缀、图注重复、h5 丢失等，影响面数百词条），全部是在译文产出后被审计/偿还环节倒查出来的。缺陷每后置一步，偿还成本就乘一次校次与条数。
2. **零信任的缺口**：宪法 I 要求成品可回溯到英文源版本钉（pubinfo、存档版名、SHA-256），但版本钉只保证"抓的是哪一版"，不保证"这一版本身格式与内容无恙"。typo（SEP 网页排印/OCR 手误）、死链、图片缺件、公式定界符、表格结构、交叉引用锚点、注释配对、段落结构——这些 HTML 本体的正确性问题，现状在 P0 入库只有 `fetch_audit` 闭包与 `en_integrity` 完整性检查，**内容正确性核查没有强制位置**。

用户 2026-11-15 裁定：把 s2.5 的源侧核查前置到零信任前置阶段（draft 之前），且必须**首先核查 HTML 本身的格式与内容正确性**（typo、死链、图片、公式、表格、交叉引用、注释、段落等）；已经译出与正在翻译的词条也必须补做一遍。

## 决策

1. **新增前置状态 `s0_source_checked`（步名 `s0`）**：retranslate 序列置于 `cleared` 与 `drafted` 之间；update 序列置于 `pending` 与 `s1_checked` 之间（update 仅变更段，证据 `changes:` 开头）。禁止跳步语义不变：`draft` 现要求 `s0_source_checked`，update 的 `s1` 现要求 `s0_source_checked`。
2. **s0 两项依次**（HTML 在前——镜像轴以 HTML 勘误与重转后的 yuanwen 为对象，顺序不可反）：
   * **HTML 本体核查**（`en/<slug>/index.html` 为 canon）：格式（页面真实性、截断、结构）＋内容（typo 嫌疑、死链、图片、公式、表格、交叉引用锚点、注释配对、段落）。机检 `tools/en_integrity.py`（既有，包完整性）＋新工具 `tools/en_source_audit.py`（内容审计）。发现按 ADR-0038 口径处置：四类"已核实"缺陷就地勘误（先入 en-errata.md 再入分歧账、重转 yuanwen）；**死链只登记不改正文**（外链失效属上游时效，不属四类）；typo 候选由人按 ADR-0038 四类定性，机检只产候选不作裁判。
   * **镜像轴保真**（yuanwen↔en，specs/018 协议逐段人审，书目逐条计数比对）：自 s2.5 移入本环节。机检辅助挂 specs/018 `regression_scan.py`。
3. **s2.5 收缩为两轴**：译文轴（译文↔en 零信任回核）＋全局对账（节集合、脚注键位、书目条数、密度统计、语体审阅、译文侧资产核验）。镜像轴不在 s2.5 重复（ADR-0040 的"三轴依次比较"自本 ADR 起为"两轴＋源侧已前移"）。
4. **机检门禁挂钩**：`advance --step s0` 自动挂 `en_integrity`＋`en_source_audit`（硬错误拦；告警留 evidence 逐条定性）。死链活体检查（外网 HEAD/GET）默认**离线只盘点**，`--net` 显式开启（礼貌抓取 ≥5 秒间隔＋退避＋URL 级缓存），不进 advance 自动链。
5. **在途与 done 存量补课**（specs/036 承接）：
   * **在途**（drafted…r3_reviewed）：用新子命令 `task_ops.py source-audit <slug>` 追加 s0 补课记录（steps append-only，状态不迁移）；发现缺陷按 ADR-0040 三层落位（yuanwen 轴修转换器＋重转＋回归扫描、en 轴走 ADR-0038、译文轴证据链修复）。**s3 及以后状态推进时机检要求任务历史中已有 s0 记录**——正在翻译的件在进三校前必须补完。
   * **done 存量**：不改状态机（specs/023 补课先例），由 specs/036 按字头 A–Z 批量补做，台账为凭证；镜像轴已有可追溯证据（specs/018/023/028 审计）者复用，缺者补做；HTML 本体核查全量补做（本 ADR 前无任何条目做过）。
   * 勘误引发的存量影响按 ADR-0038 后果条款偿还（中文成品以重转后 yuanwen 为对照基准）。
6. **revert-state 语义不变**（仍仅 `--to s2.5_checked`）；回退件重走 s3 前其历史中已有 s0 记录者满足第 5 条门禁，无者先补。
7. `rules/09` P 表增 P0.5 行（源审计 s0，角色 R2/R4）；`tasks/README.md`、`contracts/cli.md`、`progress.py` 状态枚举同步。

## 后果

**正面**

* 翻译依据在动笔前经过格式与内容双重核验，零信任从"版本钉"升级为"版本钉＋源本体可信"；源缺陷在 cost 最低的时点暴露。
* s2.5 卸下镜像轴后作业面收窄，与 s0 不再重复跑同一批比对。
* typo／死链／锚点类缺陷从"译文侧悬案"归位为"源侧登记"，责任归属清晰。

**负面 / 需跟进**

* 新增一道前置工序，单条工期增加（HTML 审计＋镜像轴逐段人审前移）；对在途与 done 存量是一次全量补课（specs/036 待批启动，未启动期间不作为在途件阻塞——s3 门禁例外：进三校前必须补）。
* typo 机检无词典依赖（stdlib 启发式），只产候选，漏报好于误报；裁判始终是人＋ADR-0038 四类。
* 死链活体检查受礼貌抓取约束，全库活检只能批量分摊；离线盘点先行，`--net` 按需。
