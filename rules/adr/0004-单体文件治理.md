# 0004. 单体文件治理（叙事类文档超限按文件夹拆分）

状态：accepted | 日期：2026-10-27

## 背景

用户裁定（2026-10-27）：规则等叙事类单体文件过大时，按文件夹重新分类；SEP 词条本体除外。摸底结果：`rules/`（最大 63 行）与 `specs/`（最大 197 行）普遍健康；唯一超限单体是根级 `jian-yi-shu.md`（736 行 / 139KB，其中脚本生成的"附录 A"名单约占一半体量）。另一类大文件是数据登记册（`SUMMARY.md` 370KB、`mu-lu-s.md` 228KB），它们是工具按单文件解析的单一事实源，天然线性增长，不适用本政策（见决策 3 豁免）。

## 决策

1. **阈值**：叙事/规则/规格/指南类 markdown 单文件超过 **1000 行或 100KB**（102400 字节）任一，即必须按文件夹拆分。门禁 `tools/check_doc_size.py`（本地预检 + `checks.yml`）。
2. **拆分模式**：`X.md` → `X/` 文件夹：`index.md` 承接原标题与主体叙事，子文件按节/附录归类、拼音命名（与 `qian-yan/` 一致）；用 `git mv` 保留历史；SUMMARY 收录状态不变（原本不在 SUMMARY 的工作文档继续不入，避免触动结构源）。
3. **豁免**（超限不直接拆，须走 spec 修改解析器后另行裁定）：单一事实源登记册 `SUMMARY.md`、`mu-lu-s.md`、`yi-zhe-shuo-ming.md`，工具生成物 `PROGRESS.md`，发布词汇表派生视图 `qian-yan/ci-hui-biao.md`。扫描范围：根级 `*.md`、`rules/`、`specs/`、`qian-yan/`、`guan-yu/`、`fang-fa-lun/`、`jian-yi-shu/`、`.specify/`；词条本体（a–z 与集群目录、`en/`、`yuanwen/`）按用户裁定不在管辖内。
4. **本次执行**：`jian-yi-shu.md` 拆为 `jian-yi-shu/index.md`（正文一~十，614 行 / 67KB）+ `jian-yi-shu/fu-lu-a.md`（附录 A 名单，125 行 / 72KB，文件头保留脚本生成数据源注记）；拆分后受管文件全部达标。附录名单若日后重新生成超限，按字母分区拆为 `fu-lu-a/` 子目录。

## 后果

* 正面：AI 会话与审阅者按需载入单节；建议书正文与数据名单各自可维护；门禁防止单体复发。
* `rules/05-ci-and-tools.md`（checks.yml 行、工具表、快速命令）已同步补记 `check_doc_size.py`——补记时该文件原有的并行会话未提交改动已在 8e7f66e1 落定，无卷入。
* 审计注记：`jian-yi-shu.md → jian-yi-shu/index.md` 的重命名因共享暂存区被并行会话提交 8e7f66e1 先行卷入（纯改名、内容未变）；正文/附录的内容拆分由本 ADR 的配套提交完成，净效果与本决策一致。
* 原文正文引用的“附录 B/C”从未落盘（仅标题级提及），属既有内容缺口，与本次拆分无关，留待数据方补齐。
