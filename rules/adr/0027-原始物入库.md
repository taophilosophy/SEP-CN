# 0027. 原始物入库（取消 en/、yuanwen/ 的本地独占）

accepted | 2026-11-09

## 背景

ADR-0003 与宪法 II 原定“原始物存本地 `en/`，不入库”，理由是体积与可再生。2026-11-09 双机拆分（ADR-0026）后，这条代价变得不可接受：

* **两机各持一份本地相**，靠 robocopy 对齐——今天实测 1.05 GB / 27 s 才同步一次，且每次 M2 抓取新词条，M1 就开始漂移。
* **缺 `en/` 的克隆跑不全门禁**：`check_all --all` 第 9 项“英文镜像深度复核”与 `check_academic` 的注号核对都依赖它。
* **CI 与任何新克隆都没有原始物**，复核能力只有那两台机器有。
* 原始物“不可变”过去只靠约定（`tools/clean.py` 保护 + 不修改的纪律），没有版本级证据。

用户 2026-11-09 裁定：“en、yuanwen 也入 git 库。其他应入 git 库的文件应入尽入。”

## 决策

1. **`en/`（原始抓取 HTML 与资产，375 MB / 5434 文件）与 `yuanwen/`（确定性转换镜像，311 MB / 4267 文件）纳入版本库**。宪法 II 相应修订（v1.2.0 → v1.3.0）。
2. **边界不变**：`.secrets/`（会话凭证）**永不入库**；`script/`（个人草稿区，rules/06 第 6 条）、`state/`（运行态）、`node_modules/`、各类缓存与构建产物仍忽略。“应入尽入”以规则既有边界为准，不外溢。
3. **不可变语义改由 git 承担**：已入库的原始物只追加、不改写；任何修改都会进历史、可审计。这比原先的口头约定更强。
4. **抓取产物随批提交**：`fetch` / `convert` 阶段收口时把 `en/`、`yuanwen/` 的增量一并 `git add` 提交；不再出现“本机有、别人没有”的原始物。
5. **门禁同步调整**：
   * `tools/check_junk.py` 删除 `^en/` 规则（否则入库即被判垃圾）。
   * `tools/clean.py` 的 `SKIP_DIRS` 增补 `yuanwen`。
   * `tools/check_images.py` 不再“CI 无镜像则跳过”——镜像入库后 CI 实核 `yuanwen/` 引用（现存 2 条悬空引用不阻断，退出码仍 0）。
   * `tools/README.md`、`rules/01`、`rules/05`、`AGENTS.md` 的“不入库”表述全部改写。

## 后果

**正面**

* 单一证据基：M1、M2、CI、任何新克隆拿到完全相同的原始物，零信任复核不再受“本机有没有抓过”影响。
* `check_all --all` 可在 CI 全量跑，不再需要“本地才有 en/”的降级分支。
* 原始物可追溯性由 git 历史担保，`baseline/` 的哈希清单与仓库内的实际文件可互相验证。

**负面 / 需跟进**

* 仓库体积：新增 686 MB 原始字节，`.git` pack 预计从 137 MB 增至 ~400–500 MB；每次 clone 与 CI checkout 变慢（15 个工作流均受影响）。
* **CI 优化待办**：对不需要原始物的工作流加 `actions/checkout` 的 `sparse-checkout`（排除 `en/`、`yuanwen/`），或按需拆分工作流触发路径。
* 抓取会持续污染工作树：每次 `fetch_entry` 都会产生未提交文件，必须按批提交，否则 `git status` 恒脏。
* GitHub 私有库存储上升；单文件最大 3.4 MB，远低于 100 MB 红线，无需 LFS。

## 迁移（另一台机器必读）

M2 本地已有未跟踪的同名目录，`git pull` 会以“untracked working tree files would be overwritten”中止。**不要删本地副本**（M2 可能有更新的抓取），按以下顺序：

```bat
cd D:\SEP-CN
ren en en.m2
ren yuanwen yuanwen.m2
git pull
robocopy en.m2 en /E /MT:16
robocopy yuanwen.m2 yuanwen /E /MT:16
git add en yuanwen
git status
git commit -m "原始物并入版本库：M2 侧较新抓取补齐"
git push
rd /s /q en.m2
rd /s /q yuanwen.m2
```

`robocopy /E` 用本机版本覆盖同名文件，`git status` 里剩下的差异就是 M2 独有的新抓取——一次提交即收敛。
