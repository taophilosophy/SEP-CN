# 0073. 采纳“判据与执行机制同视图”原则（B0/B1 求值视图事故回流）

accepted | 2026-11-18（权威＝用户指令“先解决问题，不计成本代价，再总结经验教训到软件工程理论”）

## 背景

2026-11-18 B0/B1 全量审计中，B0 判据（HTML 模板一致性）直接读 `en/` 原始字节，而生产链 `yuanwen.convert_entry` 先 `apply_en_patches` 再解析。判据在补丁前求值，把补丁已热修的格式缺陷误报为失败。用户连问“虚拟补丁和勘误表呢”“为何之前没发现”，暴露该类失效的静默性：规格未声明求值视图，实现/审计/定性全链一致继承，且补丁池（缺空格类）与 B0（不判空格）无交集，修复前后检测输出无差异，长期未被发现。

## 决策

1. **采纳 doctrine 10 号“判据与执行机制同视图原则”为工程约束**（`rules/reference/engineering-doctrine/10-judgment-execution-same-view.md`），四条律：
   - **同视图律**：判据求值视图须与其断言对象的消费者输入视图同源。
   - **交集律**：检测器对修复机制须有非空可观测交集（至少一个“修复前判红、修复后转绿”样本）。
   - **溯源律**：报告“通过”须附“为何通过”（边界样本 + 排除恒真）；未触边界只记“未失败”。
   - **约束化律**：影响正确性的系统事实须落到结构性必填项，而非仅存记忆。
2. **落 rules/05“判定权与规则所有权”节**：新增“求值视图声明与同源对照”条（ADR-0073），判官上线前强制视图声明 + 同源对照 + 交集验证 + 边界触发。
3. **本次事故的即时修复**（不计成本）：
   - `check_yuanwen_fidelity.html_text` 加 `apply_patches` 参数（默认不变，B1·I3 传 True 走补丁后）。
   - `verify_b0b1.b0_ok` 改在**转换输入视图**（en ⊕ patches）求值，与 `convert_entry` 同源。
   - 扫描器失败件三态对账 `en-errata.md`（已知勘误／新发现）。
   - 交集验证脚本 `state/verify_patch_view.py`（补丁件前后 B0 对比）留档为固定锚点。

## 凭证

- **交集验证实证**：3 个补丁件 HTML 已改（补丁生效），B0 前后皆通过——补丁缺空格类与 B0 不判空格的空交集被直接证实（`state/verify_patch_view.py`）。
- **全量 B0+B1 终跑（1,872 词条，求值视图＝补丁后）**：双过 1,816；B0 失败 9（全部已知勘误，新发现 0）；B1 失败 47（已知勘误 3，其余 44 全部命中 specs/039 转换器缺陷账，交集 47、双向差集空 → 实际新发现 0）；asym 判据不适用 320。产物 `specs/044/results/b0b1-scan-all.json`。
- **附带修复的覆盖率 bug**：`check_yuanwen_fidelity.iter_entries` 只枚举 `a-z` 单字母目录，漏掉数字目录 `yuanwen/1/`，致数字开头词条（18thGerman-preKant）B1 报 “no yuanwen md” 而非求值。修后该件 B0+B1 双通过，fidelity 门禁无破坏。这是同一族“审计覆盖面”缺陷的第二例。
- 负向证伪仍通过；fidelity 默认行为不变（`--gate` 抽样 issues 0）。

## 取代链

不取代任何既有 ADR；扩 ADR-0063“判官只读”为“判官只读 + 判官同视图”（同一族纪律：判定器的正当性既要求不能改对象，也要求在正确的层判对象）。
