# 0034. 主代理单干（禁止调用子代理）

accepted | 2026-11-10

## 背景

2026-11-10 用户裁定：主代理禁止调用子代理，一切工作由主会话亲自完成。此前已有同类裁定（2026-11-02：不用子代理直译，实测轻量模型深工率约 35%、需重试约 5%），本次由“翻译不外包”升级为全库通则。

理由在宪法 I（零信任）与 II（可追溯）：子代理的提示词与主会话上下文脱节，其写入不经过主会话的核对链，产物无法归到一条可追溯的会话记录上；主会话也难以在收工时逐条复核自己没亲眼看过的改动。写入路径只有一条时，责任与证据才闭合。

## 决策

1. `AGENTS.md`“硬约束速览”新增一条“主代理单干”：禁止主代理调用子代理（`Agent`／`Task` 及 workflow 的子代理扇出）；翻译、校对、检索、核对、工具编写与批量改写一律由主会话亲自完成。
2. 唯一例外：用户在本轮提示词中显式批准派发子代理，并写明范围与任务边界；无此批准不得调用。
3. 需要并行推进时，改为串行执行，或由用户另开独立会话（多会话间仍只经 `origin/main` 同步，见 ADR-0026/0028）；另开会话不属本 ADR 所指的子代理。
4. 本规则适用于全部会话与全部工种，不因批次大小、任务机械程度而放宽。

## 后果

* 正面：写入路径唯一，核对链完整；不存在“子代理改过而主会话未察觉”的文件。
* 负面：长任务耗时上升，缺少子代理扇出带来的加速；跨文件大批量检索只能串行。
* 跟进：`rules/06-governance.md` §多会话协作与该条相容（并行会话＝人开的独立会话）；既有文档中 workflow 扇出的历史做法不追溯重写，但不得作为先例援引。
