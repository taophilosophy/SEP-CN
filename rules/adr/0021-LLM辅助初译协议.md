# 0021. LLM 辅助初译协议（段落账本、反思式两步强制与守恒校验）

accepted | 2026-10-31

## 背景（任务方向声明）

用户指令（2026-10-31）：「复核后批准合入流程和软件工程理论，立刻落地。反思必须强制」——批准将沉浸式翻译插件（Immersive Translate）专业翻译流程研究的合理部分合入 `rules/`（流程层）与 `rules/reference/engineering-doctrine/`（软件工程理论层），立即执行；其中反思式两步翻译裁定为**强制**。

一句话复述：为 LLM 辅助初译（[rules/04](../04-translation-workflow.md) draft 步骤，ADR-0020 已引入 MTPE 验收顺序）立操作性协议，使 AI 参与的初译获得与批量改写同级的机械可判定防线。目标＝协议入库、规则衔接、理论沉淀；非目标＝不实现新检查器（长度守恒 QA 脚本另行裁定）、不改六道状态机、不动既有体例与学术门禁。验收判据＝五处落点入库、`check_all` 全绿、决策可回溯。

研究证据（明细与来源见 `specs/005-translation-campaign/results/immersive-translate-study-2026-10-31.md`）：沉浸式翻译官方文档（prompts／advanced／usage／webpage 四页）实测其流程——段落级批处理（约 25 段/次、1800 字符/次、限流与超时显式参数）、id-YAML 按段回写、标题与必需术语注入提示词、五条防幻觉铁律（仅输出译文／段落数与格式完全一致／标签位置保持／专有名词保留／无额外文本）、token 比例守恒质检、反思式两步（step1 初译＋step2 优化双版留档）。与本项目既有资产同构：id 账本 ≈ `rules/05` 批量改写纪律（逐行身份追踪、残余≠0 禁止写回）；「先忠实后流畅」两步 ≈ `rules/04` ADR-0020 MTPE 验收顺序；标记守恒 ≈ 009 归一性深读实锤的 em 粘连、星号未转义、超额包裹三类缺陷的防线。

## 决策

1. `rules/04-translation-workflow.md` 增「LLM 辅助初译协议」一节（强制，适用于 draft 采用 LLM 辅助时）：段落账本、反思式两步强制、标记守恒、术语与上下文注入、批参数显式化、质检不可绕过。
2. `specs/005-translation-campaign/fan-yi-mu-ban.md` 增 §6 操作规程（模板升 v1.2）：账本文件格式（`tasks/<首字母>/<slug>.ledger.yaml`）、提示词骨架、守恒校验清单、交接方式。
3. `tasks/README.md` 存储约定补账本文件一类（`.json` 寻址的工具不受影响）。
4. `rules/reference/engineering-doctrine/` 新增 `08-machine-translation.md`（可移植方法论：对账协议、守恒校验族、双版留档、注入边界、批参数显式化），README 目录表与 NOTICE 变更记录同步。
5. 研究存档入 `specs/005-translation-campaign/results/immersive-translate-study-2026-10-31.md`（证据，不具约束力）。

## 后果

* 正面：AI 参与的初译获得机械可判定防线（段落数、id 身份、标记计数守恒）；润色引入的缺陷可回溯（step1 对照底）；术语注入与登记册单一事实源衔接，而非第三方黑盒提取。
* 成本：每段双版产出，初译工时与 token 成本上升（用户裁定接受强制）；账本文件随任务入库，增加存储与提交量。
* 不采纳（与宪法冲突，记录以防回潮）：即译即用无审校链（流程先行）；第三方黑盒摘要/术语提取直接当事实源（零信任、可回溯）；质检设开关绕过（门禁豁免必须逐条留痕）；降级服务链（无对应需求）。
* 待用户裁定（2026-10-31 未决）：①长度守恒 QA 脚本是否立项（新工具走 spec 流程，机检前为人工判读标旗）；②双语站逐段对照审校视图排期。
