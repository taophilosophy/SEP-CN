# 0024. 标题同步改本地门禁与 CI 只读校验

状态：accepted | 日期：2026-11-07

## 背景

2026-11-07 用户指令：「解决 ci 与 summary 与实际词条名造成的不同步问题，允许 git push -f，但是禁止用 GitHub 的覆盖本地」。

现场三处证据：

* **远端分叉**：本地 `main` 领先 2 个提交（`ef40e670`、`0f970ecc`），远端领先 1 个本地没有的提交 `a05e8968`「chore: sync headers with SUMMARY.md」——由 `sync-headers.yml` 在 push 后按 SUMMARY 改写 11 个词条 H1 并直推 main 产生。
* **标题漂移 11 条**：全库 SUMMARY 条目文字与词条 H1 不一致恰好 11 条（albert-great、arabic-islamic-mysticism、gelukpa、kant-reason、kant-hume-morality、kierkegaard、knowledge-analysis、knowledge-value、korean-philosophy、korean-buddhism、kumaarila），均系 GitBook 时代导入的旧 H1 残迹（`f04c27b3` GITBOOK-9 等）；此前本地无任何门禁校验标题，漂移只能等 CI 在远端改写才暴露。
* **机制性问题非首次**：同一工作流此前已留下自动化提交（`391dabec` 2026-10-31「chore: sync headers with SUMMARY.md」、`d5d3ccd2`「修复标题同步与预期不符」）。

根因是**写入权错位**：main 有两个写入方（本地会话与 CI），而 CI 的写入发生在 push 之后，必然与本地后续提交分叉。单会话尚可 `pull --rebase` 收编；多会话并行时收编即「远端内容覆盖本地未推送内容」，正是用户明令禁止的方向。

## 决策

1. **CI 不再写回 main**：`sync-headers.yml` 改为只读校验（`python tools/check_summary.py --headers`），不一致即红灯；删除原 sed 改写 + `git commit` + `git push` 步骤。main 的唯一写入方是本地会话。
2. **本地门禁与 CI 同器实拦**：H1 一致性并入 `tools/check_summary.py`——默认全量审计含该项且计硬错误（`check_all.py` 与 `checks.yml` 直接咬住）；新增 `--headers`（只查标题，CI 用）与 `--sync-headers`（按 SUMMARY 同步 H1，写回后跑残差门）。
3. **本次 11 条收口方向（用户裁定：H1 为准）**：`SUMMARY.md` 与 `mu-lu-s.md` 的 8 条正式条目文字、2 条别名词条英文片段回写为词条 H1 文字（索引式改显示式，保留作者括注）；9 个词条 H1 补齐作者括注、gelukpa 还原 `\[ \]` 转义。收口后残差 0。
4. **push -f 仅本次授权**：本次以本地历史覆盖远端（丢弃 `a05e8968`），改写前打双 tag 留退路——`backup/2026-11-07-标题同步收口`（改写后的本地历史）与 `backup/2026-11-07-远端分叉提交`（指向被丢弃的 `a05e8968`，供随时取回比对）；`rules/06` 的「推送先 pull --rebase、force push 属授权期专属」不变，不把本次授权升格为常规政策。
5. **解析口径**：标题提取必须贪婪到最后一个 `](`（`^\s*\* \[(.*)\]\(([^)]*)\)\s*$`），不得复用结构审计的 `\[([^]]*)\]`——后者遇转义方括号即截断。

## 后果

* 远端不再自造提交，分叉源消失；CI 红点直接给出「SUMMARY 与 H1 不一致」的问题清单，而不是悄悄改写。
* 改标题变成两步：改 `SUMMARY.md` → `python tools/check_summary.py --sync-headers`；不做第二步，本地 `check_all` 即红。
* **开发期事故留痕**：首版 `--sync-headers` 误用截断式解析，把 31 个词条 H1 写成半截标题（`彼得·阿伯拉尔 Abelard [Abailard\` 等）；已按 HEAD 逐文件回退（该 31 个文件当时均无他人未提交正文改动，其中 10 个有正文），并把「贪婪解析 + 写回残差门」固化为 `tools/tests/test_check_summary_headers.py` 四项单测。
* 规则落点：`rules/01`（SUMMARY 规则、页内标题层级）、`rules/05`（工作流表、工具表）、`rules/README.md`（快速判例）、`specs/001/contracts/cli.md`（H1 同步职责）、`specs/009/spec.md`（条目文字口径）。
* **别名行英文已收口（同日执行）**：用户批准「左侧英文 := 目标词条完整标题」并要求必须用完整标题；改写 101 处（含同一别名行重复收录 1 组），截断片段（`in biology`、`and informed consent`、`logic of`…）与索引倒装残段（`clinical research, ethics of`…）一律换成 baseline `title`，`— see` 之后仍为 SEP 索引名。逐行报告 `specs/009-normalization-review/results/alias-title-fix-2026-11-07.tsv`（101 行，残差 0）；`check_summary.py` 增设 `alias fragment` 硬门禁与两项单测防复发。
