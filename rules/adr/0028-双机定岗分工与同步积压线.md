# 0028. 双机定岗分工与同步积压线（修订 0026 并发条款）

accepted | 2026-11-10（2026-11-16：裁定②「积压线」由 [ADR-0059](0059-提交即推自动推送.md) 部分取代，改为提交即推）

## 背景

2026-11-10 同步事故：原始物入库（ADR-0027）这类批量工程在两机并行开展、无认领互斥；M1 侧积压 4 个大提交未推送，pull --rebase 判弃快照（d39ad790a）后共 4 个提交孤儿化。用户裁定弃置本地、以 GitHub 远程强制覆盖 M1 克隆。内容经 M2 侧 d0294236f 恢复入库，无成果丢失，但暴露协议两处缺口：批量工程无单写入者约束；rebase 判弃无自检实拦。

另实测澄清拓扑：M1（DESKTOP-RLOEIG9）侧的 `D:` 是映射网络盘（`\\Desktop-m5p610n\d`，即 M2 物理磁盘）；两机 git 用户名同为 ykla。

## 决策（用户 2026-11-10 裁定）

1. **分工定岗**（取代“批量工程认领互斥”设想）：M1 只负责**词条翻译**（含随附的术语/人名登记、任务与账本操作）；其余一切——原始物、抓取管线、术语跑批、全库审阅、规则/ADR/工具维护、上游 intake、更新流程——归 M2。同工种单机化即互斥，双机不再并行同类工程；协作唯一通道仍是 `origin/main`。
2. **积压线**（2026-11-16 起由 [ADR-0059](0059-提交即推自动推送.md) 部分取代：改为「提交即推」，本条的「途中 ≤1」与「收工清零」作废，收工核对 `git log origin/main..main` 为空保留）：翻译 push 三检查点（认领／advance／done 收口，0026）不变；另加硬线——作业途中未推送提交 ≤1，**收工时必须清零**（`git log origin/main..main` 为空）。例外：M2 关机致代理不可用时允许积压跨夜，恢复联网后第一件事清零。
3. **判弃自检实拦**：`tools/sync_guard.py pull` 包装 `pull --rebase`——拉前记录 `origin/main..HEAD` 清单并以 `git cherry` 标注 patch-identical（`-`）；rebase 后逐条核对，`-` 件被弃放行并提示，`+` 件被弃判为事故（退出码 2，给 reflog 恢复指引），rebase 冲突停台退出码 3。`status` 子命令显示积压数，服务收工清零。开工命令一律改用本工具。
4. **孤儿件处置协议**：发现本地提交不在远程历史，先 `git cherry` 判内容是否已在远程；已在→本地弃置（本次裁定合法化）；不在→reflog 恢复后推送。处置记入对应 spec execution-log，禁止静默。
5. **工作面归属**：M1 会话工作区 = `C:\Users\ykla\Documents\SEP-CN`；M1 侧 `D:` 映射只作只读观测，不写。M2 会话工作区 = `D:\SEP-CN`。M1 会话遇管线/规则/工具问题记录上报，不自行修复（除非用户当场指示）。

## 后果

**正面**

* 批量工程单机化，本类事故（双机同类批量 + 长积压 + 判弃）结构上不再可能。
* 积压线把分叉面压到单提交级，rebase 风险与冲突面最小化。
* 判弃自检由工具实拦，不再依赖事后人肉发现；孤儿处置有既定通道，不再临场裁决。

**负面 / 需跟进**

* M1 翻译会话遇到管线/规则/工具缺陷只能上报，修复等待 M2 侧（或用户指示）。
* 收工清零要求把 done 前的中间态（账本、任务 JSON）也以提交推送，微提交略增。
* M2 关机时 M1 无法 push/pull（代理单点，0026 原条款沿用），收工清零此时豁免。
