# 0045. 原始物双账语义与分歧账（原始网页钉冻结＋en 就地勘误登记＋漂移判定改口径）

accepted | 2026-11-15（用户裁定“保存原始网页 sha 和本地的 sha，仅当上游变化时才变化本地，比较差异，决定是否逆向补丁”）

## 背景

ADR-0027 定“原始物只追加、不改写”，ADR-0038 开“en 四类勘误可就地改”破例并要求逐条登记。破例开口后出现两类失控：

1. **sha 比较失去判别力**。至 2026-11-15，en/ 共 22 文件 23 路径被批准勘误就地改动（015 偿还“en 同改”、egoism 缩写同步、简讯提交排印修正等），而 `baseline/entries.json` 的 `files[].sha256` 无人更新、也无机制区分“批准的本地偏离”与“上游真变”。`compare.py` 的快速“无变更”判定取 `yuanwen.source_sha256`（ADR-0038 全量重转后已按**改后**文件重算）、深层 diff 基准取本地 `en/<slug>/index.html`——两条路都被勘误污染：上游没变也报变更，勘误伪装成上游漂移，正是用户指出的“修改后 sha 发生明显变化，无法作为比较”。
2. **登记要求未工具化**。ADR-0038 的登记（en-errata.md）是纯人读册，无门禁拦截“静默改字”；且 ADR-0038 决策 2“`source_sha256` 由重转时按当前文件重算”一句若施于 `files[].sha256` 会抹掉上游锚点——本 ADR 明确其只适于 yuanwen 的 md/源哈希，不适于原始钉。

## 决策

1. **双账语义**：`baseline/entries.json` 的 `files[].sha256` 定名**原始网页钉**——永远只记抓取时刻的上游字节（本地 HTML 来源即 `https://plato.stanford.edu/entries/<slug>/` live 页原样字节，版次以 `archive_edition` 钉），**批准勘误与重转不得改写**。本地偏离逐条登记 `baseline/divergences.json`（schema `sep-cn-divergences/1`）：`{slug, path, upstream_sha256, local_sha256, bytes, commit, subject, base_commit, reason, registered_at}`；`base_commit` 指向 git 历史中原始字节所在提交（存量 23 件全部锚定 d0294236f“原始物入库”），原始字节**不另存副本**，按需 `git show` 取回。人读勘误册 `specs/001-sep-sync-pipeline/results/en-errata.md`（ADR-0038）继续记载原串＋改正＋依据，与机器账互为表里。
2. **verify 门禁**（check_all 第 10 项）：`tools/divergence.py verify` 核三账一致——en/ 文件 sha ≠ 原始钉而未登记 → 红灯（堵静默改原文）；已登记而钉被改写、本地又被动、重复登记、路径不在台账 → 同样红灯。`--deep` 加核 `base_commit` 的 git blob sha256 == 原始钉（需完整历史，浅克隆失败如实报告，仅本地跑）。
3. **漂移判定改口径**：`compare.py` 快速判定与比较基准一律用**原始网页钉**——本地件与钉一致直接用；有批准分歧经分歧账 `base_commit` 回溯 git 原始字节再比。本地勘误不再可能伪装成上游变更。
4. **fetch_entry 行为**（“仅当上游变化时才变化本地”）：上游与原始钉一致 → 不写盘、不动台账，报告 `unchanged`；上游已变而该词条有未搬运分歧 → 拒抓，待搬运；上游已变且无分歧 → 写入新上游并前移钉（此即原始物的正常更新）。
5. **逆向补丁搬运**（上游真变时）：`divergence.py patch <path>` 输出 原始字节→本地 的 unified diff；与上游新旧 diff 对照裁定——分歧 hunk 与上游改动不相交可随迁，相交转人工；搬运完成后更新或注销账目再重抓。自动随迁工具列为跟进项，暂按此手工流程执行。
6. **存量登记**：2026-11-15 建账即登记 23 件（21 件 015 偿还期勘误 + auriol + moral-responsibility-empirical，均为 ADR-0038 四类内），verify 与 --deep 全绿；bohr-correspondence 两处漏登补入 en-errata.md（§四）。
7. **礼貌抓取一次性豁免**：本轮建账零网络请求；若批“1872 词条全量回源核对 sha”回填任务，允许绕过 5 秒间隔（用户 2026-11-15 裁定），登记于 specs/001 spec.md Assumptions，不作 rules/05 常态修订。

## 后果

**正面**

* 漂移判定恢复判别力：上游 sha 比较有了不被本地污染的锚点；“我们故意改的”与“上游变了”重新可区分。
* 静默改原文从纪律升为门禁：任何 en/ 改动不登记即红灯，ADR-0038 的登记要求有了机器执行者。
* 原始字节零冗余：git 历史（d0294236f 起）即原始仓库，账目只记哈希与锚点。

**负面 / 需跟进**

* 浅克隆（CI 默认 depth=1）下 `--deep` 不可核，CI 只跑核心 verify（sha 三账一致不需要历史）。
* 台账 4499 条文件记录去重后 4386 唯一路径（40 个跨词条共用资产路径），verify 按唯一路径计；读数时注意口径。
* 并行会话覆写事故（34945130b）曾把 moral-responsibility-empirical 的 en 勘误还原又重应用，过程中 pin 始终未被改写——双账语义经受住了这次冲击，但也暴露：sweep 式提交会把在途工具代码卷入他人提交（本轮工具链即被“！”提交收编），登记册（en-errata.md）与实物（en/）可能短暂脱节，verify 会如实报警。
* 逆向补丁自动随迁未实现（跟进项）；分歧账与 en-errata.md 的行级对应暂靠 reason 字段文字关联。
