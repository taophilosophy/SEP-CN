# 0072. 最佳建议立项：B0 全库遍历 + 两道他证 + 不进行全量翻译边界

accepted | 2026-11-18（权威＝用户指令“批准建议但不进行全量翻译”）

## 背景

基于 `开源翻译.md` 调研与本项目现状（s0 覆盖 20/1872、核心段完成 394），用户批准了最优路径建议，并附加边界“不进行全量翻译”。本 ADR 固化立项决策、优先级、否决项与边界。

## 决策

1. **P0 B0 全库遍历（审计，立即执行）**：对全部 1,872 词条跑 B0 十谓词（`specs/044/bin/verify_b0b1.py` 的 `b0_ok`），产出疏漏清单。**只读审计**：不写 en/、不改 yuanwen/、不动 baseline、不产译文、不改勘误表。工具 `specs/044/bin/b0_scan_all.py`，产物 `specs/044/results/b0-scan-all.json`。逐件定性（文字层→勘误表 / 格式层→补丁池）是审计的下一步，属登记动作、非翻译，单独一批执行（须先确认 `en-errata.md` 无并行会话持有）。
2. **P1 结构反向核验（立项）**：补 I2 自证盲区（md 渲染回结构 ↔ HTML 结构比对），堵“两边都错”。机检性质，可全量。方案另立 specs（承接 ADR-0070 建议⑤）。
3. **P2 独立模型族辅助判官（立项）**：s3/r3 引入与翻译模型不同族的 LLM，按 MQM 产出错误清单供人审（GEMBA-MQM v2 思路）。两条硬边界：①不替代人审（ADR-0070）；②评估模型与翻译模型不同族（自偏好偏差）。**LLM 处理仅限测试词条（1–5），不全库跑**。
4. **P3 增强项（立项）**：术语自动提取回填（s2.4）、reverse-check 回译核验（R 链）、实时术语提示（P4 之外轻量通道）。测试词条验证。
5. **否决**：①引入多智能体重工作流（TACTIC/Translation OS 全套）——本项目 r1–r3 已是多审阅者，alphaXiv 实证智能体成本 5x–15x token 且质量不必然更好；②引入第三方 MT 引擎作初译——本项目 LLM 直译优于离线 NMT，是退化。

## 边界（不进行全量翻译）

- 本 ADR 立项与审计均**不启动对全部词条的翻译**。
- 审计类（B0 遍历、结构反向核验）可全量——它们只读、只判格式，不产译文。
- LLM 处理类（P2 独立判官、P3 术语提取/回译）仅限测试词条（1–5）。
- 真正的全量翻译由后续独立批准启动，不在本 ADR 范围内。

## 取代链

不取代任何既有 ADR；P0 是 specs/044 方案与 specs/036 存量补课的正式化；P1/P2 承接 ADR-0070 的立项项（建议⑤③）；P2 的 MQM 清单与 ADR-0071 的 ISO 5060/MQM 采纳（S01/S03）互证。

## 落点

- `specs/044-b0b1-baseline/bin/b0_scan_all.py`：B0 全库遍历工具。
- `specs/044-b0b1-baseline/results/b0-scan-all.json`：遍历结果（机读）。
- P1/P2/P3 方案：另立 specs（P1 承接 specs/044，P2/P3 新 specs）。
