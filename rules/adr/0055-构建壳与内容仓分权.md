# 0055. 构建壳与内容仓分权：依赖只装壳根，主题层与配置层解耦

accepted | 2026-11-15

## 背景

`taophilosophy.github.io` 是 GitHub Pages 的构建壳：根上有 `package.json` 与两条 Pages 工作流（`push_deploy.yml`、`sync_deploy.yml`），`docs/` 以子模块指向本仓（`taophilosophy/SEP-CN`）。实际状态是两边各有一套互不相干的声明：

* 壳的 `package.json` 仍是一套旧站点依赖（`vitepress 1.6.4` + `vite-plugin-vitepress-auto-nav` + `markdown-it-mathjax3-tao` 等），与本仓 `.vitepress/config.mts` 需要的 `vitepress 2.0.0-alpha.21` + `vitepress-plugin-pagefind` + `mathjax 4.1.3` + 字体包完全不匹配，`vitepress build docs` 无法成立；
* 本仓根同时持有 `package.json` / `bun.lock`，依赖、脚本、`node_modules` 都长在内容仓里；
* `.vitepress/prepare-assets.mjs` 以 `process.cwd()` 拼 `node_modules/mathjax`，依赖一旦 hoist 到壳根即找不到；
* 站点构建只做了一半的迁移：`public/`、`.vitepress/` 已在内容仓，依赖声明却在内容仓与壳之间双重存在。

用户 2026-11-15 裁定：按 `FreeBSD-Ask/FreeBSD-Ask` 的结构办——内容仓只留 `.vitepress/`、`public/` 与内容，**依赖与构建脚本全部在壳根**；主题与配置分层解耦。

## 决策

1. **壳是唯一构建入口与唯一依赖声明处**。壳的 `package.json` 只列本站真正用到的依赖（`vitepress 2.0.0-alpha.21`、`vitepress-plugin-pagefind`、`pagefind`、`mathjax 4.1.3`、两款 `lxgw-wenkai` 字体、`littlefoot`、`rollup`），脚本以 `docs` 为 VitePress root；保留 `docs:dev` / `docs:build` / `docs:preview` 别名，既有工作流不改调用方式。旧的 auto-nav / footnote / mathjax3 / task-checkbox 依赖删除（本站不用）。
2. **内容仓不持有包管理文件**。本仓根不再有 `package.json` / `bun.lock`，`.gitignore` 显式排除；`tools/check_junk.py` 的 `ROOT_ALLOW` 对 `package.json`、`bun.lock` 保留为历史豁免，并新增 `node_modules`（本地预览时可为指向壳的目录联接），二者本地误跑包管理或挂依赖不判垃圾，但不得入库。
3. **`public/` 与 `.vitepress/` 留在内容仓**（含 `config.mts`、`math-plugin.mjs`、`prepare-*.mjs`、`theme/`）。壳不复制、不改写这些文件。
4. **主题层与配置层解耦**为契约：
   * 配置层（`config.mts`、`math-plugin.mjs`）只管站点结构——元数据、`srcExclude`、SUMMARY 解析、双语配对、侧栏、markdown 规则、`transformPageData`；不 import 主题层、不写视觉样式。
   * 主题层（`.vitepress/theme/`）只管呈现——字体、样式、槽位组件；不 import 配置层、不读 `config.mts` 内部变量，只消费 frontmatter 与 `useData()`。
   * 两者只经 VitePress 约定接口交互。删掉 `theme/` 仍可构建（退回默认主题）；删掉 `config.mts` 站不成立——不对称是有意的。
5. **构建前置脚本与 cwd 解耦**：`prepare-assets.mjs` 按 Node 解析顺序自 `.vitepress/` 逐级向上找 `node_modules/mathjax`，产物固定写回本仓 `public/mathjax/`；`prepare-gitstamps.mjs` 一仍其旧（自身路径推导，写本仓 `.vitepress/git-stamps.json`）。两脚本由壳脚本按序调用。
6. **CI 的 `cp docs/README.md docs/index.md` 保留**：VitePress 把 `README.md` 编成 `README.html`，Pages 站点根需要 `index.html`；该文件只在 CI 生成、不入库。dev 端的 `index.md → README.md` 中间件继续保留。
7. **锁文件不入库，构建不用缓存**（用户 2026-11-16 裁定）：壳仓 `.gitignore` 排除 `*.lock` / `bun.lock`，`package.json` 的版本声明是唯一版本约束；壳与内容仓的 CI 一律不用依赖缓存，每次 `bun install` 现装。`render-artifact-audit.yml` 只从壳取 `package.json`，不取锁文件、不带 `--frozen-lockfile`。

## 后果

* **正面**：一套依赖、一个构建入口（锁文件不入库、构建不用缓存）；内容仓根目录回到“内容 + 阅读站实现”两件事，依赖升级不再需要动内容仓；`vitepress build docs` 与本地 `bun run dev` 走同一条路径，杜绝“本地 2.0-alpha、CI 1.6.4”的静默错版。
* **代价**：内容仓单独 clone 无法构建与预览——必须有壳（或用目录联接把 `docs/` 指到工作树）。这是刻意的：构建不是写作的前置。
* **已知限制**：子模块浅克隆时 `git log` 只有一条提交，页脚“最后更新于”统一显示子模块提交时间。
* **规则面**：`rules/05-ci-and-tools.md` 站点运行一节改为壳入口命令；`rules/01-repository-structure.md` 根白名单中包管理文件条目注明为历史豁免；`.vitepress/README.md` 增“构建壳与分层”一节（说明而非规则）。

## 落点

* 壳仓：`package.json`（依赖 + 脚本）；锁文件 `.gitignore` 排除、不入库，`node_modules/` 本地现装。
* 本仓：删除 `package.json`、`bun.lock`；`.gitignore` 增加排除；`.vitepress/prepare-assets.mjs` 改为逐级解析；`.vitepress/README.md` 重写命令与构建期准备两节并新增分层表。
