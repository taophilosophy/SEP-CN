# 0086. 标准条款锚点补遗与项目规格机检

状态：accepted　日期：2026-11-25（用户“继续任务补遗”，承接 specs/061 清单）

## 背景

`specs/061-standards-realignment-2026/spec.md` 的 P0 与 D1–D5 已落地（ADR-0083／0084），但补遗清单仍有七项悬空：G4 项目规格只写进 `rules/04` 的文字、无机器校验；G6 ISO 5060 的评分卡／抽样／评估者能力无落点；G9 CY/T 123-2015 条款未锚定；G11 转写系统只有一句“逐版待核”；G14 CY/T 154-2017 其余条款未映射；G15 索引标准列在 `cited` 易误导；G16 F2575／J2450 版本陈旧。`rules/04` 已 30,651 字节（上限 30,720），不能再承载条款表。

## 决策

1. **新建 `rules/10-standards-clauses.md`**（ADR-0004 分文件先例）：集中承载 CY/T 123 条款锚点、CY/T 154 条款映射与机检子集（仅 8.1／8.2／5.8.2／5.12.2 四类进机检，其余明标人工）、转写系统表、ISO 5060 评分卡与抽样、不采纳／不适用、TBX 导出字段映射。条款原文取自 nppa.gov.cn 行业标准全文（检索日 2026-11-25）。
2. **项目规格机检（G4）**：`tools/task_ops.py` 建账时写入 `project_spec` 六项（`audience`／`purpose`／`register`／`terminology_basis`／`delivery`／`qa_level`，ISO 11669:2024），默认值即本项目规格；`tr-02` 前进前 `_project_spec_gate` 校验六项非空，缺项即拒。CLI 增 `--spec-audience` 等六参覆盖；未知字段或空覆盖即 `UsageError`。
3. **转写系统（G11）**：按 iso.org 页面逐版核（2026-11-25）——ISO 9:1995＋Amd 1:2024（90.92，FDIS 在研）、ISO 233-2:1993／233-3:2023（233:1984 为 90.92、FDIS 233-1 在研）、ISO 259:1984（90.93）、ISO 843:1997（90.93）、ISO 3602:1989（90.93）、ISO 7098:2015（90.93）、ISO 15919:2001（第 2 版 DIS 已通过转 FDIS，40.99）、ISO 24229:2022、ISO 15924:2022。该表只用于**识别**来源页转写系统与登记代码，ADR-0030 的映射表禁令不变。
4. **登记册校正（G15／G16）**：ISO 999:1996 与 GB/T 22466-2023 由 `cited` 改列 `not_adopted`（网页词条无索引对象；CY/T 123 5.11.4 允许以译名对照表替代，本库由 `shu-yu-biao`／`ren-ming-biao` 承担）；ASTM F2575 校正为 F2575-25（2025-11-15 发布、代替 23e2）、SAE J2450 校正为 J2450_201608；ISO 30042:2019 补“第 3 版 CD 已通过转 DIS（30.99）”，GB/T 44227-2024 补“MOD 采用”。
5. **ISO 5060 落地（G6）**：评分卡七维与严重度分档入规则章；抽样＝机检全量＋人工按 H2 分层（每层≥1 段、总量≥10% 且≥20 段、`sha256(slug+段序号)` 定序可复算、命中 Critical 转全量）；评估者须登记资质并与 D1=C 终审分离挂钩。
6. **TBX 导出（G8）**：只导 TBX Core（DCT），依据 GB/T 44227-2024（MOD ISO 30042:2019）；字段映射入 §10.6，生成器 `tools/term_tbx.py`，产物禁手改。

## 后果

* 正面：补遗七项全部有落点与判定方式；`rules/04` 不再膨胀；项目规格从“人工核”变“机检＋可覆盖”；条款引用可带号复核。
* 代价：`rules/` 增一章；任务 JSON 增 6 字段；新增两个生成器／校验器的维护面。
* 回退：`git revert` 本批；`rules/10` 可独立删除而其余门禁不受影响（`check_all` 不依赖它）。
