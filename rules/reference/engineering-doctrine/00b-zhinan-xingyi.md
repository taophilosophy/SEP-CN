# 00b 知难行易：任务方向先于手段

本文件是 `00-philosophy.md` 的补充方法论，也是 `rules/08-intent-first.md` 的理论底稿。

**命名与性质**：“知难行易”为**项目侧提炼**，不是 00a 源文档原文；命名溯及孙中山《孙文学说》仅作注记，不构成论证依据。本文档自身仍是形式主义：若不能改变决策、产物或门禁，应按 `00-philosophy.md` §9 删除或降级。

## 1. 核心命题

工程任务里，**知是最难的一步**：弄清楚用户到底要什么、要解决什么真实矛盾、做到什么算完成、什么不做、代价由谁承担。方向一旦确定，**行相对容易**：工具、框架、流程、实现路径都是可替换的手段。手段是次要的——它服务于目标，不能反过来定义目标。

一句话：**先把问题想对，再把事情做快；方向错了，执行力只是放大损失。**

## 3. 知与行的分层

| 层 | 内容 | 判定问题 | 可变性 |
| --- | --- | --- | --- |
| 知（方向层） | 用户意图、真实矛盾、目标、非目标、验收判据、边界、代价承担者 | 用户到底要什么？做到什么算完成？ | 不弄清不动手 |
| 行（手段层） | 工具、框架、流程、脚本、实现路径、提交与门禁 | 为什么是它？替代方案是什么？何时替换？ | 可替换，随目标与约束变化 |

判据：**换手段不需要重开方向讨论；改方向必须重评手段。**

## 4. 四条命题

1. **方向错误放大损失**：执行力越强，错误方向造成的返工、破坏与信任损失越大；先慢后快优于先快后返工。
2. **手段可替换**：工具、框架、流程都是当前和解，不是目标；“业界都这样”“工具支持所以做”不构成理由。
3. **知是行的前提，不是行的替代**：知与行是闭环——方向明确后立即执行最小可验证步骤，用结果修正理解；以“还没想清楚”为由长期停滞同样是失败。
4. **形式主义手段表演**：用工具使用、流程走完、文档篇幅证明“做了”，却没有改变任何决策、产物或用户结果——应删除或降级（`00-philosophy.md` §9、本目录 README §6）。

## 5. 开工四问

1. **谁要什么**：用一句话复述用户意图，不含手段，也不含自己偏好的方案。
2. **为什么现在**：要解决什么真实矛盾？不做会怎样？谁在痛？
3. **什么算完成**：可执行的二值验收判据与失败路径。
4. **什么不做、谁承担代价**：非目标、约束、负面后果与承担者。

四问答不清时：先问用户，不猜；确需临时推进，标 `[假设]` 并把验证放在第一步。

## 6. 六类反模式

| 反模式 | 表现 | 后果 | 纠正 |
| --- | --- | --- | --- |
| 先动手后理解 | 直接改代码、建目录、跑脚本，再补理由 | 返工，误改他人工作 | 先写方向声明 |
| 手段替代目标 | 以“用了某工具、走完某流程”当完成证据 | 流程表演，真实问题未解 | 以验收判据与证据验收 |
| 猜测式实现 | 需求含糊时自行补全 | 做对了一个没人要的东西 | 先问不猜，假设显式 |
| 过度工程 | 为想象中的未来需求提前设计 | 复杂度与维护成本 | 只做当前验收所需 |
| 问题重述失真 | 把用户的话改写成自己熟悉的问题 | 答非所问 | 复述并请用户确认 |
| 分析瘫痪 | 以“还没想清楚”为由不动手 | 交付停滞 | 可逆决策以最小步骤快行 |

## 7. 方向声明卡

```text
用户原话：
意图复述：（不含手段与方案）
真实矛盾 / 谁在痛：
目标：
非目标：
验收判据：（二值、可执行）
约束与代价承担者：
手段候选：（为何选此、替代方案、替换条件）
失效条件与复审触发：
```

极简任务可压成一句话：**“用户要 X，做到 Y 算完成，不做 Z；选 W 是因为……”。** 卡不是文书负担；写不出这句话，说明还没到动手的时候。
