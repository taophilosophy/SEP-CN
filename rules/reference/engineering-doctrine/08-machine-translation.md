# 08. 机器翻译辅助工程（MTPE 协议）

机器与 LLM 参与翻译初稿时的工程纪律。案例来源：SEP-CN 项目对沉浸式翻译（Immersive
Translate）插件流程的研究与落地（其 ADR-0021 回流本目录）。本文件是方法论：只陈述
可移植的原则与判据，不绑定具体模型、服务或语言对。

## 1. 原则

1. **机器产出按批量改写对待**：凡机器文本写回正文，适用对账协议（逐项身份追踪、
   残余≠0 禁止写回、幂等重跑、改写前基线还原）；机器不是免检通道。
2. **翻译单位是段落，不是句子**：句级切分破坏上下文，是机翻腔的第一成因。
   批处理按段落合并请求以降成本，但必须按段对账。
3. **先忠实后流畅，两版留档**：初译（忠实）与优化（流畅）分步产出且双版保留；
   验收顺序先查幻觉/漏译/增译，再查术语，最后语言（MTPE 惯例）。双版留档使
   "润色引入的缺陷"可归因、可回溯。
4. **守恒校验族**：结构化产物在转换前后必须通过机械可判定的守恒检查——单位
   数量、逐项身份、标记/定界符计数、键名集合。守恒失败即整批拒绝写回。
5. **对账用 id 协议，慎用分隔符协议**：分隔符依赖"输入文本中不会出现该串"的
   假设，文体复杂的输入必然打破（业界做法是选罕见分隔符降低概率，但仍靠概率
   而非确定性）；给每个单位稳定 id 并要求按 id 回写，校验从字符串匹配升级为
   身份匹配。
6. **注入本地可控**：提示词可注入术语表、标题、节标题等上下文以提高质量，但
   注入物必须来自本地可控的登记源（单一事实源），并标注强制性（"必需术语；
   无译名者保留原文"）；机器自提取的术语只是候选，审定登记后方可使用。
7. **质检不可绕过**：守恒校验不设配置开关；豁免逐条留痕。"跳过校验"的配置项
   是流程债。
8. **批参数显式化**：批尺寸、限流、超时、温度是工程参数，登记入证据，不许
   隐式默认。

## 2. 判据（机器初稿何时可信）

| 信号 | 判据 |
| --- | --- |
| 守恒 | 全部守恒校验通过（数量、身份、标记、键名） |
| 双版一致性 | step1/step2 语义差仅限语言层面（抽样判读） |
| 术语命中 | 登记术语全部按注入译名落地 |
| 长度比例 | 译文/原文比例在常态带内；越带即人工判读漏译/增译/串段 |
| 幻觉抽检 | 专名、数字、年代、引注逐项核对（最高风险位） |

## 3. 反模式

* 分隔符协议遇到含分隔符的输入（概率性防线必然失效）；
* 机器译文直接成稿、无人工验收链；
* 用第三方黑盒摘要/术语提取结果直接当事实源；
* 只留优化稿不留初译稿（润色缺陷无法归因）；
* 复检只读优化稿（等于复检被审对象自己写的自述）；
* 质检可配置关闭（风险被静默转移给下游）。
