# 10. 判据与执行机制同视图原则（SEP-CN 回流）

来源：SEP-CN 项目 2026-11-18 B0/B1 全量审计事故的归纳回流，触发于用户连续追问
“虚拟补丁和勘误表呢”“为何之前没发现”。案例引用本项目 ADR-0062（两路处置）、
specs/044（B0/B1 基线）、`state/verify_patch_view.py`（交集验证留档）。本文件是方法论：
只陈述可移植的原则与判据，不绑定具体项目、语言对或工具。与 `09-rework-lessons.md` 的
关系：09 讲返工的成因与防线，本文件讲一类**静默型**失效——判据本身错在求值层，
却因全链自洽与数据巧合而长期不被发现。

## 1. 失效类型：判据在错误的视图上求值

### 1.1 定义

同一份输入在系统内往往有多个视图：原始字节、预处理后、规范化后、补丁后、译后。
**判据的语义决定它必须在哪个视图上求值**；若判据取错的视图，其输出就是一个
在语法上完全正确、在语义上完全错位的布尔值。

B0（HTML 模板一致性）的语义是“**转换输入**能否被解析器正确消费”。而补丁池的职责正是
把上游格式缺陷热修成可解析输入。检测端在补丁前、修复端在补丁后——两者不在同一视图上，
检测对象既不是修复前的缺陷，也不是修复后的产物，而是“本该被修好却被当没修”的幻影。

### 1.2 判据

> **同视图律**：任何判据，其求值视图必须与它所断言对象的**消费者输入视图**同源。

对每个判据问三句：

1. 它断言的对象，在系统里被谁消费？（转换器 / 发布器 / 人）
2. 那个消费者拿到的是哪个视图？（原始 / 补丁后 / 规范化后）
3. 判据读的是不是同一个视图？若不是，即为错位。

## 2. 为何这类失效长期不被发现

### 2.1 全链自洽掩盖层间错位

当规格、实现、审计、定性四步一致地在同一错误视图上工作时，链内没有任何矛盾信号。
每一环都“忠实实现”了上一环，而错误在链的最上游（规格未声明求值视图）。错得一致
比错得离散更危险：离散错误至少产生接口冲突，一致错误只产生自洽假象。

> **自洽律的反面**：内部自洽不是正确性的证据，只是错误一致性的可能结果。判据系统
> 至少需要一个**外部锚点**（与生产链的实际输入对照），否则无法自我发现层间错位。

### 2.2 信号源与检测器的空交集

若缺陷修复机制（如补丁池）修的恰好是检测器不判的维度，检测器对这类修复**永远盲**：
修复前不报错、修复后也不报错，差异为零。本例实证：补丁池 3 条全是“缺空格”类，
而 B0 十谓词不判空格——补丁件在 B0 下前后皆通过，交集验证直接显示“HTML 已改，
B0 失败=无→无”。缺失被“检测器根本不看这里”完美隐藏。

> **交集律**：检测器对修复机制必须存在**非空可观测交集**——至少构造一个“修复前被
> 检测器判红、修复后转绿”的样本，否则该检测器对该修复类形同虚设。

### 2.3 “通过”被误读为“设计正确”

机检全绿有两种可能：判据正确且对象合格；或判据与对象不匹配导致恒真。两者在输出上
无法区分。若不追“它为何绿”，就会把**侥幸正确**当成**设计正确**计入交付。

> **溯源律**：报告“通过”必须附带“为何通过”——触发了哪个边界样本、排除了哪种恒真
> 可能。未做过边界触发的“通过”，只能记为“未失败”，不能记为“正确”。

### 2.4 审计账未 join 全部已知账

“新发现”的定义不是“本次扫描第一次出现”，而是“与**所有**已知缺陷账核对后仍无归属”。
若审计只 join 一部分已知账（如只 join 上游勘误表、不 join 转换器缺陷定性账），会把
已定性问题重新报成“新发现”，制造伪工作量与伪缺口判断。

> **对账律**：审计产出的每个“失败”，必须 join 全部已知账（上游缺陷／转换器缺陷／
> 合法移位白名单／待考项）；无归属者才是新发现。

判例：B1 全量 47 失败，初判 44 为“新发现”；join `specs/039` 转换器缺陷账后，
47 全部命中既有候选（交集 47、双向差集为空），“新发现”实为 0。审计口径若只挂
勘误表，就会得出“44 个新问题”的错误结论。

## 3. 知识形态：事实必须提升为约束

“补丁在解析前应用”是一条**事实**；它在某次实现中被复述、被引用，却未在写判定器的
决策点上被激活——因为事实与约束是两种知识形态。事实回答“系统如何工作”，约束回答
“我在这一步必须做什么”。前者可存储，后者才可触发。

> **约束化律**：凡影响正确性的系统事实，必须落实到某个**结构性必填项**（字段、断言、
> 检查器），而非仅存于文档或记忆。约束的判据：删掉它，某处会报错。

本项目的落地：判定器新增“求值视图”必填字段，未声明即不合格；判据上线前强制
“与生产链输入同源”对照写入 docstring。

## 4. 最小防线（可移植清单）

1. **视图声明**：每个判据在规格中显式声明求值视图（原始/预处理后/补丁后/译后）。
2. **同源对照**：判据上线前，核对其输入是否与其断言对象的消费者输入同源。
3. **交集验证**：对每个修复机制，构造“修复前判红、修复后转绿”的最小样本。
4. **边界触发**：报告“通过”前，必须触发过至少一个应失败的边界样本。
5. **约束化**：把系统事实写进结构性必填项，而非仅存记忆；删掉该项应导致报错。

## 5. 与既有理论的关系

* 本原则是 `09-rework-lessons.md` 五类返工成因中“**判据/验收维度缺陷**”在**静默层**
  的展开：09 关注“事后被发现并返工”，本文关注“因自洽与空交集而永不被发现”。
* 与 `00b-zhinan-xingyi.md` 的“先知后行”互补：知难行易强调动笔前明确方向与判据；
  本文补充一条——**判据自身也有“视图方向”，判据写对了但视图取错了，等于方向错**。
* 与项目侧 ADR-0070“机检为筛、人审为判”一致：机检不仅可能漏检、误报，还可能在
  错误的层上求值；这是“机检必要不充分”的第三种失效形态。

## 6. 判例（可移植化）

**事故**：一个 HTML 模板一致性判据（B0）直接读上游原始字节；而系统的转换器先对原始
字节打格式补丁、再解析。判据在补丁前求值，把补丁已修好的缺陷报为“失败”，把本该
由补丁消除的问题重复计入缺陷账。

**为何长期未现**：①规格未声明视图，实现、审计、定性全链一致继承；②补丁池恰好只含
检测器不判的维度（缺空格 vs 不判空格），修复前/后检测输出无差异，交集为零；
③“全量 0 问题”被读作“设计正确”，未追“为何绿”。

**修正**：判据改在补丁后求值；源流统一走补丁后；规格补“求值视图”必填字段；
新增交集验证脚本（补丁件前后对比）；把“同视图/交集/溯源”三条写成结构性检查。

**教训一句话**：**错得一致，比错得离散更难发现；检测器必须与它要保护的修复机制
在同一层上睁开眼。**
