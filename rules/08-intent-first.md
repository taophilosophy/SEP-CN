# 任务意图与方向先行（知难行易）

本规则落实宪法第 VII 条（知难行易：先明方向，后择手段），适用于**全部会话与全部任务类型**——翻译、校对、结构改动、术语登记、管线工具、站点、规则修订、发布。理论底稿见 `reference/engineering-doctrine/00b-zhinan-xingyi.md`；本文件是约束性条文，冲突时以本文件为准。

## 1. 开工前方向声明

任何任务在动笔、动代码、跑批之前，先用一句话复述**用户到底要什么**（意图，不含手段与自己偏好的方案），并写清：

| 字段 | 要求 |
| ---- | ---- |
| 意图复述 | 用户原话加一句话转述；不得替换成自己熟悉的问题 |
| 目标 / 非目标 | 要达成什么；明确不做什么 |
| 验收判据 | 可执行的二值判据（命令加期望输出、检查器、交付物形态） |
| 作废条件 | 枚举何种发现会使本任务/批次产物作废（语言、语体、保真、基准、证据、结构等维度），并声明各维度的验收层（机检层／语义留痕层）；“检查器全绿”不得替代未设验收层的维度（ADR-0039） |
| 约束与代价 | 边界条件、由谁承担负面后果 |
| 适用规范基线 | 任务触及的已登记标准条款（`rules/README.md`“规范性引用标准”节）与筛查结论；未登记域先按 §13 检索再动手；判“无适用”也须留筛查结论（ADR-0042） |

落点：文档任务写入任务 JSON 的 `evidence`（首条）；工程改动写入 `specs/<NNN>-*/spec.md` 或 ADR 的“背景/决策”节；极简任务可在回复中一句话完成。写不出这句话，视为尚未立项。

## 2. 需求不明：先问不猜

* 指令存在两种以上合理解释、缺少验收判据、或与既有规则冲突时，先向用户确认（提问并给候选方案与影响），不得自行假设后直接实施。
* 确需临时推进时，假设必须显式标 `[假设]`，并把验证该假设作为第一步；假设被推翻即停手重定向。
* 禁止把“业界惯例”“工具默认”“上一个任务这么做”当作需求来源。

## 3. 手段后置且可替换

* 工具、框架、流程、脚本是实现变量，不是目标；选择手段须说明为何此手段服务于该目标、替代方案是什么、何时替换。
* 禁止以“已运行某工具”“已走完某流程”“文档已写”作为完成证据；完成证据只能是验收判据的通过结果与可复核凭证。
* 工具或流程与实际目标冲突时，改手段，不改目标；确需改目标，回到第 1 条重新声明。

## 4. 以验收判据验收

* 完成等于验收判据全部通过加证据可复核；不以提交数、文档长度、工时、在线状态衡量。
* 收工自检：本次工作改变了哪个决策、产物或门禁？答不出，视为形式主义，删除或降级（doctrine §9）。

## 5. 可逆快行，不可逆先知后行

* 可逆决策（草稿、试验分支、临时脚本、可回退的小改动）允许快速试错，试错结果必须留痕。
* 不可逆决策（结构重排、批量改写、数据格式、协议、权限、对外发布、破坏性动作）必须先方向声明并写清代价，再按 [06](06-governance.md) 的前置条件执行。

## 6. 知与行的闭环

方向声明不是拖延许可证。明确方向后立即执行**最小可验证步骤**，用结果修正理解；禁止以“还没想清楚”为由长期停滞，也禁止以“先做起来再说”绕过方向确认。

## 7. 判例

| 场景 | 错误做法 | 按本条做法 |
| ---- | ---- | ---- |
| 用户说“优化一下” | 直接改代码或改结构 | 先问：优化哪个指标、现状值、目标值、如何验证 |
| 用户说“新增某理论并全局落实” | 直接新建文件、只改一处规则 | 先确认理论主题、来源、落地层级（reference、rules、宪法）与验收形态 |
| 翻译任务起步 | 先跑脚本、先建目录 | 先确认词条范围（含补充材料）、六道验收与学术挂钩，再创建任务 |
| 用户指令与既有规则冲突 | 默默按自己理解执行 | 指出冲突，给两种方案与影响，请用户裁定 |
| 新规则、新手段或新领域开工 | 凭记忆与惯例直接写、直接做 | 先按第 13 条筛查→吃透→落地；条文引条款号，偏离登记在案 |

## 9. 批量批次立卡与基准钉（ADR-0039）

* 长线批次（波次/战役）开工须**立卡**：方向声明（含第 1 条全部字段）落入 `specs/<NNN>-*/spec.md` 或任务 JSON `evidence`，不得只存在于会话上下文。
* 批量产线开工前**钉对照基准**（源 commit／版本／转换器版本）入卡；基准变更（重转、上游勘误、口径修订）必须先评估存量回归面并登记偿还战役，未评估不得继续铺量。

## 10. 手段试金石（ADR-0039）

* 大规模采用新手段（新脚本、新替换策略、新工具链、新写回流程）前，先**小样本试金石**（≥3 件）＋回源定性＋与目标对齐的论证留痕（为何此手段、替代方案、替换条件）；样本不过即停。
* 语义类改写禁机械手段（呼应 [02](02-style.md) 破折号条款、ADR-0033）；返工归因登记见 [specs/004 §五](../specs/004-engineering-doctrine/spec.md)。

## 11. 自报完成独立复算（ADR-0039）

* 凡“已重译／已修复／已收口”类自报主张，验收以**独立复算**为准（逐处定位比对、diff、守恒检查）；主张本身不作证据，不以“流程走完”代验收。

## 12. 返工归因登记（ADR-0039）

* 返工按五类成因归因：R1 验收维度缺口、R2 手段先行、R3 基准漂移、R4 写入路径脱核、R5 证据推演（理论：doctrine 09）。
* 按四元组登记：规模／作废维度／被跳过条款／新防线，入 specs/004 登记表；**同一成因二次发案，防线必须升级**（约定→门禁→硬门禁）。

## 13. 开工前标准文献启发式研读（ADR-0042）

本条是知难行易的重要体现：知不止于用户意图（第 1 条），还包括**规范基线**——干活前必须启发式阅读有关 ISO、IEEE、国标、官方文档、规范、建议等标准化文献，必须吃透并落地。理论底稿见 doctrine 00b §6。三步：

| 步 | 约束性要求 |
| ---- | ---- |
| 筛查 | 先查 rules/README“规范性引用标准”节：命中即引条款号，不重读全集；未登记域按域关键词检索 ISO、IEEE、国标、官方文档、规范与建议；判“无适用”也须在方向声明留筛查结论 |
| 吃透 | 研读到条款级：能引条款号与版本钉，能判本仓库现状是超集、有意偏离还是缺口；版本钉以登记清单为准，防代替关系漂移 |
| 落地 | 研读成果落到条文引用（含条款号）、清单/模板登记、机检或验收判据至少一处；有意偏离登记 ADR 在案；官方原文与笔记凭证归档 specs bin。只读不落＝以研读当完成证据，按第 3、4 条判形式主义 |

* **启发式边界**：登记清单是研读缓存，命中已登记条款直接引用不重读；新领域、新手段、新规则起草才触发检索义务；极简任务一句话收口（“适用 GB/T 15834 §4.13，无新增偏离”）。
* 联网检索遵守 [05](05-ci-and-tools.md) 礼貌抓取。
* 判例：起草新规则 → 先查 GB/T 1.1-2020 助动词分级（rules/README 起草约定）；动参考文献 → 先查 GB/T 7714-2025 适用边界（[07](07-academic-norms.md)）；进入未登记的新工程领域 → 先检索 ISO/IEC/IEEE 对应标准再设计。
