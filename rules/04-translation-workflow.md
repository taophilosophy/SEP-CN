# 翻译与三审三校流程

本规则展开宪法第 IV 条（流程先行）与第 VI 条（体例即契约），落地 `specs/001-sep-sync-pipeline/spec.md` 的 FR-011/012/013。任务状态的机器可判定载体是 `tasks/` 下的 JSON 文档任务（协议见 `tasks/README.md`，操作用 `python tools/task_ops.py`）。

## 任务方向声明（宪法 VII）

创建任务前先写清：词条范围（主文与补充材料）、目标读者、验收判据（六道全过、`check_academic --strict` 0 硬错误、CI 全绿）与非目标（不改原文、不补内容、不造引文）。方向声明写入任务 JSON 的 `evidence` 首条；含糊先问不猜（[08](08-intent-first.md)）。

## 任务类型与状态机

| 类型 | 触发 | 状态序列 |
| ---- | ---- | -------- |
| retranslate（重译） | 全量重译战役、错误过多重处理 | pending → cleared → drafted → s1_checked → s2_checked → s3_checked → r1_reviewed → r2_reviewed → r3_reviewed → done |
| update（更新） | 上游 SEP 修订引发 | pending → s1_checked（仅变更段）→ s2_checked（变更段所在节）→ s3_checked（全文档）→ r1 → r2 → r3 → done |

**禁止跳步**。blocked 标志独立于状态，用 `advance --unblock` 解除。

## 六道的含义（经典出版映射，用户 2026-10-26 裁定）

| 步骤 | 名称 | 做什么 | 合格凭证 |
| ---- | ---- | ---- | ---- |
| draft | 初译 | 以英文源为唯一底稿从头翻译（见下节纪律） | 译文全文入库 |
| s1 | 一校（准确性） | 对照英文源逐节核销：漏译、错译、事实错误（人名、年代、编号） | 对照记录；残留外文碎片检查为 0 |
| s2 | 二校（语言） | 消除欧化句、倒装、死译，打磨口吻与流畅（含 [02](02-style.md) 反欧化条款） | 修改 diff；`tools/check_prose.py` 告警清零或逐条豁免留痕（ADR-0020） |
| s3 | 三校（体例） | 引号、空格、术语登记册一致性、格式检查 | `tools/check_style.py` 0 issue + markdownlint 绿 |
| r1 | 初审 | 对照原文自审并签字 | 自审记录 |
| r2 | 复审 | 逐句回核原文与逻辑 | 复核记录 |
| r3 | 终审 | 终稿验收 + CI 全绿 | CI 通过 + 验收签字 |

每步在任务 JSON 的 `steps` 数组登记：`actor`（执行者）、`at`（ISO 时间戳）、`evidence`（可复核凭证：哈希、diff、检查输出、对照记录位置）。

### 复核独立性与问题分级（ADR-0020）

* **MQM Core 映射**：一校对 Accuracy（误译／漏译／增译／未译）；二校对 Fluency 与 Style（语法、欧化、语域）；三校对 Terminology 与 Locale Convention（登记册一致性、标点体例）；初审至终审做 Verity 抽查与整体验收。
* **问题分级**：校次发现的问题按 Critical（改变原文立场、事实错误、术语反用）、Major（破句、漏译、成语误用）、Minor（措辞、标点）登记在 evidence；Critical 不得带入 done。
* **复核独立性**（ISO 17100：校者独立于译者且资质相当）：r1–r3 至少其一应由初译 actor 以外的会话或人工执行；单会话作业时，终审前须冷置（先做其他任务再回读），并在 evidence 记明。执行形态默认值见 [ADR-0020](adr/0020-译文语言质量门禁.md) 待裁定项。

## 重译纪律（零信任，宪法 I）

* **既有中文译文一律不作为底稿或修改依据**——杜绝错误沿袭。
* 重译前置条件：该词条已登记可信英文基线（`baseline/` 有版本钉：pubinfo 日期 + 存档版名 + SHA-256），清空动作（cleared）才能执行；全库级清空必须可由 git 历史回溯。
* 可疑处回到原始 HTML 或官方页面核对（`yuanwen/`、`en/` 为本地原始物，不入库），禁止以缓存、既有翻译或中间产物替代源验证。

## 逐句校对要求

一校、复审必须逐行逐句与英文源对照，重点类别：事实性错误（人名、公司、版本号、时间线）、漏译（句子、信息框、脚注）、机翻腔、用词不当、语法文字错误、欧化汉语与倒装。

* 对需要外部事实的查询（失效链接、版本号、史实）联网复核后再改。
* **禁止复查旧错**：已完成校次的错误不重复劳动；每轮内容必须是新的。
* 逐个修改，禁止软件工具批量替换；每次修改前后复核，确认问题真实、改动准确。
* LLM 辅助初译的验收顺序（MTPE 惯例，ADR-0020）：一校先查幻觉、漏译、增译，再查术语漂移（逐节对照登记册），最后处理语言与欧化；不要先润文笔。
* 上游更新任务（update）只对变更段落重走相应校次，其余内容不重复过校（不复查旧错原则）。

## 演示与纠偏循环

流程的可行性由实跑证明：每完成一轮真实词条演示，暴露的问题必须在流程文档（本目录、宪法、specs）中修订或明确记录“维持原设计”的理由（演示日志见 `specs/001-sep-sync-pipeline/demo-log.md`）。
