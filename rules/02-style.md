# 编写体例

译文以“像中文学术作者直接写作的论文”为标尺：用现代汉语学术书面语，准确、平实、可读；忠实原文的论证与语气，不译成文言或半文半白，也不译成欧化汉语或翻译腔。原文的讽刺、调侃与举例色彩在学术语域内保留，不拔高成官样文章。本规则的机器可判定部分由 `tools/check_style.py` 执行（宪法 VI），推送后由 CI 复核；语体与文风（是否文言、破折号是否滥用）由复核人通读后作语义判断，不设关键词命中规则。

体例修改同样是任务：先确认要修哪类问题、以 `check_style.py` 0 issue 为验收，再逐处手动修改；禁止以“跑了格式化工具”代替判断（[08](08-intent-first.md)）。

## 引号

* 正文必须使用中文弯引号：双引号 `“ ”`、单引号 `‘ ’`（外层双引号，引内层用单引号）。
* 引号必须成对、方向正确：左引号只用于开启，右引号只用于收束。
* 禁止英文直引号 `"` `'`、直角引号（U+300C、U+300D、U+300E、U+300F）、日式半角引号与全角直引号。
* 代码块与行内代码内保持原样；英文单词内部的撇号（O'Brien、don't）不算引号。
* 引号与相邻汉字之间不加空格；引号与西文、数字之间保留半角空格；引号内部的中英文之间照常加空格。
* 发现错误引号逐个手动修正，禁止机械替换。

## 空格

* 中英文、中文与数字之间必须加半角空格；**书名号内的中英混排同样加空格** （写《C 程序设计语言》，不写 `《C程序设计语言》`）。
* `**加粗**` 两侧与相邻正文恰好一个半角空格（段首、块首例外；与中文标点、全角括号紧贴；行尾、表格竖线、破折号允许紧贴或一个空格）。全角空格一律改半角。

## 代码块与终端摘录

* shell 命令与终端会话用 ` ```sh `，C 代码用 ` ```c `，配置/数据按内容选语言，无法判断时用无语言标注的 ` ``` ` 兜底，**禁止 `text` 作为语言标注**。
* 终端会话保留原书提示符：`%`（csh）、`$`（sh）、`#`（root）。
* 代码块内的英文注释必须翻译为中文；只译注释，不得改动命令、代码、变量名与格式。
* **禁止篡改** 代码块内容：软件版本号、错误信息、文件名、变量名一律原样（错误信息在正文中可译、代码块内保持英文）。
* 数学定界符与 LaTeX 内容原样保留（宪法 VI）。

## 排版元素

* 信息框统一用 `>` 引用块，关键词加粗，与正文空行分隔。
* 表格对齐以源表性质为准（2026-11-13 修订，取代原“一律居中”，[ADR-0037](adr/0037-表格与图片体例.md)）：公式盒子、数据表等源 `<table class="centered">`/`cell-center` 者居中（`:---:`）；文献条目表、长文本列与源默认 `vert-top` 者左对齐（`---`）——en 源 576 处以 `vert-top` 为默认，整段文献居中不可读。表头几列，数据行就必须几列，缺列写 `| |`；表格单元格用紧凑风格（管道内侧不留空格）。
* 学术工具节一律列表形态（全库 359 列表 / 71 旧表形态，2026-11-13 归一）：`* [如何引用本词条](…)` 起四条，不用带空表头的上引表。
* 表格文字（用户裁定 2026-11-13，[ADR-0037](adr/0037-表格与图片体例.md)）：表头与单元格的说明、描述性文字一律译中文；表内西文文献条目骨架照录＋书名括注通行汉译（查证到实书才译，查不到保持原样并登记）；中国文献条目（古今）译为中文；公式与数学记号原样保留，公式盒子表标签语（Definition. 等）译中文。门禁：`tools/check_tables_images.py` 预检＋逐表人眼复核。
* 图注形态（[ADR-0037](adr/0037-表格与图片体例.md) 决策 8）：图注行统一 `图 N：说明`（全角冒号，禁半角句点/句号作分隔）；图前标签行（无说明）统一 `图 N`，加粗者 `**图 N**`；正文句中引用不动。
* 图片（用户裁定 2026-11-13，[ADR-0037](adr/0037-表格与图片体例.md)）：alt 与图注一律译中文，SEP 源占位 alt（missing text, please inform）译说明性中文；中文词条图片引用一律 `../assets/<slug>/<文件名>`（解析到根级 `assets/`，[01](01-repository-structure.md)），禁引 `../yuanwen/assets/`；reprinted with permission 图片在图注标明来源。
* 禁止任何 HTML 语法；禁止 AsciiDoc 残留（`xref:…[…]`、`link:…[…]`、行尾 `+` 软换行）；所有段落同一行内完成。
* 命令、选项、参数用行内代码（`ls -l`）；不带选项参数的裸命令一般不加反引号。
* 正文路径与 IP 用 **加粗**，不用反引号；代码块中的路径保持原样。
* 上下标（用户裁定 2026-10-28）：有 Unicode 原生字符的直接用原生字符（`x²`、`u(a₁)`、`Sₓ`、`E⁻¹`），与英文镜像 `yuanwen/` 的转换约定一致；无原生字形的（如 `q` 下标、`⊥` 上标、含斜线的 `^{−1/2}`）保持记号 `_{…}`/`^{…}`，由站点渲染层转 HTML sub/sup 兜底；真公式一律入数学定界符 `$…$`/`$$…$$`，公式内部用 LaTeX 记法，不适用本条。
* 斜体与加粗（用户裁定 2026-10-29）：**中文强调不使用斜体 `*中文*`，使用加粗 `**中文**`**（中文排版无斜体传统，CJK 斜体渲染歪斜难读）；拉丁/希腊/希伯来字母的书名、术语与逻辑符号（如 *dharma*、*svabhāva*、*A*、*B*）保留斜体不改（斜体拉丁字母渲染正常且是中文学术出版引用外文术语的标准做法）；`**` 两侧空格遵守 bold-spacing 规则；参考文献节照录条目豁免本条。门禁：`tools/check_style.py` 规则 `italic-cjk`。
* 强调语法有效性（用户裁定 2026-10-30，ADR-0019）：**`**` 星号内侧禁空格**——`** 内容 **` 违反 CommonMark 翼规则永不渲染，页面显示裸 `**`（A 批 9 词条 237 对实测）；编号记号（ABD1、CP 等）在英文源无强调标签时保持纯文本；正文强调形式以英文源标签为准映射（源 `<em>` → 中文粗体/拉丁斜体），不得无凭据改样式。验证走渲染产物级扫描 `tools/check_render_artifacts.py`（源合法 ≠ 产物正确）。

## 内容纪律

* 禁止篡改：软件版本号、人名、书名、URL、邮箱、带圈数字必须与原文一致，位置和数量不得变动。
* 避免滥用“已”字：“XX 已新增”改为“新增 XX”。禁止机械替换。
* 避免章节交叉引用：原文“see Chapter 11”等改写为语义化描述或指向对应中文页面的相对链接。
* 第二人称一律用“你”，不用“您”。
* 原书写于特定年代的内容按当时视角陈述，**不要用今天的现状改写原文**；确需补充现状，只能以译注单独成段，标“（译注：……）”，谨慎克制。
* 参考文献节（“参考文献”/“Bibliography”/“References（引用注释）” 标题及其下内容）非中文条目原文照录不译，豁免引号与中西文空格规则；**中国文献条目（无论古代现代）一并译为中文**（用户裁定 2026-10-28，ADR-0011；[07](07-academic-norms.md)），翻译后的含汉字行按正体例检查。

## 语体与文风（语义判定）

**标尺**：现代汉语学术书面语。合格的译文读起来应像当代中文学术著作的正文，而不是文言、半文半白或翻译腔。

* **禁文言与仿古**：译文自己的叙述（标题、导言、节下正文、译注、脚注说明）一律用现代汉语；不得使用文言句式、文言虚词与仿古修辞。典型形态：句末“矣／焉／哉／耳／乎／耶”，“……者，……也”，文言代词“吾／吾人／彼／厥”，文言连词“然则／何则／是以／若夫／至若／盖”，以及为求凝练而堆叠的四字、对偶、骈句。不得以“古雅”“凝练”为由把现代汉语改写成文言。
* **判断方式（语义）**：整段通读，以“当代中文学术读者能否不借助白话翻译自然读懂”为准；不按“之／其／而／则”等字的关键词命中数机械判定——这些字现代汉语照用，命中数不构成证据。发现疑似文言段落，回读上下文与英文源，确认是译文语体问题还是引文照录。
* **破折号节制**：破折号只承担真正的插入、转折与解释，不得当作默认的停顿或连接手段。同段多处破折号，或用破折号替代冒号、括号、分句更顺的，一律改写（AI 生成文本的典型腔调之一）。判断看句法功能与可读性，不按个数机械判定。
* **破折号滥用的修复方式**：修复滥用时，以含破折号的原句为单位、回英文源句（`yuanwen/` 镜像）整句重新翻译，按新句法自然安置破折号（真正的插入语可保留）；禁止在旧译文本上做符号层机械替换（如一概把“——”换成冒号或括号）——那是把旧译文当修改底稿，违背零信任（宪法 III）。重新翻译只重整句法与停顿，不得改变原句的命题内容。
* **豁免**：直接引文、典籍原文、碑铭，以及题记中的原引文与参考文献照录条目，保持原文语体，不受本条约束；译文对引文的说明与评论仍须用现代汉语。
* **复核留痕**：二校（语言）与初审（r1）各通读一次全文（排除上述豁免内容），在任务 evidence 写下语体结论（如“语体：现代汉语学术书面语；破折号仅用于插入与转折，无滥用”）。门禁只校验该结论是否留痕，语体好坏由复核人语义判断。

## 语言质量

清除以下毛病，逐句对照原文校对：

| 问题类型 | 示例 |
| -------- | ---- |
| 欧化汉语 | 滥用“被”字句、“进行/作出/加以 + 动词”、超长“……的”定语、滥用“们” |
| 后置与倒装 | 从句后置按汉语习惯重排：先因后果、先条件后结论 |
| 偷换主语 | 长句主语变化时显化或断句 |
| 虚词冗余 | 多余的“的、了、着、是、被、所、会、将” |
| 死译 | 双关与玩笑语按中文习惯改写，宁可意译不留硬译 |

### 反欧化条款（ADR-0020，2026-10-31）

上表之外，以下条款给出可判定阈值与 A 批实译判例；机检部分由 `tools/check_prose.py` 预检（告警级，登记见 [05](05-ci-and-tools.md)）。告警逐条人工判断后修改或豁免，机器不替代逐句校对：

* **长句拆分**：单句（以 。；！？ 计）≥70 汉字原则上拆分或重组——主语先行、先因后果、先条件后结论。判例：“把你引向这个结论、而在相当多的哲学家看来也能为这一结论提供辩护的，恰恰是这样一个事实：……”→“你之所以得出这个结论，是因为这样一个事实：……；而且在相当多的哲学家看来，这一事实也为结论提供了辩护。”
* **被动句**：非必要不用“被”；可改主动，或换“受／遭／由／给／为……所”。判例：“不久之后，这颗如今被称为‘海王星’的行星被发现了。”→“不久人们便发现了这颗行星，即今天所说的海王星。”单句 ≥2 个“被”须复核。
* **弱动词**：“进行／作出／加以／予以 + 抽象名词”恢复动词本力（“作出决定”→“决定”；“在……时所起的作用”能省则省）。
* **定语链**：“的”三连或单句 ≥6 个“的”须重排（拆句、并列、去“的”）：“我们对他人的证言的信任”→“我们对他人证言的信任”。
* **类名“们”**：作者们、科学家们→论者、学界，或径去“们”；人称代词不受限。
* **冠词与存在句**：“作为一个 X”→“作为 X／身为 X”；“存在着”→“有／存在”接实义成分。
* **直译框架**：“当……的时候”多可只留“……时”；“如果……那么”能简则简。
* **指代显化**：“它／它们／其”的先行词须在上文近句内可回指；句首“这”指代前文整句时改“这一点／这种做法”。
* **成语与判词**：成语主语须相容——“我们至今仍付之阙如”不通，“这样的判准至今付之阙如”才通；warrant／license 等规范性判词按语境译“许可／支持／有理由推出”，不得译“只配／够格”。
* **脱稿通读**：二校收尾须“忘掉原文通读中文”（思果：译文要像中文）；不通顺处常是未理解原意处，回核原文再改（王太庆：达是信的前提）。

## 检查

* 本地预检：`python tools/check_style.py <路径>...`（规则：curly-quotes、bold-spacing、cjk-spacing、no-html、no-text-fence、no-asciiart；输出 JSON，退出码 0 为无问题）。
* 语体（文言／仿古、破折号滥用）不做关键词机检：由复核人通读判断并在任务 evidence 留痕（见“语体与文风”）；`check_academic.py` 只校验该类结论是否留痕。
* CI 复核：markdownlint（统一配置根目录 `.markdownlint-cli2.jsonc`，`.github/.markdownlint.json` 为等价规则副本，ADR-0002）+ `check-images.yml` + `links.yml`。
* 机器检查不替代逐句校对；三校（体例）时两者都要做。
