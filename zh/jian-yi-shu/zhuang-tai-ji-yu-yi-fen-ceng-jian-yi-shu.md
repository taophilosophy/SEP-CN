# 状态机语义分层与环节治理建议书

**状态**：建议（未实施）｜**日期**：2026-11-17｜**性质**：评估类交付（rules/08 §14：结论＋证据＋建议，不含实施）
**上游**：用户五问（done 语义、四层关系、工作归属、环节重复、插入与降级）＋ 2026-11-17 体系解读与目录规范两轮实测

## 一、方向声明

* **意图复述**：用户要求给出符合公理体系的最优解，解决"done 不可能、四层关系不清、环节重复、插入与降级无判据"五个问题。
* **目标**：让 `state` 只承担阶段语义；其余三类语义各有独立载体与判据；把"改判据的降级强度"写成可机检规则。
* **非目标**：不新增状态、不改 `ORDER`、不迁移存量状态、不改任何条文与工具（本文件只给方案）。
* **验收判据**（供后续实施卡使用）：① 同一检查器同一档位出现在 ≥3 个阶段时门禁告警；② 每个阶段的判据来源可从一张表查到；③ `revert` 目标态由 `ORDER` 推导而非硬编码；④ `done` 的过期状态可在不改任务 JSON 的前提下显示。
* **作废条件**：若实测发现四类语义中任一类无法在不改 `state` 的前提下表达，则本方案退回"新增状态"路线。

## 二、根因

`state` 一个字段被要求同时回答四个问题：

| 问题 | 现由谁回答 | 后果 |
| --- | --- | --- |
| 走到哪一格 | `state` | 正常 |
| 这一格是否还成立（钉是否过期） | 无人回答 | `done` 被读成永久完成 |
| 这一格的判据由谁定义 | 散在 rules/04、specs/001、ADR、步级挂钩 | 同类检查器重复挂载无人察觉 |
| 属哪个批次、谁认领 | `ledger.json` | 正常 |

四问中前两问挤在 `state` 上，第三问无载体。这是"done 不可能"与"环节重复"的共同来源。

## 三、最优解：四载体分离

### 3.1 载体划分（A5 单一事实源：一域一源）

| 载体 | 只回答 | 存储 | 判官 | 写入者 |
| --- | --- | --- | --- | --- |
| `state` | 走到哪一格 | `tasks/<letter>/<slug>.json` | `task_ops.expected_prev` | `task_ops` |
| `stale` | 该钉是否已过期 | **不落盘**，派生视图 | `drift_scan` 报告 ＋ `baseline` 钉 | 无（只读派生） |
| `stages` | 这一格的判据由谁定义 | `rules/stages.json` | `check_stages`（新增） | 治理会话（走 ADR） |
| `ledger` | 属哪个批次、谁认领 | `specs/005-translation-campaign/ledger.json` | `campaign.status` | `campaign` |

**关键约束**：`stale` 不写入任务 JSON。写入会带来三害：每次上游变动全库重写（写放大）、`steps` 混入非阶段事件（污染 append-only 语义）、并行会话冲突面扩大。派生视图由 `task_ops show` 与 `progress.py` 现算。

### 3.2 方案 A：`done` 语义修正（零迁移）

* **条文**：`rules/04` 增一句"`done` 表示在 `version_pin` 所指版本下交付完毕，非永久完成；钉变更后由 `stale` 派生位标示过期，不自动迁移状态"。
* **统计**：`PROGRESS.md` 的 done 列拆为两列——"当前钉下已交付"与"其中钉已过期"。
* **数据源**：`drift_scan.py` 已有"live index.html 对原始钉核对"能力，其报告 `specs/001-sep-sync-pipeline/results/drift-scan-<ts>.json` 即 stale 清单；`task_ops show` 读该报告最近一份，比对任务的 `version_pin.sha256`。
* **公理**：A1（不改 `en/`）、A3（用三元钉判定）、A5（stale 只派生于钉，不另立登记源）、A11（派生只读）。
* **代价**：`drift_scan` 需按需重跑才有新鲜度；报告缺失时 stale 显示"未知"，不显示"未过期"（A12 禁静默乐观）。

### 3.3 方案 B：阶段判据登记表 `rules/stages.json`

每条阶段一行，字段固定：

```
id / order_index / entry / exit_to / criteria[] / actor /
evidence / replay_on_change / authority
```

* `criteria`：该阶段的检查器与档位（如 `check_math_zh:default`、`check_math_zh:strict` 视为两个不同项）。
* `replay_on_change`：`none`｜`patch`｜`from:<state>`｜`full`，即"该阶段判据变更时，存量件如何处理"。
* `authority`：条文的正文锚（rules/04 节号或 ADR 编号），供 S1 锚存在审计。
* **判官 `check_stages.py`** 四谓词：
  * T1 `ORDER` 的每个态在表中有行，且 `order_index` 与 `ORDER` 顺序一致（双向）。
  * T2 `criteria` 里每个工具在 `tools/` 存在（S2 载体存在，防虚载）。
  * T3 同一 `(tool, 档位)` 出现在 ≥3 个阶段 → **告警**（重复可见化）；出现在 2 个阶段且档位不同 → 视为有意升档，不告警。
  * T4 `replay_on_change` 值域合法；`from:<state>` 的目标必须在 `ORDER` 中且早于本阶段。
* **公理**：A5（判据来源单一）、A11（判官只读）、A12（缺字段即硬失败）、R2（单源→校验工具）。
* **代价**：需一次性填写 13 行 × 9 字段；此后每次插入环节必须同时改此表，否则 T1 红灯。

### 3.4 方案 C：`s2.5` 去重（放宽，不需重走）

现状：`s2.5` 同时含"译文轴逐段回 en 核对漏译／增译／错译"与"全局轴（节集合对账、脚注键总数、书目条数、密度统计）"。前者与 `s1` 判据相同。

处置：删除逐段译文轴，只保留全局轴；逐段归 `s1`。

* **依据**：`rules/04` 自述 s2.5 的独立价值在"逐段不可见、全局现形"的分布类缺陷（specs/004 W11）。
* **降级强度**：**放宽**。新判据是旧判据的子集，存量 395 件 `s2.5_checked` 的凭证覆盖了更多要求，**无需重走**。
* **公理**：A2（不引入第二裁决源）、A8（独立复核由 r2 承担，不靠重复检查充数）。
* **风险**：s2.5 变薄后可能被当作"可跳过"。用 T3 谓词盯住：若 s2.5 的 criteria 少于 2 项，告警。

### 3.5 方案 D：`r` 链按 MQM 重新划界（更换，需重走）

`rules/04` 的 MQM 映射声明 r1–r3 做 Verity 与整体验收，但 r1/r2 的步骤描述在重做 Accuracy。二者取其一。

处置：以 MQM 映射为准——
* `r1` = Verity：读者适切性（术语读者可见性、体例读者可见性、导言可读性、译注是否过度）。
* `r2` = 逻辑链：论证结构、指代、转折、例证与原文的对应；**不重复 s1 的漏译检查**。
* `r3` = 验收：CI 全绿 ＋ 用户指定（不变）。

* **降级强度**：**更换**。旧凭证证明的是 Accuracy／逐句回核，新判据要 Verity／逻辑链，无包含关系 → 存量 `r1_reviewed` 1 件、`r2_reviewed` 15 件需重走该环节。数量小，可承受。
* **公理**：A8（复核独立性的实质是独立视角，不是重复劳动）、A9（r3 不变）、R4（人判留痕）。

### 3.6 方案 E：`revert` 目标态由 `ORDER` 推导

现状：`revert-state` 的 `--to` 硬编码 `{s2.5_checked, s2.4_termchecked}`，源态硬编码五个。

处置：改为推导——
* 目标：`ORDER[kind][index(drafted) : index(current)]`，即**不早于 `drafted`**（更早等于重译，应走 `reopen --clear` 的清空 gate）。
* 源：`index(current) > index(drafted)`。
* 校验：`index(to) < index(current)`，否则拒绝。

* **公理**：A7（转移合法由单源推导，不靠第二张白名单）、A12（越界即拒）。
* **代价**：放开后可能出现"退到 s1 重做"的用法，需在 `rules/04` 写明：退到 `s1` 等同于重做全部校次，须在 `--reason` 说明必要性。
* **收益**：将来在 `s1` 之前插入环节时，无需再改白名单。

### 3.7 方案 F：插入协议（把判据写成规则）

`rules/04` 新增一节，规定任何新环节登记时须填五要素：

| 要素 | 要求 |
| --- | --- |
| 位置 | 前驱态与后继态，须为 `ORDER` 中相邻对 |
| 判据谓词 | 可机检的断言；写不出者只能作登记项，不得入门禁（rules/08 §14） |
| 检查器与档位 | 落入 `stages.json` 的 `criteria` |
| 降级策略 | 按 §四判定，填 `replay_on_change` |
| 存量处置 | 全量重走／补课／不动，附数量估算 |

插入形态优先次序（成本从低到高）：**横向批次（不改状态机）→ 状态内扩容（改名不改序）→ 新增状态（改 ORDER）**。前两者能解决时不得用第三者。

## 四、判据变更三型与降级强度（本次方案的核心判据）

存量处理不取决于"是否新增状态"，只取决于**新旧判据的包含关系**：

| 型 | 关系 | 旧凭证 | 动作 | 本方案实例 |
| --- | --- | --- | --- | --- |
| **放宽** | 新 ⊂ 旧 | 仍有效 | 不动 | s2.5 去逐段轴（395 件不重走） |
| **收紧** | 旧 ⊂ 新 | 部分有效 | 补做新增部分 | s0 加入时（存量补 `source-audit`） |
| **更换** | 无包含 | 失效 | 重走该环节及下游 | r 链划界（16 件重走） |

ADR-0053 的"全重走"属于第三型（存量 done 从未经 s2.4/s2.5，旧凭证不覆盖新判据）；ADR-0052 的"原地补课"属于第一、二型之间（`en/` 冻结，缺陷走译注，不改变下游输入）。两者不是风格差异，是同一判据的两个结果。

## 五、迁移面与代价

| 方案 | 改什么 | 存量影响 | 门禁影响 |
| --- | --- | --- | --- |
| A done 语义 | rules/04 一句、PROGRESS 两列、`task_ops show` 派生 | 0 | 无新硬门（stale 是信息） |
| B stages 表 | 新增 rules/stages.json ＋ check_stages ＋ GATES 一行 | 0 | T1–T4，其中 T3 告警 |
| C s2.5 去重 | rules/04 一节、ADR | 0（放宽） | s2.5 criteria 下限告警 |
| D r 链划界 | rules/04 三行、ADR | 16 件重走 | 无 |
| E revert 推导 | task_ops 一处 ＋ rules/04 一句 | 0 | 无 |
| F 插入协议 | rules/04 新节、rules/08 §14 扩一条 | 0 | 由 B 承载 |

合计：1 个新工具、1 张新表、2 个 ADR、约 40 行条文；无状态迁移。

## 六、否决的替代方案

* **新增 `stale` 状态**：违反"状态只表示阶段"这一分层前提；且每上游变动全库迁移一次，写放大不可接受。
* **把判据表并入 `layout.json`**：`layout.json` 管"文件放哪"，`stages.json` 管"阶段判什么"，两问不同域，合并即回到 A5 的双源问题。
* **保留 r1/r2 现状，只删 s2.5 重复**：只解决一半。r 链仍重做校次，MQM 映射仍与实操矛盾。
* **改 `ORDER` 增加 `delivered` 状态**：七处同步＋全库任务迁移，收益仅为一个名字，成本远高于方案 A。

## 七、结论

五个问题不是五个缺陷，是**一个字段承担四种语义**的四种表现。最优解是分离而非增补：

1. `state` 只留阶段（方案 A 修语义、E 去掉硬编码白名单）；
2. `stale` 用派生视图回答时效（方案 A）；
3. `stages` 一张表回答判据来源，并让重复可机检（方案 B）；
4. 重复本身按 MQM 重新划界，用"放宽／收紧／更换"三型决定存量处理（方案 C、D）；
5. 插入环节走五要素协议，优先不改状态机（方案 F）。

全部落在既有公理内：不新增事实源（A5）、不改冻结物（A1）、判官只读（A11）、缺字段即拒（A12）、越界即拒（A7）。
