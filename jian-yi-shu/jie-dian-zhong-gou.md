# 节点重构：17 个工位的职责与判据归属

**日期**：2026-11-17｜**性质**：设计（未实施）｜**依据**：`rules/04` 全文、`task_ops.py` 的 `ORDER`、五个检查器的职责声明、`jian-yi-shu/zhu-xian-jie-dian-quan-biao.md`
**授权**：用户允许重构节点（合并、拆分、移出、改判据）

## 方向声明

* **意图复述**：把每个节点“做什么”逐条列清，并在此基础上重构——允许合并、拆分、改判据、移出主线。
* **目标**：让每个节点的**判据互不重叠**，且节点名与它实际做的事一致。
* **判据**：①不存在两个节点用同一谓词判同一对象；②节点名不误导（叫“三校”的必须真的是校次）；③状态名不变，故 1,199 条任务零迁移；④重跑面可算清。
* **反目标**：不为减少节点数而合并；不改变 R1–R3 的最小集地位。

---

## 一、诊断：五组判据重复，两处名实不符

| # | 重复的两端 | 共同判据 | 性质 |
|---|---|---|---|
| 1 | `s1` ↔ `s2.5` 逐段轴 | 对照源查漏译／错译 | 同谓词、同对象 |
| 2 | `s2` ↔ `s2.5` 语体轴 | 欧化、破折号、“一个”密度 | 同谓词、同对象 |
| 3 | `r1` ↔ `s1`＋`s2` | 对照原文＋通读语体 | 重做校次 |
| 4 | `r2` ↔ `s1` | 逐句回核原文 | 重做校次 |
| 5 | `s2.4` 体例轴 ↔ `s3` | `check_style` 同档 | 同档重复执行 |

两处名实不符：

* **`s3` 名为“三校”，实为体例节点**。`rules/04` 给它的作业是“引号、空格、格式检查；连接号三形、表号表题、顿号、题注”——全是体例，没有内容判断。叫“三校”会让人以为要重读全文。
* **`s0` 名为“源审计”，一半在查转换**。它第二条轴是 `yuanwen ↔ en` 镜像保真，对象是转换产物，不是源。源的信任问题与转换的忠实问题是两件事。

---

## 二、重构原则

1. **一个节点只对一个对象负责**。对象变了就是两个节点，哪怕工序名相同。
2. **写者与判官不同一**。转换器不给自己发合格证（A11 的延伸）。
3. **判据只在一个节点硬拦**。其余节点可以复用同一工具做辅助，但退出码不由它决定。

## 三、17 个节点：逐条列清做什么

### Seg1 英语文本提取（5 节点）

#### 1. `P1` 抓取锁钉 · pipe · 强制

1. 按 `baseline/catalog.json` 的 URL 请求上游页面（重试、编码、UA）。
2. **原样**保存 HTML 到 `en/<slug>/index.html`，不做任何清洗、不加包裹层。
3. 计算 SHA-256，记录 `pubinfo_date` 与 `archive_edition`。
4. 写 `version_pin`。
5. 与既有 pin 比对：变化则发 `lock` 事件并标 `stale`；未变只记时间戳。

产物 `en/index.html` ＋ `lock` 事件｜判据 `fetch_audit`（包完整、HTTP 状态、非错误页）

#### 2. `P2` 转换 · pipe · 强制

1. 解析 HTML：DOM 树、文本节点、属性、注释。
2. 生成 markdown：标题层级、段落、有序／无序／嵌套列表、表格、公式定界符、脚注、引用块、图片。
3. **格式差异**（序号、缩进、空白、无语义标签）生成虚拟补丁，写 `baseline/en-patches/`。
4. **实质差异**（缺字、错字、标签导致语义丢失）登记为待勘误，**不在此处修**。
5. 写 `yuanwen/<letter>/<slug>.md`，与 `en` 保持逐字符镜像（ADR-0009）。

产物 `yuanwen/*.md` ＋ 补丁池｜判据 `check_en_patches`、`divergence`

#### 3. `P3` 保真校验 · pipe · 强制 · **双轴（重构：吸收 s0 镜像轴）**

**结构轴**

1. 把 `yuanwen` 的 markdown 渲染回结构树。
2. 逐项比对：节层级深度与顺序、列表层级与条目数、表列数与对齐、脚注序号与键位、数学块位置与定界符、图片 alt 与路径。
3. 差异三分：转换器缺陷（回 `P2`）／源缺陷（转 `s0`）／格式类（补丁池）。

**文字轴**

4. 逐段比对 `en` 文本节点与 `yuanwen` 段落，字符级差异。
5. 用 `norm` 归并判类：`norm` 相等→3.1 格式；`norm` 不等→3.2 实质。
6. 3.2 类登记进全局勘误表，**不改 md、不改 HTML**。

产物 反校报告（结构差异清单 ＋ 字符差异分类表）｜判据 `check_yuanwen_fidelity`

#### 4. `s0` 源完整性 · pipe · 强制 · **单轴（重构：镜像轴移出）**

1. 页面真实性：是否真是目标词条页（标题、作者、SEP 编号）。
2. 截断检查：标签闭合、末段完整、无省略号截断。
3. 结构完整性：目录锚点可跳、注释配对、脚注定义与引用一一对应。
4. 内容嫌疑：明显 typo、重复段落、乱码、编码错误。
5. 资源：图片是否可达、公式是否渲染错误、表格是否错行。
6. 出结论：可信／可疑（列清单）／不可用（阻断）。

产物 `s0` 事件 ＋ 疑点清单｜判据 `en_integrity`、`en_source_audit`

#### 5. `F1` 镜像格式闭合 · format · 强制

1. markdown 语法：标题不跳级、表格有对齐行、代码块闭合、公式定界符配对。
2. HTML 实体转义正确（`&amp;`、`&#124;`）。
3. 行尾空白、连续空行、文件末换行。
4. **零差异也写一条 `pass`**，否则无法区分“没查”与“查了没问题”。

产物 `F1` 事件｜判据 复用 markdownlint 的 md 侧规则

### Seg2 中文翻译（5 节点 ＋ 1 入口动作）

#### 0. `cleared` 置空 · 入口动作 · 强制

1. 前置：`version_pin` 存在且可信，`s0` 已 pass。
2. 旧译文移入历史（不删 git 历史）。
3. 保留旧 `steps` 作为凭证。
4. 发 `cleared` 事件。

产物 `cleared` 事件｜判据 `version_pin` 存在（机检）

#### 6. `P4` 预处理 · stage · 强制

1. 术语摘录：从 `yuanwen` 抽候选术语，与登记册比对，分“已定／待定／冲突”三类。
2. errata 注入：取该条目的全局勘误条目，把**参考读法**写进提示词。
3. 结构清单：本节标题、层级、必须保留的锚点。
4. 组装提示词（ADR-0021 骨架：术语摘录 ＋ 标题 ＋ errata ＋ 体例要求）。

产物 术语摘录表 ＋ 提示词｜判据 `check_terms`

#### 7. `draft` 初译 · stage · 强制

1. step1 忠实初译：逐句对应，不增不减，保留原文语序痕迹。
2. step2 语言优化：去欧化、调语序、润色。
3. 双版留档：step1 作一校对照底，step2 为成稿对象。
4. 结构对齐：节标题、脚注、引用块、图片位置与 `yuanwen` 一一对应。

产物 译文 ＋ 双版账本｜判据 无（只有产物要求）

#### 8. `s1` 一校 · stage · 强制

1. 逐节核销：漏译、错译、增译、未译。
2. 事实核查：人名、年代、书名、编号、专名。
3. 残留外文碎片检查（须为 0）。
4. 对照 step1 查幻觉：润色是否引入原文没有的内容。
5. 出对照记录（账本 diff 或锚点表）。

产物 对照记录｜判据 `check_pairs`

#### 9. `s2` 二校 · stage · 强制 · **判据收窄（重构：只挂 check_prose）**

1. 去欧化：长定语、被动句、倒装、“的的不休”。
2. 破折号与“一个”滥用检查。
3. 语体确认：现代汉语学术书面语、无文言仿古。
4. 句读与节奏：短句合并、长句切分。
5. 出修改 diff ＋ 语体结论。

产物 修改 diff ＋ 语体结论｜判据 `check_prose`（**体例项全部移到 S3，不在此处跑 `check_style`**）

#### 10. `F2` 中文段内格式闭合 · format · 强制

1. 标题层级与 `SUMMARY` 一致。
2. 列表标记统一、缩进层级正确。
3. 正文内标点全半角。
4. 图片引用路径可解析。
5. 书内链接与脚注键位不悬空。

产物 `F2` 事件｜判据 无独立命令

### Seg3 审阅校对（6 节点）

#### 11. `s2.4` 术语与勘误锁定 · stage · 强制 · **双轴（重构：体例轴移出）**

**术语轴**

1. 逐条比对译文术语与登记册主形。
2. 别名是否已归并、有无未登记新词。
3. 一词多译、多词一译的冲突。

**勘误轴**

4. 取该条目的全局勘误条目，逐条核销译文是否含“参考读法”。
5. 未含者判失败，回 `s2` 或开 `rework`。
6. 3.2 类必须有译注承载，缺译注即失败。

产物 术语锁定记录 ＋ 勘误核销表｜判据 `check_terms`、`check_pairs --gate`

#### 12. `global` 全局一致性 · stage · 强制 · **单轴（重构：删除逐段轴）**

1. 节集合对账：`SUMMARY` 声明 vs 文档实际，逐节名比对。
2. 脚注：定义数 ＝ 引用数，键位无重复，序号连续。
3. 书目：条数、条目与正文引用一一对应。
4. 密度统计：破折号、“一个”、连接号、括号套用的全文密度。
5. 图表：表号连续、图号连续、题注完整。
6. 跨节一致性：同一术语在不同节的形态是否一致。

产物 审计记录（`changes:` 开头）｜判据 `check_math_zh`、`check_quotes`、`check_tables_images`、`check_academic --strict`

#### 13. `S3` 体例终校 · stage · 强制 · **合并（吸收原 s2.4 体例轴、原 s3、原 F3）**

1. 引号形态（弯引号）、中西文之间空格。
2. 连接号三形、顿号新规、括号套用。
3. 表号表题与表身空值、题注细则。
4. 节名与行形态正典化（吸收 `X1` 的单件可判部分）。
5. 交付格式：图片引用、跨文档链接、`SUMMARY` 条目、H1 与文件名一致。
6. markdownlint 全绿。

产物 s3 凭证（含适用规范基线结论）｜判据 `check_style`（全项，唯一硬拦点）、markdownlint、`check_images`、`check_summary`

#### 14. `R1` 受众适切性 · review · 强制 · **改判据**

1. 抽 3–5 段，假设读者为哲学专业本科生，判断能否读懂。
2. 术语是否符合中文哲学界习惯用法（不是“字面正确”）。
3. 需要背景知识处是否有足够提示（不增译，但不得无限定）。
4. 语体是否与全书一致（不是“好文笔”，是“同一本书”）。
5. 签字。

产物 适切性记录｜判据 须独立于译者

#### 15. `R2` 连贯性 · review · 强制 · **改判据**

1. 全文逻辑链：论证步骤是否连贯、有无跳跃。
2. 指代：代词指向是否明确。
3. 跨节呼应：前文承诺后文兑现、术语首次出现是否给定义。
4. 段落衔接：有无孤段、突然转折。
5. 问题单：逐处位置 ＋ 改前改后，禁机械批量。

产物 复核记录｜判据 问题单形态

#### 16. `R3` 交付验收 · review · 强制

1. CI 全绿（14 项门禁）。
2. 交付清单完整：正文、图片、脚注、书目、`SUMMARY`、H1。
3. 上游 pin 仍有效（`stale` 为假）。
4. 用户显式授权记录（`--mandate`）。
5. 验收签字。

产物 验收签字｜判据 CI ＋ `--mandate` 必填（ADR-0054）

## 五、五处关键决定

### 决定一：镜像保真从 `s0` 移到 `P3`

`rules/04` 把 `yuanwen ↔ en` 的逐段人审放在 `s0`，理由是“源审计要确认源可信”。但镜像比对的**对象是转换产物**：它验的是“转换器忠不忠实”，不是“上游页面可不可信”。

移到 `P3` 后，`P3` 有两个轴：结构轴（渲染回结构比层级）、文字轴（逐段比字符）。两者同属“转换保真”，只是层面不同。`s0` 则专注源本身。**对象与判据一一对应。**

### 决定二：`s2.5` 只留全局轴

`s2.5` 自己声明的独特价值是“**全局**——节集合与结构对账、脚注键位总数、书目条数、密度统计”，这些逐段看不见。但它同时保留了“逐段回 en”，与 `s1` 完全重叠。

去掉逐段轴后，`global` 的定位反而清楚：**它只回答“整篇作为一个整体是否自洽”，不回答“某句译得对不对”。**

### 决定三：`s2.4` 交出体例轴，`s3` 正名为体例终校

原设计里体例跑两次：`s2.4` 的体例轴（结构硬、空白告警）与 `s3`（`check_style` 0 issue ＋ markdownlint）。两处同档。

合并后：`s2.4` 只做术语与勘误（都是“这一条词／这一处读法对不对”），`S3` 独占体例（“全篇形式是否合规”）。

顺带把 `s3` 从“三校”改名 `S3 体例终校`——它从来没做过内容校对，叫校次会误导。

### 决定四：`F3` 并入 `S3`，因为判据已被覆盖

这是本轮唯一需要先取证才能拍的决定。核对五个检查器的职责后确认：

| 原计划并入 `F3` 的项 | 已有覆盖 |
|---|---|
| 图片引用可解析 | `check_images`（悬空引用、大小写、未本地化） |
| `SUMMARY` 与 H1 一致 | `check_summary`（ADR-0024 硬门） |
| 引号／空格／连接号 | `check_style`（curly-quotes、cjk-spacing、connector-form） |
| 脚注键位 | `global` 的 footnotes 对账 ＋ `check_pairs` |

**四项全部已有归属**。所以 `F3` 合并不产生任何新判据，也不触发全库重跑。这是“节点数减少”的唯一一处零成本合并。

### 决定五：`R1`／`R2` 改判据，且承认需要补判

`rules/04` 的 MQM 映射写的是“初审至终审做 Verity 抽查与整体验收”，但同文件的步骤表让 `r1` 做“对照原文自审＋通读语体”、`r2` 做“逐句回核原文”——两者都是重做校次。

改为：
* `R1` = 受众适切性（Verity）
* `R2` = 连贯性与逻辑链
* `R3` = 交付验收

这是**判据更换**（新旧互不包含），按三型判据，已过的 `pass` 不能自动沿用。受影响面 = 曾达 `r1_reviewed` 及以上的条目：385 件 `done` ＋ 24 件 `s3` ＋ 16 件 `r2` ＋ 3 件 `r1` = **428 件**。

缓解：`R1`／`R2` 是人工判断，旧记录里“语体结论”（r1）与“逻辑回核”（r2）部分覆盖新判据。执行时按**差额补判**——旧记录已覆盖的维度不重做，只补缺口维度。实际成本远低于 428 次全量。

| `X1` 跨词条批次 | 移出主线，由 `specs/030` 的批次凭证承载 | 0（不改现有流程） |

**唯一的重跑面是 `R1`／`R2` 的差额补判 428 件。** 其余零迁移。

## 七、否决的重构

| 否决 | 理由 |
|---|---|
| 合并 `s1` 与 `s2` 为“一次校订” | MQM 的 Accuracy 与 Fluency 是两个维度，合并会丢失“错在哪一类”的分类能力，问题单无法按维度统计 |
| 合并 `P2` 与 `P3` | 写者不能给自产发合格证（A11 延伸）；这是全套体系最硬的一条边界 |
| 取消 `F1`／`F2` | 段末闭合的意义是“格式问题不跨段传染”；取消后 `P2` 的格式缺陷会一路带到 `S3` 才被发现 |
| `R1`–`R3` 减为 `R1`–`R2` | 用户明确 R1–R3 是最小集、可增不可减；`R3` 还承载 `--mandate` 授权门槛 |
| 彻底取消 `X1` | 跨词条形态问题客观存在（节名不统一、行形态各异），只是不属于单件流水线；移出主线而非取消 |
| 把 `global` 与 `S3` 合并为“终检” | 一个是内容全局自洽（节集合、脚注、密度），一个是形式合规（引号、连接号），对象不同 |
