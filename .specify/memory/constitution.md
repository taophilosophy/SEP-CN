# SEP-CN 项目宪法

## Core Principles

### I. 零信任（Zero Trust, NON-NEGOTIABLE）

任何数据源（SEP 在线页、RSS、archinfo、既有中文译文、脚本中间产物）在使用前必须核验：抓取物登记 SHA-256 哈希与抓取时间；版本以 pubinfo + archinfo 双源核对；**既有中文译文一律不作为底稿或修改依据**（全量重译原则）；可疑处回到原始 HTML 或官方页面核对；禁止以缓存替代源验证。每件成品必须可回溯到具体英文源版本（版本钉：pubinfo 日期 + 存档版名 + 哈希）。

### II. 可追溯与不可变原始物

原始 HTML 抓取副本不可变；一切提取/转换/翻译产物必须能由原始物复算复核。每次抓取/提取/翻译变更留下凭证（哈希、时间戳、原文锚点或 diff）。元数据清单入版本库作审计索引；原始物存本地 `en/`（不入库）。

### III. 单一事实源

目录结构以 `SUMMARY.md` 为唯一数据源（H1 由 CI 同步，不手改）；学科分类目录 `mu-lu-s.md` 为手工维护的独立视图，不在 SUMMARY 自动生成范围（ADR-0001 登记、`rules/01` 为准）；术语译法以 `yi-zhe-shuo-ming.md` 为准；人名译法以 `ren-ming-biao.md` 为准（ADR-0012，两登记册同属本条登记源）；任务状态以 `tasks/` 下的任务记录为准。任何地方出现两个说法，以登记在案的单一源为准并修正另一处。

### IV. 流程先行、高频小步提交

先有流程文档与验收清单，再执行；执行暴露的问题回流修订流程文档（演示→纠偏循环）。每完成一个单元立即提交，提交信息中文一行简述；与本次工作无关的文件不入提交。

### V. 礼貌抓取与失败显式化

相邻 HTTP 请求 ≥5 秒；4xx/5xx/超时退避重试并记录最终状态；缺省件（无脚注/无图/无补充材料）显式登记为缺省而非错误；禁止静默跳过。

### VI. 体例即契约

译文必须通过仓库既有检查（markdownlint、引号/加粗空格检查脚本、图片引用检查）；代码块内容禁止篡改；数学定界符与 LaTeX 原样保留；术语先登记后使用。

### VII. 知难行易（先明方向，后择手段）

任何任务开工前，必须先弄清楚“用户到底要什么”：任务方向、目标、非目标、验收判据、边界与代价承担者（知）；工具、流程、实现路径（行）是可替换的次要变量，不得反客为主。需求含糊时必须先问、先复述、先求证，禁止猜测性实施；完成与否以验收判据与证据判定，不以工具使用、流程走完、文档篇幅或工时判定。可逆决策允许快速试错；不可逆决策（结构重排、批量改写、数据格式、权限、对外发布）必须方向先行并留证据。操作性展开见 `rules/08-intent-first.md`。

## 附加约束

* SEP 词条文本许可 CC BY-NC-SA；“reprinted with permission” 图片必须标注来源；图片本地化存放、禁止外链。
* 全库级破坏性动作（如批量清空既有正文）必须先满足：该词条已有可信英文基线快照，且动作可由 git 历史回溯。
* AGENTS.md 归属修正由独立会话处理，本宪法不重复其内容。

## Governance

宪法优先于其他一切实践规范；修订须在提交信息中注明“修订宪法 vX.Y”并说明理由。运行期开发指引见各 feature 的 plan.md 与仓库 README。
